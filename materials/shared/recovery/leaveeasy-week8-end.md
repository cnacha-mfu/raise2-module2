## ชุดที่ 1 — ปิดข้อมูลรายห้องด้วย Security Rules ⏱ ~5 นาที

> 🔬 **ก่อนเขียนกฎ ให้ทดลองก่อน** — สมัครบัญชีใหม่อีกบัญชี (พนักงาน ข.) แล้วดูว่าเปิดใบลาของบัญชีแรกได้ไหม
> **ได้ — เพราะกฎขั้นต่ำของสัปดาห์ที่แล้วเช็คว่าล็อกอินหรือยังเท่านั้น ใครสมัครก็เดินเข้ามาได้ — ล็อกอินไม่เท่ากับปลอดภัย และนั่นคือสิ่งที่กำลังจะแก้**

```
ตอนนี้กฎของผมมีข้อเดียวคือต้องล็อกอินก่อน
ช่วยเขียน Security Rules ของ Firestore ใหม่ให้ครบตามเช็กลิสต์ 5 ข้อนี้

1. คนที่ไม่ล็อกอิน อ่านอะไรไม่ได้เลย
2. ผู้ใช้เขียนข้อมูลใหม่ได้เฉพาะในชื่อตัวเอง
   คือ requesterId ต้องตรงกับ uid ของคนที่ล็อกอินอยู่
3. ผู้ใช้อ่านใบลาได้เฉพาะใบของตัวเอง
   ยกเว้นคนที่มี role เป็น manager ที่เห็นได้ทุกใบ
4. เปลี่ยนสถานะเป็น อนุมัติ หรือ ไม่อนุมัติ ได้เฉพาะ manager
   และแก้ประเภทการลาในโฟลเดอร์ leaveTypes ได้เฉพาะ manager
5. ต้องเขียนกฎให้โฟลเดอร์ย่อย approvals ด้วย
   เพราะกฎของ leaveRequests ไม่ครอบโฟลเดอร์ย่อยอัตโนมัติ

และปิดท้ายด้วยกฎที่ปฏิเสธทุกอย่างที่ไม่ได้ระบุไว้
เขียนเสร็จแล้ว บอกผมว่าต้อง deploy กฎขึ้นไปอย่างไร
```

> ⚠️ **prompt นี้ยาวกว่าปกติเพราะเป็นเช็กลิสต์ความปลอดภัยที่ตกข้อเดียวแล้วข้อมูลรั่ว** งานอื่นให้กลับไปสั่งสั้นเหมือนเดิม

**✍️ เปิดไฟล์กฎที่ AI เขียนมาอ่าน แล้วตอบให้ได้ว่า** บล็อกของ `approvals` อยู่บรรทัดที่เท่าไร — ตอบว่า "ครบแล้ว" เฉย ๆ ไม่นับ

> 🆘 **ถ้าเขียนกฎแล้ว permission denied ทุกอย่าง** — ปกติมาก Rules ปฏิเสธเป็นค่าเริ่มต้น
> วาง: `ตอนนี้ผมโดน permission denied ทุกหน้า ช่วยเปิดกฎทีละโฟลเดอร์แล้วบอกผมทดสอบทีละอัน อย่าเปิดรวดเดียวทั้งไฟล์`

จากนั้น **deploy กฎขึ้นไป** (ระบบออนไลน์อยู่แล้วจากสัปดาห์ที่ 7 — บันทึกไฟล์ในเครื่องอย่างเดียวไม่พอ)

🚩 **ตรวจสำคัญที่สุดของสัปดาห์นี้ — ⚠️ ห้ามดูหน้าจอตัวเองอย่างเดียว ต้องทดสอบด้วยการสวมรอย**
1. สมัครบัญชีที่สอง (พนักงาน ข.) ในหน้าต่างไม่ระบุตัวตน
2. ล็อกอินเป็นพนักงาน ข. แล้วพยายามเปิดใบลาของพนักงาน ก. → **ต้องเปิดไม่ได้** ✅
3. ปิดล็อกอินทั้งหมด แล้วเปิดเว็บ → **ต้องอ่านอะไรไม่ได้เลย** ✅
4. ส่ง URL ให้เพื่อน → เขาสมัครแล้วใช้งานได้ **แต่เปิดดูใบลาของคุณไม่ได้** ✅

## ชุดที่ 2 — ปุ่มผู้ช่วย AI ผ่าน OpenRouter ⏱ ~5 นาที

> 🔑 **เตรียมคีย์ก่อน** — คีย์ OpenRouter ของคุณต้องอยู่ในไฟล์ `js/config.js` ที่ `.gitignore` กันไว้แล้วเท่านั้น
> ⚠️ **คีย์ที่อยู่ในหน้าเว็บ คนอื่นเปิดดูได้** — ยอมรับได้เฉพาะในคาบเรียนเพราะผู้สอนตั้งวงเงินไว้ · **ไม่ใช่วิธีที่ถูกต้องสำหรับระบบจริง** จดเรื่องนี้ใส่ Backlog Sprint 2

```
ผมอยากเพิ่มปุ่ม "ให้ AI ช่วยจัดประเภทการลา" ในหน้ายื่นใบลาใหม่
โดยเรียก AI ผ่าน OpenRouter ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ
```

**อ่านแผนที่ AI เขียนมา แล้วตรวจว่ามีครบ 6 ข้อนี้ไหม** ถ้าขาดให้บอกให้เพิ่ม

| # | ต้องมีในแผน |
|:--:|---|
| 1 | กดปุ่มแล้วอ่านข้อความในช่องเหตุผลการลา ส่งไปพร้อม**รายชื่อประเภทการลาที่มีอยู่จริง**ในโฟลเดอร์ `leaveTypes` |
| 2 | **ผลที่ได้ต้องเป็นประเภทที่มีอยู่จริงเท่านั้น** — ถ้า AI ตอบนอกรายการ ให้ขึ้นข้อความว่าจัดให้ไม่ได้ และไม่เปลี่ยนค่าเดิม |
| 3 | มีป้ายกำกับ **"ข้อเสนอจาก AI — โปรดตรวจสอบก่อนยืนยัน"** และผู้ใช้แก้ค่าที่ AI เลือกได้เสมอ |
| 4 | ระหว่างรอ ปุ่มขึ้นว่ากำลังทำงานและกดซ้ำไม่ได้ |
| 5 | เรียกไม่สำเร็จ มีข้อความภาษาไทยบอก และ**ระบบต้องใช้ต่อได้ ห้ามค้าง** — ยังกดบันทึกใบลาเองได้ตามปกติ |
| 6 | คีย์อ่านจากไฟล์ `js/config.js` ที่ `.gitignore` กันไว้ **ห้ามเขียนคีย์ลงไฟล์อื่น** |

```
แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน
```

🚩 **ตรวจ 3 อย่าง:**
1. พิมพ์เหตุผล "มีไข้สูง แพทย์ให้พักสองวัน" → กดปุ่ม → เห็นสถานะกำลังทำงาน → ได้ประเภท **ลาป่วย** พร้อมป้าย "ข้อเสนอจาก AI"
2. **ปิดเน็ตแล้วกดปุ่ม** → มีข้อความภาษาไทยบอกว่าเรียกไม่สำเร็จ และยังบันทึกใบลาเองได้ — ระบบไม่ค้าง
3. 🔑 สั่ง *"แสดงรายการไฟล์ที่กำลังจะส่งขึ้น GitHub"* → **ต้องไม่เห็น `js/config.js` ในรายการที่จะถูก commit** — ถ้าเห็น หยุดทันที อย่า commit แล้วแก้ `.gitignore` ก่อน

## ชุดที่ 3 — Reviewer Sub-Agent ⏱ ~3 นาที

```
ช่วยสร้าง sub-agent ชื่อ reviewer ให้โปรเจกต์นี้
ให้ตรวจ 5 เรื่องนี้
1. Security Rules มีรูรั่วไหม โดยเฉพาะโฟลเดอร์ย่อย
2. มีที่ไหนไม่ตรวจข้อมูลที่ผู้ใช้กรอกก่อนบันทึกไหม
3. มีที่ไหนไม่ได้จัดการกรณีไม่พบข้อมูลหรือเรียก AI ไม่สำเร็จไหม
4. ชื่อช่องข้อมูลสะกดตรงกันทุกที่ไหม
5. มีคีย์หรือรหัสผ่านหลุดอยู่ในโค้ดที่จะ commit ไหม
และให้เขียนไว้ในไฟล์ตั้งค่าว่า reviewer ห้ามแก้ไขโค้ดเอง ให้รายงานอย่างเดียว
```

**✍️ เปิดไฟล์ตั้งค่าที่ Claude สร้างมาอ่าน แล้วยืนยัน 2 ข้อ** — มีบรรทัด "ห้ามแก้ไขโค้ดเอง" ไหม · รายการตรวจครบ 5 ข้อไหม

```
รัน reviewer ตรวจทั้งโปรเจกต์ แล้วสรุปผลเป็น 3 กอง
แดง = ต้องแก้ทันที เหลือง = แก้ก่อนส่งมอบ ขาว = รับทราบแต่ยังไม่แก้
เขียนลงไฟล์ review-notes.md ยังไม่ต้องแก้อะไร
```

**✍️ อ่านผลแล้วย้ายกองอย่างน้อย 1 ข้อพร้อมเหตุผล** — ถ้าเห็นด้วยทุกข้อโดยไม่ย้ายเลย แปลว่ายังไม่ได้อ่านจริง

```
แก้เฉพาะกองแดงทีละข้อ commit ทีละข้อ
เสร็จแต่ละข้อบอกผมก่อน ผมจะทดสอบเอง
```

🚩 **ตรวจ:** ไม่เหลือประเด็นสีแดง และระบบยังทำงานได้เหมือนเดิม
