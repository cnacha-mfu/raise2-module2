## ชุดที่ 1 — CLAUDE.md และ GitHub ⏱ ~3 นาที

> 💡 หลักของสัปดาห์นี้: **ให้ AI ร่าง แล้วเราอ่านตรวจว่าอะไรขาด** — ไม่ต้องนั่งพิมพ์เองทั้งไฟล์

```
ช่วยร่างไฟล์ CLAUDE.md คู่มือประจำโปรเจกต์นี้ให้ผมดูก่อน
อ่านโครงสร้างโปรเจกต์ประกอบด้วย ต้องมีหัวข้อเหล่านี้

1. โครงงานนี้คืออะไร — ระบบขอลาออนไลน์ พนักงานยื่นใบลา หัวหน้าอนุมัติ
2. เครื่องมือที่ใช้ ห้ามเปลี่ยน — HTML CSS JavaScript ธรรมดา ไม่ใช้ framework
   ฐานข้อมูล Firestore · ล็อกอิน Firebase Authentication · ขึ้นออนไลน์ Firebase Hosting
3. โครงสร้างข้อมูลบน Firestore เขียนเป็นโฟลเดอร์และไฟล์
   โฟลเดอร์ users     ไฟล์มี name email role
   โฟลเดอร์ leaveTypes ไฟล์มี name
   โฟลเดอร์ leaveRequests ไฟล์มี
     title reason status
     requesterId requesterName
     approverId approverName
     leaveTypeId leaveTypeName
     startDate endDate createdAt
     และมีโฟลเดอร์ย่อยชื่อ approvals
       ไฟล์ในนั้นมี authorId authorName message createdAt
4. ข้อตกลง — ข้อความบนหน้าจอเป็นภาษาไทย
   สถานะใช้ได้ 3 ค่าเท่านั้น รอพิจารณา อนุมัติ ไม่อนุมัติ
   ใบลาที่สร้างใหม่ตั้งสถานะเป็น รอพิจารณา เสมอ
   ชื่อ field ต้องสะกดตรงตามข้างบนเป๊ะ Firestore แยกตัวพิมพ์เล็กใหญ่
5. สิ่งที่ห้ามทำ — ห้ามเปลี่ยนไปใช้ framework
   ห้ามใส่รหัสผ่านหรือคีย์ลงในโค้ดที่จะ commit
   ห้ามใช้ข้อมูลส่วนบุคคลจริงของใคร ใช้ชื่อสมมติเท่านั้น
```

> ⚠️ **prompt นี้ยาวกว่าปกติเพราะเนื้อหาคือรายการชื่อ field ที่สะกดผิดแล้วพังแบบเงียบ ๆ** งานอื่นให้กลับไปสั่งสั้นเหมือนเดิม

**✍️ อ่านไฟล์ที่ AI ร่างมา แล้วตอบให้ได้ว่าครบ 5 หัวข้อไหม อะไรขาด** — ตอบว่า "ครบแล้ว" เฉย ๆ ไม่นับ ต้องชี้ได้ว่าหัวข้อไหนอยู่บรรทัดไหน

จากนั้น

```
1. ตรวจไฟล์ .gitignore ให้กัน node_modules และไฟล์ที่มีคำว่า config key secret
2. บอกวิธีสร้าง repo บน GitHub และ push ขึ้นไปให้ผมทีละขั้น
3. ก่อน push ให้แสดงรายชื่อไฟล์ที่จะถูกส่งขึ้นไป ผมจะตรวจเอง
```

🚩 **ตรวจ:** เปิด repo บน GitHub แล้วเห็น `CLAUDE.md` และ **ไม่มีไฟล์ที่มีคำว่า key หรือ secret**

## ชุดที่ 2 — CRUD ให้ครบ 4 ตัว ⏱ ~5 นาที

> สัปดาห์ที่แล้วมีตัว **R** (หน้ารายการอ่านจากฐาน) แล้ว — ชุดนี้เติม **C · U · D** ให้ครบ
> ⚠️ **ทำทีละอย่าง ทดสอบทีละอย่าง** อย่าสั่งทำทั้ง 4 อย่างรวดเดียว

**C — เพิ่ม**
```
เปลี่ยนหน้ายื่นใบลาใหม่ให้บันทึกลง Firestore จริง
ตั้งสถานะเป็น รอพิจารณา และบันทึก createdAt เป็นเวลาปัจจุบัน
ต้องบันทึกครบทุก field รวม requesterName approverName leaveTypeName ด้วย
เสร็จแล้วบอกผม ผมจะยื่นใบลาทดสอบเอง
```
**จะเห็น:** ยื่นใบลาใหม่ → เปิด Firebase Console → มีไฟล์ใหม่โผล่ในโฟลเดอร์ `leaveRequests`

**R (หน้ารายละเอียด) + U — อ่านและแก้**
```
เปลี่ยนหน้ารายละเอียดใบลาให้อ่านจาก Firestore
และปุ่มอนุมัติ ไม่อนุมัติ ให้แก้ field status ในไฟล์นั้นจริง
ให้แก้เฉพาะ field status ห้ามเขียนทับ field อื่น
พร้อมบันทึกความเห็นลงโฟลเดอร์ย่อย approvals
```
**จะเห็น:** กดอนุมัติ → รีเฟรช Console → `status` ของใบนั้นเปลี่ยนจริง

**D — ลบ**
```
เพิ่มปุ่มลบในหน้ารายละเอียดใบลา
กดแล้วต้องมีหน้าต่างถามยืนยันก่อนเสมอ ยืนยันแล้วลบไฟล์นั้นจาก Firestore จริง
ให้ลบได้เฉพาะใบที่สถานะยังเป็น รอพิจารณา
```

**หน้าที่เหลือ**
```
เปลี่ยนหน้าประเภทการลาและหน้าแดชบอร์ดให้ใช้ข้อมูลจาก Firestore
แล้วลบไฟล์ js/data.js ที่เป็นข้อมูลปลอมทิ้ง
ตัวเลขบนแดชบอร์ดต้องนับจากข้อมูลจริง
เสร็จแล้ว commit ด้วยข้อความว่า "CRUD ครบ 4 ตัว"
```

🚩 **ตรวจ:** ⭐ **ยื่นใบลาใหม่ → ปิดเบราว์เซอร์ → เปิดใหม่ → ใบลานั้นยังอยู่ · แก้ได้ · ลบได้**

## ชุดที่ 3 — ล็อกอิน ⏱ ~4 นาที

> **ทำด้วยมือก่อน** — เข้า Firebase Console → เปิดใช้งาน Authentication → เปิดวิธีล็อกอินแบบอีเมล/รหัสผ่าน

```
ผมเปิดใช้ Firebase Authentication แบบอีเมลกับรหัสผ่านแล้ว
อยากเพิ่มระบบล็อกอินให้เว็บนี้ ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ
```

**อ่านแผนที่ AI เขียนมา แล้วตรวจว่ามีครบ 5 ข้อนี้ไหม** ถ้าขาดให้บอกให้เพิ่ม

| # | ต้องมีในแผน |
|:--:|---|
| 1 | หน้า `login.html` มีทั้งเข้าสู่ระบบและสมัครสมาชิก |
| 2 | สมัครสำเร็จแล้วสร้างไฟล์ใน `users/` โดยใช้ uid เป็นชื่อไฟล์ พร้อมช่อง `role` ค่าเริ่มต้น `employee` |
| 3 | ทุกหน้าถ้ายังไม่ล็อกอิน ให้ส่งกลับไปหน้า login |
| 4 | แถบเมนูแสดงชื่อคนที่ล็อกอินอยู่ + ปุ่มออกจากระบบ |
| 5 | ยื่นใบลาใหม่ ให้บันทึก `requesterId` เป็น uid ของคนที่ล็อกอินอยู่จริง |

```
แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน
สำคัญ ต้องรอให้สถานะล็อกอินพร้อมก่อน ค่อยอ่านข้อมูลจาก Firestore
```

🚩 **ตรวจ:** สมัครบัญชีใหม่ → ยื่นใบลา → เปิด Firebase Console ดูว่า `requesterId` เป็น uid ของคนที่ล็อกอินจริง

## ชุดที่ 4 — กุญแจประตูหน้าบ้าน: กฎขั้นต่ำ 1 ข้อ ⏱ ~2 นาที

> 🔬 **ก่อนเขียนกฎ ให้ทดลองก่อน** — เปิดเว็บในหน้าต่างไม่ระบุตัวตน (ไม่ล็อกอิน) แล้วดูว่าตอนนี้ยังอ่านข้อมูลได้ไหม
> **ได้ — เพราะโหมดทดสอบเปิดให้ทุกคน และนั่นคือสิ่งที่กฎข้อนี้จะปิด**

```
ช่วยเขียน Security Rules ของ Firestore ให้ผม 1 ข้อ
ต้องล็อกอินก่อน ถึงจะอ่านหรือเขียนข้อมูลได้ ทุกโฟลเดอร์
ยังไม่ต้องแยกสิทธิ์ตามคนหรือตามบทบาท สัปดาห์หน้าค่อยทำ
เขียนเสร็จแล้วให้ผมอ่านก่อน แล้วบอกวิธี deploy กฎขึ้นไป
```

**✍️ อ่านกฎที่ AI เขียนมา แล้วชี้ให้ได้ว่าบรรทัดไหนคือ "ต้องล็อกอินก่อน"**

🚩 **ตรวจ:** เปิดหน้าต่างไม่ระบุตัวตน (ไม่ล็อกอิน) → **ต้องอ่านอะไรไม่ได้เลย** · ล็อกอินแล้ว → ใช้งานได้ปกติ

> ⚠️ **กฎข้อนี้ยังไม่ใช่ปลอดภัยจริง** — ใครสมัครบัญชีใหม่ก็เข้ามาอ่านได้หมด · สัปดาห์ที่ 8 จะปิดรายห้องด้วยเช็กลิสต์ 5 ข้อ
