## ชุดที่ 1 — CLAUDE.md และ GitHub ⏱ ~4 นาที

```
ช่วยเขียนไฟล์ CLAUDE.md ให้โปรเจกต์นี้ เพื่อให้คุณอ่านทุกครั้งก่อนเริ่มงาน
ใส่หัวข้อเหล่านี้

1. โครงงานนี้คืออะไร
   ระบบขอลาออนไลน์ พนักงานยื่นใบลา หัวหน้าอนุมัติ

2. เครื่องมือที่ใช้ ห้ามเปลี่ยน
   HTML CSS JavaScript ธรรมดา ไม่ใช้ framework
   ฐานข้อมูล Firestore
   นำขึ้นออนไลน์ Firebase Hosting

3. โครงสร้างข้อมูลบน Firestore เขียนเป็นโฟลเดอร์และไฟล์

   ข้อความบนหน้าจอเป็นภาษาไทย

   ใบลาที่สร้างใหม่ตั้งสถานะเป็น รอพิจารณา เสมอ
   ชื่อ field ต้องสะกดตรงตามข้างบนเป๊ะ Firestore แยกตัวพิมพ์เล็กใหญ่
   ตัวเลขบนแดชบอร์ดต้องนับจากข้อมูลจริง ห้ามพิมพ์ค้างไว้

5. สิ่งที่ห้ามทำ
   ห้ามเปลี่ยนไปใช้ framework
   ห้ามใส่รหัสผ่านหรือคีย์ลงในโค้ดที่จะ commit
   ห้ามใช้ข้อมูลส่วนบุคคลจริงของใคร ใช้ชื่อสมมติเท่านั้น

```

## ชุดที่ 2 — สร้าง Firebase project และต่อ Firestore ⏱ ~5 นาที

> **ทำด้วยมือก่อน** — ไปที่หน้าเว็บ Firebase สร้างโปรเจกต์ใหม่ แล้วเปิดใช้งาน Firestore
> ⚠️ ตอนเลือกโหมด ให้เลือก **โหมดทดสอบ** และ **จดวันหมดอายุไว้** (ค่าเริ่มต้นหมดอายุใน 30 วัน)

```
ผมสร้าง Firebase project และเปิดใช้ Firestore แล้ว
ช่วยต่อเว็บของผมเข้ากับ Firestore ให้หน่อย

1. บอกผมว่าต้องคัดลอกค่าตั้งค่าจากหน้าไหนของ Firebase มาวางตรงไหน
2. สร้างไฟล์สำหรับเก็บค่าตั้งค่านั้น และเชื่อมเข้ากับทุกหน้า
3. อธิบายให้ผมฟังสั้น ๆ ว่าค่าตั้งค่าชุดนี้ปลอดภัยที่จะอยู่ในหน้าเว็บหรือไม่ เพราะอะไร

ยังไม่ต้องแก้หน้าจอ ขอให้ต่อติดก่อน
```

**จะเห็น:** AI บอกให้ไปคัดลอกค่าจากหน้าตั้งค่าของ Firebase · ทำตามแล้ววางกลับมา

## ชุดที่ 3 — ย้ายข้อมูลปลอมขึ้น Firestore ⏱ ~3 นาที

```
ช่วยเขียนสคริปต์ใส่ข้อมูลตัวอย่างลง Firestore ให้ผม
ใช้ข้อมูลชุดเดียวกับที่อยู่ใน js/data.js ตอนนี้เลย

1. โฟลเดอร์ users 3 ไฟล์
2. โฟลเดอร์ leaveTypes 3 ไฟล์
3. โฟลเดอร์ leaveRequests 5 ไฟล์
   ทุกไฟล์ต้องมีทั้ง requesterId กับ requesterName
   และ approverId กับ approverName
   และ leaveTypeId กับ leaveTypeName ให้ครบทุกคู่
   สถานะกระจายให้ครบทั้ง 3 ค่า
4. ใส่ความเห็นลงโฟลเดอร์ย่อย approvals ของใบที่พิจารณาแล้ว

รันแล้วบอกผมว่าใส่สำเร็จกี่ไฟล์
```

🚩 **ตรวจสำคัญ:** เปิด **Firebase Console** ในเบราว์เซอร์ → กดเข้าโฟลเดอร์ `leaveRequests` → **เห็นไฟล์ใบลา 5 ไฟล์ด้วยตาตัวเอง** → กดเข้าไปในไฟล์แล้วหาโฟลเดอร์ย่อย `approvals` เจอ

## ชุดที่ 4 — เปลี่ยนจากข้อมูลปลอมเป็นข้อมูลจริง ⏱ ~4 นาที

> ⚠️ **ทำทีละอย่าง ทดสอบทีละอย่าง** อย่าสั่งทำทั้ง 4 อย่างรวดเดียว

```
เปลี่ยนหน้ารายการใบลาให้อ่านข้อมูลจาก Firestore แทน js/data.js
ยังไม่ต้องแตะหน้าอื่น
เสร็จแล้วบอกผมให้รีเฟรชดูก่อน
```

```
เปลี่ยนหน้ายื่นใบลาใหม่ให้บันทึกลง Firestore จริง
ตั้งสถานะเป็น รอพิจารณา และบันทึก createdAt เป็นเวลาปัจจุบัน
ต้องบันทึกครบทุก field รวม requesterName approverName leaveTypeName ด้วย
```

```
เปลี่ยนหน้ารายละเอียดใบลาให้อ่านจาก Firestore
และปุ่มอนุมัติ ไม่อนุมัติ ให้แก้ field status ในไฟล์นั้นจริง
ให้แก้เฉพาะ field status ห้ามเขียนทับ field อื่น
พร้อมบันทึกความเห็นลงโฟลเดอร์ย่อย approvals
```

```
เปลี่ยนหน้าประเภทการลาและหน้าแดชบอร์ดให้ใช้ข้อมูลจาก Firestore
แล้วลบไฟล์ js/data.js ที่เป็นข้อมูลปลอมทิ้ง
ตัวเลขบนแดชบอร์ดต้องนับจากข้อมูลจริง
```

## 🆘 ติดตรงนี้ให้ทำอย่างไร

| อาการ | ทำอย่างไร |
|---|---|
| **permission denied / ต่อ Firestore ไม่ติด** | ตรวจว่าเปิดใช้ Firestore แล้ว · **ตรวจว่ากฎโหมดทดสอบยังไม่หมดอายุ** (เข้าไปดูวันหมดอายุในหน้า Rules) — นี่คือสาเหตุอันดับ 1 |
| กรอกแล้วข้อมูลหายหลังรีเฟรช | เปิด Console ดูว่ามีไฟล์ใหม่เพิ่มไหม · **ถ้าไม่มี = พังตอนเขียน · ถ้ามี = พังตอนอ่าน** แยกให้ออกก่อนแก้ |
| ข้อมูลอยู่ใน Console แต่ไม่ขึ้นบนหน้าจอ | ตรวจว่าสะกดชื่อโฟลเดอร์ตรงกันไหม — Firestore แยกตัวพิมพ์เล็ก-ใหญ่ |
| ชื่อผู้ขอลาไม่ขึ้น ขึ้นแต่รหัส | ไม่มี JOIN ใน Firestore — ต้อง**จดชื่อซ้ำไว้ในไฟล์ใบลาเลย** สั่งให้เพิ่ม `requesterName` |
| ขึ้น error เรื่อง index ตอนเรียงลำดับ | **กดลิงก์ที่ error ให้มาแล้วสร้างตาม** เป็นเรื่องปกติ รอสักครู่แล้วลองใหม่ |
| เผลอ push ไฟล์คีย์ขึ้น GitHub | **เพิกถอนคีย์นั้นทันทีใน Firebase Console** แล้วค่อยลบไฟล์ |
| **ใช้เวลาเกิน 25 นาทีแล้วยังไม่จบ** | **หยุด แล้วเรียกผู้ช่วยหรือ TA ทันที** |
