# ปัญหาของ prototype ที่กลุ่มคุณถืออยู่

- 🖼️ **prototype** (หน้าเว็บตัวอย่างที่กดดูได้) จาก Module 1 เป็น *ภาพนิ่ง*
- กรอกอะไรลงไป รีเฟรชแล้วหายหมด
- เพราะยังไม่มี **ฐานข้อมูล** (ตู้เก็บข้อมูลที่อยู่ต่อแม้ปิดเบราว์เซอร์)
- 🎯 วันนี้เราต่อตู้เก็บข้อมูลให้ระบบของกลุ่มคุณ

> note: ถามห้องก่อนว่า "ใครเคยกรอกฟอร์มใน prototype ของตัวเองแล้วรีเฟรช ข้อมูลหายไหมครับ" รอคำตอบในแชท แล้วพูดว่า "หายทุกกลุ่มครับ เพราะมันยังไม่มีที่เก็บ วันนี้เราจะแก้เรื่องนี้"

!! ระบบเริ่มมีความจำ

> note: หยุด 3 วินาทีให้อ่าน แล้วพูดว่า "ประโยคนี้คือความคิดเดียวของวันนี้ครับ เย็นนี้ระบบของกลุ่มคุณจะจำข้อมูลได้ ปิดเบราว์เซอร์แล้วเปิดใหม่ ข้อมูลยังอยู่"

# วันนี้กลุ่มของคุณจะได้ 4 อย่างกลับไป

- 📁 **Repo** (โฟลเดอร์โครงงานที่มีปุ่มเซฟย้อนได้) ที่รันเว็บของกลุ่มได้
- 📝 แบบโครงสร้างข้อมูลบนกระดาษ 1 แผ่น
- 🗄️ **Firestore** (ตู้เก็บข้อมูลบนคลาวด์) ที่มีข้อมูลจริงอยู่ข้างใน
- 🖥️ หน้ารายการที่อ่านข้อมูลจากตู้จริง ไม่ใช่ของปลอมในโค้ด

> note: พูดว่า "สี่ข้อนี้คือของจับต้องได้ ไม่ใช่ความรู้สึกว่าเข้าใจ ตอนบ่ายกลุ่มคุณจะทำครบทั้งสี่ข้อกับโครงงานของกลุ่มเอง" ย้ำว่าข้อสุดท้ายคือครั้งแรกที่หน้าจอกับฐานข้อมูลได้เจอกัน

!! สิ่งที่คุณไม่ต้องรู้

> note: หยุด 2 วินาทีก่อนพูด แล้วพูดว่า "ก่อนเริ่ม ผมอยากเคลียร์เรื่องนี้ก่อน เพราะความกลัวว่าต้องรู้ทุกอย่างทำให้คนหยุดตัวเองก่อนได้เริ่ม" ค้างสไลด์ 5 วินาทีให้อ่านทัน

# 5 อย่างที่คุณไม่ต้องรู้ใน Module นี้

- ❌ ไม่ต้องเขียนโค้ดเองจากศูนย์
- ❌ ไม่ต้องท่องคำสั่ง เปิดใบงานดูได้ตลอด · ลืมเมื่อไรพิมพ์ `/help`
- ❌ ไม่ต้องรู้ว่าทุกไฟล์ทำอะไร
- ❌ ไม่ต้องเข้าใจเบื้องหลังของ Firebase
- ❌ ไม่ต้องจำศัพท์อังกฤษ มีแผ่นคำแปลให้

> note: พูดทีละข้อ ช้า ๆ แล้วปิดท้ายว่า "สิ่งที่คุณต้องทำได้มีอย่างเดียว คืออ่านสิ่งที่ AI เขียนมาแล้วบอกได้ว่าใช่หรือไม่ใช่ นั่นคือทักษะของ Module นี้" · เตือนว่า "คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ถ้าพิมพ์แล้วไม่ได้ผล พิมพ์ /help ดูรายการที่ใช้ได้จริงในเครื่องคุณ"

# Node.js และ npm — เท่าที่ใช้จริงวันนี้

- **Node.js** = โปรแกรมที่ทำให้เว็บของเรารันบนเครื่องได้
- **npm** = ตัวติดตั้งชิ้นส่วนสำเร็จรูปที่คนอื่นเขียนไว้
- ติดตั้งไว้แล้วตั้งแต่ Module 1 — วันนี้ไม่ต้องติดตั้งใหม่
- 📌 คุณไม่ต้องรู้จักชื่อชิ้นส่วน Claude เลือกให้

> note: เปรียบว่า "Node เหมือนเครื่องเล่นแผ่น ถ้าไม่มีเครื่องเล่น แผ่นก็เปิดไม่ได้ · npm เหมือนร้านขายน้ำพริกแกงสำเร็จ ไม่ต้องตำเอง" แล้วบอกว่ากลุ่มไหนพิมพ์ node -v แล้วไม่ขึ้นเลขเวอร์ชัน ให้พิมพ์ 🔴 ในแชทตอนบ่ายทันที

# commit — ปุ่มเซฟที่ย้อนกลับได้

- **commit** = กดเซฟหนึ่งครั้ง พร้อมเขียนกำกับว่าทำอะไรไป
- ทุก commit คือหมุดที่ย้อนกลับมายืนได้
- AI แก้เร็วและบางครั้งแก้พัง — มีหมุดจึงกล้าปล่อยให้แก้
- 🎯 กติกาทั้งเดือน: ทำอะไรสำเร็จ → commit ทันที

> note: พูดว่า "commit คือเหตุผลที่เรากล้าให้ AI แตะโปรเจกต์จริง พังเมื่อไรย้อนกลับได้ใน 5 วินาที" · เตือนว่าข้อความ commit ต้องอ่านรู้เรื่อง เช่น "เพิ่มหน้ารายการใบแจ้งซ่อม" ไม่ใช่ "update" เพราะตอนต้องย้อน คุณต้องหาหมุดเจอ · บ่ายนี้ Checkpoint 3 ตรวจข้อนี้

# ถ้า AI แก้แล้วพัง — ตาข่ายรับ 2 ชั้น

```code
Esc          หยุด Claude กลางคัน
Esc Esc      เปิดเมนูย้อนกลับ เลือกจุดที่จะย้อน (/rewind ได้ผลเดียวกัน)
git checkout .   ย้อนไฟล์กลับไปจุดที่ commit ไว้ล่าสุด
```

- 🥅 ชั้นที่ 1 — `Esc Esc` ใช้ตอนรู้ตัวทันทีว่าคำสั่งเมื่อกี้ไม่ใช่
- 🥅 ชั้นที่ 2 — `git` ใช้ได้เสมอ แม้ปิดหน้าต่างหรือพังข้ามวัน

> note: เปิดด้วยคำถามที่ทุกคนกลัวที่สุด "ถ้า AI แก้แล้วพังจะทำยังไงครับ" รอ 5 วินาที แล้วชี้ทีละบรรทัดว่า "มีตาข่ายรับสองชั้น ไม่ได้มีชั้นเดียว" · ย้ำว่าเมนู Esc Esc ย้อนได้ทั้งไฟล์และบทสนทนา · ปิดท้ายว่า "ถ้าเมนูหน้าตาไม่เหมือนของผม พิมพ์ /help ดูรายการของเวอร์ชันคุณ"

# นำ prototype เข้าโครงโปรเจกต์ — 4 ขั้น

```code
1) สร้างโฟลเดอร์ใหม่ → คัดลอกไฟล์ prototype ทั้งหมดเข้าไป
2) git init → commit แรก "นำ prototype เข้าโปรเจกต์"
3) ให้ Claude ตั้งค่าให้สั่ง npm run dev ได้
4) เปิดเบราว์เซอร์ → เห็นหน้าเว็บเดิมของเรา ขึ้นจาก repo
```

> note: ชี้ทีละบรรทัดแล้วพูดว่า "สังเกตว่าปุ่มย้อนมาก่อนเสมอ ขั้นที่ 2 มาก่อนขั้นที่ 3 เพราะเดี๋ยว AI จะเข้ามาแตะไฟล์จริง เราต้องมีหมุดก่อน" · บอกว่านี่คือส่วน A ของใบงานบ่ายนี้ทั้งส่วน

> note: พูดว่า "ถ้าไฟล์หนึ่งสะกดตัวเล็ก อีกไฟล์สะกดตัวใหญ่ ระบบจะพังแบบเงียบ ๆ ไม่มี error ให้เห็น หน้าจอจะว่างเฉย ๆ" · บอกว่า "นี่คือเหตุผลที่ตอนบ่ายกลุ่มคุณต้องเขียนชื่อช่องข้อมูลทุกตัวลงกระดาษก่อน แล้วใช้ชุดเดียวกันทั้งระบบ และเป็นเหตุผลเดียวที่วันนี้จะมี prompt ยาวอยู่หนึ่งอัน"

# ข้อที่ต่างจากตารางมากที่สุด — ไม่มี JOIN

- ในไฟล์ใบแจ้งซ่อม เก็บไว้เท่านี้ `reporterId: "u001"`
- อยากรู้ชื่อผู้แจ้ง ต้องเปิดโฟลเดอร์ `users` หาไฟล์ `u001` อีกที
- ทำทุกครั้งที่แสดงรายการ = ช้าและยุ่ง
- 20 ใบแจ้งซ่อม = เปิดหาอีก 20 รอบ

> note: **สไลด์ที่ห้ามรีบที่สุดของช่วงนี้** · เล่าเป็นภาพ "เหมือนเปิดใบเสร็จแล้วเห็นแต่รหัสลูกค้า ต้องวิ่งไปเปิดแฟ้มทะเบียนลูกค้าอีกตู้ทุกครั้งที่อยากรู้ว่าใคร" · แปลศัพท์ JOIN = การเชื่อมสองตารางเข้าหากันในฐานข้อมูลแบบเดิม ซึ่ง Firestore ไม่มี

# ทางแก้ — จดชื่อซ้ำไว้ในไฟล์เลย

- ศัพท์ทางการเรียกว่า **Denormalize (จดซ้ำ)**
- เก็บทั้ง `reporterId` และ `reporterName`
- เปิดไฟล์ใบเดียว ได้ครบทุกอย่างที่ต้องแสดง
- ไม่ต้องวิ่งไปเปิดโฟลเดอร์อื่น

> note: ย้ำคำเทียบ "Denormalize = จดข้อมูลที่ใช้บ่อยซ้ำไว้ในไฟล์เลย จะได้ไม่ต้องไปเปิดหาที่อื่น" · พูดว่า "ถ้าตอนบ่ายชื่อคนไม่ขึ้นบนหน้าจอ ขึ้นแต่รหัสประหลาด 90% คือเก็บแต่ ID ไว้ ให้กลับมาที่สไลด์นี้"

# ไม่มี JOIN จึงต้องจดชื่อซ้ำ

```flow compare
❌ เก็บไว้เฉพาะรหัส :: เปิดใบแจ้งซ่อม | *เห็นรหัส u001 | วิ่งไปเปิด users
✅ จดชื่อซ้ำไว้ในไฟล์ :: เปิดใบแจ้งซ่อม | เห็นชื่อสมชาย | จบในไฟล์เดียว
```

> note: ชี้แถบบนไล่จากซ้าย หยุดที่กล่องเข้ม "ถึงตรงนี้หน้าจอขึ้นแต่ u001 อ่านแล้วไม่รู้ว่าใคร" · กล่องขวาสุดแถบบน "ใบแจ้งซ่อม 20 ใบ ก็วิ่ง 20 รอบ" · ไล่แถบล่างทีละกล่อง ปิดที่ "จบในไฟล์เดียว นี่คือสิ่งที่เรียกว่าจดซ้ำ"

# ราคาของการจดชื่อซ้ำ — ต้องรู้ก่อนเลือก

- สมชายเปลี่ยนชื่อเป็น "สมชาย ใจดี"
- ไฟล์ใน `users` แก้จุดเดียวจบ
- แต่ใบแจ้งซ่อม 20 ใบยังขึ้นชื่อเก่า
- **ต้องไล่แก้ทุกใบที่จดชื่อเขาไว้**

> note: พูดว่า "นี่คือการแลกที่ NoSQL บังคับให้เลือก ไม่มีทางเลือกที่ได้ทุกอย่าง" · เกณฑ์ตัดสิน: จดซ้ำสิ่งที่ต้องโชว์บนหน้ารายการและเปลี่ยนไม่บ่อย เช่นชื่อคน ชื่อประเภท · ตอบไม่ได้ว่าเปลี่ยนบ่อยไหม ให้จดซ้ำไว้ก่อน

# แปลง DB Schema เป็นโฟลเดอร์ — กติกา 4 ข้อ

> note: บอกว่า "สี่บรรทัดนี้คือทั้งหมดของการแปลง ถ่ายรูปสไลด์นี้เก็บไว้ ตอนบ่ายกลุ่มคุณใช้มันวาดแบบของโครงงานตัวเองบนกระดาษ" · อธิบายข้อสาม "ช่องที่ชี้ไปตารางอื่น ศัพท์ทางการคือ Foreign Key เช่นช่องผู้แจ้งที่ชี้ไปตาราง users"

# Firestore — ตู้เก็บข้อมูลบนคลาวด์

- เก็บเป็น 📁 โฟลเดอร์ 📄 ไฟล์ แบบที่เพิ่งเรียนเป๊ะ ๆ

> note: พูดว่า "ข้อสามคือของขวัญของ Firebase ครับ หลักสูตรทั่วไปต้องเขียนตัวกลางเองอีกชั้น เราข้ามไปได้ทั้งชั้น" · ถามว่า "กลุ่มไหนเข้า Firebase console ไม่ได้ หรือลืมรหัส พิมพ์ 1 ในแชท" ให้ TA ตามช่วยก่อนบ่าย

> note: ชี้ทีละกล่องจากซ้าย "ผู้ใช้เปิดหน้ารายการ หน้าเว็บไปถามตู้ Firestore ส่งข้อมูลกลับมา แล้วแสดงบนจอ" · หยุดที่กล่องเข้ม "กล่องนี้กล่องเดียวอยู่บนคลาวด์ ที่เหลืออยู่ในเครื่องคุณ ข้อมูลจึงไม่หายตอนปิดเบราว์เซอร์" · ปิดท้าย "สังเกตว่าลูกศรวิ่งทางเดียว วันนี้เราอ่านอย่างเดียว ยังไม่เขียนจากหน้าเว็บ"

# วันนี้ทำตัว R ตัวเดียว — CRUD ที่เหลือสัปดาห์หน้า

| ตัว | แปลว่า | ทำเมื่อไร |
|:---:|---|---|
| C | เพิ่มข้อมูลจากหน้าเว็บ | สัปดาห์ที่ 7 |
| **R** | **อ่านข้อมูลมาแสดง** | **วันนี้** ⭐ |
| U / D | แก้ / ลบ | สัปดาห์ที่ 7 |

> note: แปลศัพท์ CRUD = เพิ่ม ดู แก้ ลบ ข้อมูล · ย้ำหนัก ๆ ว่า "วันนี้ห้ามทำเกินตัว R นะครับ กลุ่มที่รีบไปทำปุ่มบันทึกวันนี้ จะไปพังตอนสัปดาห์ที่ 7 ซึ่งมีที่ทางของมันอยู่แล้ว" · ส่วนข้อมูลที่ใส่วันนี้ใช้ตัวช่วยที่เรียกว่า seed ซึ่งอยู่สไลด์ถัดไป

# 4 ขั้นที่ผมจะทำให้ดู


> note: ไล่ทีละกล่อง "หนึ่ง เปิด Firestore ในโหมดทดสอบ · สอง เชื่อมเว็บกับตู้ แล้วใส่ข้อมูลตัวอย่างที่เรียกว่า seed · สาม เปิด Console ส่องด้วยตาว่าข้อมูลเข้าจริง · สี่ ต่อหน้ารายการให้อ่านจากตู้จริง" · หยุดที่กล่องเข้ม "ขั้นที่สามคือขั้นที่คนข้ามแล้วเจ็บที่สุด สร้างเสร็จต้องส่องด้วยตาเสมอ"

# โหมดทดสอบ — ประตูตู้ยังเปิดอยู่

- **โหมดทดสอบ (test mode)** = ตู้ที่ใครมีที่อยู่ก็เปิดอ่านเขียนได้
- มีวันหมดอายุ — **จดวันที่ไว้** เลยแล้วระบบจะเงียบใส่
- 🚫 ห้ามใส่ข้อมูลจริงของคนอื่น — ใช้ชื่อสมมติ สมชาย สมหญิง
- 🔑 กุญแจจริง (ล็อกอิน + กฎ) มาสัปดาห์ที่ 7–8

> note: พูดว่า "โหมดทดสอบเหมาะกับวันนี้เพราะเรายังไม่มีล็อกอิน แต่มันคือตู้ที่ไม่ล็อกกุญแจ ห้ามใส่ข้อมูลจริงของใครเด็ดขาด" · จำนวนวันหมดอายุขึ้นกับ Firebase **ตรวจสอบล่าสุดก่อนสอน** ตอนสาธิตให้ซูมที่วันหมดอายุแล้วให้ทุกกลุ่มจดของตัวเองตอนบ่าย

> note: พูดว่า "เมื่อเช้าผมบอกว่า prompt ต้องสั้น วันนี้มีข้อยกเว้นเดียวคือตอนใส่ข้อมูลตัวอย่าง เพราะต้องระบุชื่อช่องข้อมูลให้ครบทุกตัวจากแบบบนกระดาษ ห้ามให้ AI เดา" · ย้ำว่าใบงานบ่ายนี้เขียนกำกับไว้ตรงจุดนั้นแล้วว่าทำไมยาวได้

# prompt สรุปสถานะ — เก็บความจำก่อนล้าง

```prompt พิมพ์ก่อนล้างบทสนทนาเสมอ
สรุปสถานะโปรเจกต์ตอนนี้ให้ผมเป็นข้อ ๆ
เขียนให้ผมคัดลอกไปเริ่มบทสนทนาใหม่ได้เลย
```

- อ่านสรุปแล้วตอบว่าอะไรขาด — ใช้จังหวะที่ 3 เหมือนตรวจแผน
- คัดลอกเก็บลงไฟล์ `บันทึกสถานะ.md` ในโปรเจกต์

> note: พูดว่า "อย่าล้างบทสนทนาทิ้งเฉย ๆ นะครับ เก็บสรุปก่อน ไม่งั้นต้องเล่าใหม่ทั้งหมด" · ย้ำข้อแรก "สรุปที่ AI เขียนก็ต้องตรวจ เหมือนแผน ถ้าขาดข้อตกลงเรื่องชื่อสถานะ บอกกลับไปว่าขาด"

# เริ่มรอบใหม่ — /clear

```code
/clear      ล้างบทสนทนาปัจจุบันทั้งหมด แล้วเริ่มจากศูนย์
```

- 📌 **ไฟล์ในโปรเจกต์ไม่ได้ถูกล้างไปด้วย ยังอยู่ครบทุกไฟล์**
- สิ่งที่หายคือความจำของบทสนทนาเท่านั้น
- เริ่มรอบใหม่แล้ว วางสรุปสถานะเป็นข้อความแรก

> note: **ย้ำข้อแรกให้หนักที่สุด** "คำว่าล้างทำให้คนกลัวจนไม่กล้าพิมพ์ ผมยืนยันว่าไฟล์ในโฟลเดอร์ไม่หายสักไฟล์ หายเฉพาะความจำของบทสนทนา" · ให้ทุกคนพิมพ์ในแชทว่าเข้าใจข้อนี้แล้วก่อนไปต่อ

# ยังไม่อยากเริ่มใหม่ — /compact

```code
/compact                    ย่อบทสนทนาให้สั้นลง คืนพื้นที่ความจำ
/compact เน้นเรื่องหน้าจอ    บอกได้ว่าให้เก็บเรื่องไหนไว้
```

- คุยต่อได้เลย ไม่ได้เริ่มใหม่ ข้อตกลงยังอยู่แบบย่อ
- ทางเลือกกลาง ระหว่างคุยต่อจนมั่ว กับล้างทิ้งทั้งหมด

> note: พูดว่า "บางทีเราไม่อยากทิ้งบทสนทนาทั้งอัน คำสั่งนี้ย่อของเก่าให้สั้นลง คืนพื้นที่ความจำ แล้วคุยต่อได้เลย" · ชี้บรรทัดสอง "เติมข้อความต่อท้ายเพื่อบอกว่าให้เก็บเรื่องไหนไว้เป็นพิเศษได้ด้วย"

# ความจำเริ่มเต็ม — เลือกทางไหน

| ทางเลือก | เลือกเมื่อ | ความจำเดิม |
|---|---|---|
| คุยต่อ | เพิ่งเริ่ม ยังตอบตรงอยู่ | อยู่ครบ |
| `/compact` | เริ่มช้าลง แต่ยังทำเรื่องเดิม | เหลือแบบย่อ |
| `/clear` | เปลี่ยนเรื่องใหม่ หรือลืมข้อตกลงแล้ว | ไม่เหลือ |

> note: อ่านทีละแถว แล้วพูดว่า "สามทางนี้ไม่มีทางไหนผิด ต่างกันที่สถานการณ์" · ย้ำแถวกลาง "/compact คือทางตรงกลางที่หลายคนไม่รู้ว่ามี" · ปิดท้ายว่า "บ่ายนี้ขอให้ทุกกลุ่มได้ใช้จริงอย่างน้อยหนึ่งครั้ง ใบงานมีจุดให้ใช้"

# Token = เวลา และเงิน — เปิดดูด้วย /usage

```code
/usage      เปิดดูปริมาณการใช้งานของบัญชีคุณ
```

- บทสนทนายาว ๆ กินโควตาเร็วกว่าที่คิด
- ⚠️ สิ่งที่เห็นขึ้นกับประเภทบัญชี — เปิดดูของตัวเองแล้วจดไว้
- ⚠️ คำสั่งเปลี่ยนตามเวอร์ชันได้ ไม่ได้ผลให้พิมพ์ `/help`

> note: พูดว่า "โควตาไม่ได้ไม่จำกัดนะครับ กลุ่มที่คุยยาวโดยไม่จัดการความจำ จะหมดโควตากลางคาบ ผมเห็นมาทุกรุ่น" · ห้ามบอกว่าทุกคนจะเห็นหน้าตาเดียวกัน เพราะบัญชีต่างประเภทแสดงต่างกัน ให้เปิดดูเองแล้วจด
