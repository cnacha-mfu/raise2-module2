## 🔁 วิธีสั่งงาน AI ที่สาธิตทั้งวันนี้ — วงจร 4 จังหวะ

```
1️⃣ สั่งสั้น 1–3 บรรทัด  →  2️⃣ AI เขียนแผน  →  3️⃣ เราตรวจและแก้แผน  →  4️⃣ สั่งลงมือทีละข้อ
```

- **prompt ทุกอันในเอกสารนี้สั้น 1–3 บรรทัด** เพราะรายละเอียดที่เหลือเราไปบอกในจังหวะที่ 3 ตอนที่เห็นแผนแล้ว
- **ขั้นที่ 5 คือรอบเต็มของวงจรนี้ ห้ามตัด** — ผู้เรียนต้องเห็นทั้งตอนที่ AI เขียนแผนมาผิด และตอนที่ผู้สอนแก้แผนด้วยประโยคเดียว
- ⚠️ **จังหวะที่ 3 คือจังหวะที่ผู้เรียนต้องทำเองทั้งเดือน** ทุกครั้งที่สาธิตถึงจังหวะนี้ ให้หยุดและพูดออกเสียงว่า "ตรงนี้คืองานของคุณ"

### ⌨️ คำสั่งของ Claude Code ที่สาธิตในเอกสารนี้ — สาธิตตรงจุดที่มันแก้ปัญหา

| คำสั่ง | สาธิตที่ | แก้ปัญหาอะไร |
|---|---|---|
| `Esc` · `Esc Esc` · `/rewind` | ขั้นที่ 7 | สั่งแล้วพัง อยากย้อนทันทีระหว่างทำงาน |
| `/compact` | ขั้นที่ 8 (ขั้นกู้ที่ 3) | ความจำเริ่มเต็ม แต่ยังอยากคุยเรื่องเดิมต่อ |
| `/clear` | ขั้นที่ 8 (ขั้นกู้ที่ 4) | ต้องเริ่มบทสนทนาใหม่จริง ๆ |
| `/usage` | ขั้นที่ 9 | อยากรู้ว่าใช้โควตาไปเท่าไรแล้ว |

> ⚠️ **บรรทัดที่ต้องพูดออกเสียงอย่างน้อย 1 ครั้งในคาบนี้:** "คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ"
> 🔧 **เตรียมตัวก่อนคาบ:** ลองพิมพ์ทั้ง 5 คำสั่งนี้ในเครื่องตัวเอง 1 รอบ **ให้เห็นกับตาว่าเวอร์ชันของคุณแสดงหน้าตาแบบไหน** จะได้ไม่ต้องเดาต่อหน้าห้อง

# บล็อก A — สร้างโปรเจกต์ FixIt ⏱ 18 นาที

### ขั้นที่ 1 — สร้างโฟลเดอร์และเริ่มต้นโปรเจกต์ Node ⏱ 5 นาที

**พูดว่า:** "เราจะเริ่มจากศูนย์จริง ๆ นะครับ ตอนนี้บน Desktop ผมมีโฟลเดอร์ว่าง ๆ อยู่หนึ่งอัน ชื่อ fixit-demo ข้างในไม่มีอะไรเลย"

**ทำ:**
1. ลากหน้าต่าง File Explorer มาให้เห็นโฟลเดอร์ว่าง
2. สลับไป terminal พิมพ์คำสั่งเข้าโฟลเดอร์

```
cd Desktop/fixit-demo
```

3. พิมพ์คำสั่งเริ่มต้นโปรเจกต์

```
npm init -y
```

**ผู้เรียนจะเห็น:** terminal พิมพ์ข้อความสีเทาออกมาประมาณ 12 บรรทัด ที่ขึ้นต้นด้วย `Wrote to ...package.json` และมีเนื้อหาที่ดูเหมือนรายการในวงเล็บปีกกา · ใน File Explorer มี **ไฟล์ใหม่ 1 ไฟล์ชื่อ `package.json`** โผล่ขึ้นมา

**ชี้ให้ดูตรงนี้:** ชี้เมาส์ค้างที่ไฟล์ `package.json` ใน File Explorer แล้วพูดว่า "ไฟล์นี้คือใบรายการชิ้นส่วนของโปรเจกต์ ตอนนี้ยังว่าง ๆ เดี๋ยวมันจะยาวขึ้นเรื่อย ๆ คุณไม่ต้องแก้ไฟล์นี้เองเลยทั้งเดือน"

**เชื่อมเข้า Workshop:** "ตรงนี้ของ FixIt คือโฟลเดอร์ `fixit-demo` — **ถ้าเป็น LeaveEasy ขั้นนี้จะได้โฟลเดอร์ `leaveeasy`** — **แล้วของกลุ่มคุณล่ะ ชื่อโฟลเดอร์โครงงานของกลุ่มคืออะไร** ตอนบ่ายกลุ่มคุณจะสร้างมันด้วยสองคำสั่งเดียวกันนี้"

> 🆘 **ถ้า `npm init -y` ขึ้นว่าไม่รู้จักคำสั่ง:** ปิด terminal แล้วเปิดใหม่ 1 ครั้ง · ถ้ายังไม่ได้ ให้พูดว่า "อาการนี้ตอนบ่ายจะมีคนเจอ ผมเตรียมห้องย่อยไว้ให้แล้ว" แล้วสลับไปโฟลเดอร์ `fixit-backup` ทำต่อ อย่าไล่แก้สดหน้าห้อง

### ขั้นที่ 2 — `git init` และ commit แรกทันที ⏱ 5 นาที

**พูดว่า:** "ก่อนจะให้ AI แตะโปรเจกต์นี้ ผมขอติดปุ่มย้อนเวลาก่อนครับ นี่คือกฎข้อแรกของ Module นี้ ปุ่มย้อนต้องมาก่อนเสมอ · Git ทุกคนใช้เป็นแล้วจาก Module 1 ผมทวนสามคำสั่งนี้ให้เห็นจังหวะเฉย ๆ"

**ทำ:** พิมพ์ทีละบรรทัด **หยุดอ่านออกเสียงทุกบรรทัด**

```
git init
git add .
git commit -m "เริ่มต้นโปรเจกต์ FixIt"
```

**ผู้เรียนจะเห็น:**
- บรรทัดแรก ขึ้นข้อความ `Initialized empty Git repository in ...`
- บรรทัดที่สาม ขึ้นข้อความประมาณ `[main (root-commit) a1b2c3d] เริ่มต้นโปรเจกต์ FixIt` และบรรทัดว่า `1 file changed`

**ทำต่อ:** พิมพ์

```
git log --oneline
```

**ผู้เรียนจะเห็น:** 1 บรรทัด เป็นรหัสสั้น ๆ ตามด้วยข้อความ `เริ่มต้นโปรเจกต์ FixIt`

**ชี้ให้ดูตรงนี้:** ชี้ที่บรรทัดใน `git log` แล้วพูดว่า "นี่คือหมุดตัวแรกของเรา ตั้งแต่นาทีนี้เป็นต้นไป ไม่ว่าจะพังยังไง ผมกลับมาที่จุดนี้ได้เสมอ"

**เชื่อมเข้า Workshop:** "ตอนบ่ายส่วน A ของใบงาน คือสามคำสั่งนี้เป๊ะ ๆ — **ถ้าเป็น LeaveEasy ข้อความ commit จะเป็น เริ่มต้นโปรเจกต์ LeaveEasy** — **แล้วของกลุ่มคุณจะเขียนว่าอะไร**"

> 🆘 **ถ้า git ถามหาชื่อและอีเมล** (ขึ้นข้อความ `Please tell me who you are`) ให้พูดว่า "เจอแล้วครับ อาการคลาสสิก เครื่องยังไม่รู้จักเรา" แล้วพิมพ์ 2 บรรทัดนี้ให้ดู แล้ว commit ใหม่
> ```
> git config --global user.name "ชื่อผู้สอน"
> git config --global user.email "อีเมลผู้สอน"
> ```

### ขั้นที่ 3 — เปิด Claude Code แล้วให้อ่าน Spec ⏱ 8 นาที

**พูดว่า:** "ทีนี้ถึงเวลาเรียกผู้ช่วยเข้ามาแล้วครับ แต่ก่อนจะให้มันสร้างอะไร ผมจะให้มันอ่านโจทย์แล้วเล่ากลับมาให้ผมฟังก่อน"

**ทำ:**
1. ลากไฟล์ `fixit-spec.md` จาก Desktop เข้าโฟลเดอร์ `fixit-demo` **ให้ผู้เรียนเห็นการลาก**
2. ใน terminal พิมพ์ `claude` เพื่อเปิด Claude Code ในโฟลเดอร์นี้
3. วาง prompt ด้านล่าง

**prompt ที่ใช้ (จังหวะที่ 1 — สั่งสั้น):**

> อ่านไฟล์ fixit-spec.md แล้วสรุปให้ผมฟังเป็นข้อ ๆ
> ว่าระบบนี้ทำอะไร มีกี่หน้าจอ ผู้ใช้มีกี่บทบาท

**ผู้เรียนจะเห็น:** Claude Code แสดงบรรทัดว่ากำลังอ่านไฟล์ `fixit-spec.md` แล้วพิมพ์สรุปออกมาเป็น 3 ข้อ ระบุว่าเป็นระบบแจ้งซ่อม มี 5 หน้าจอ (รายการใบแจ้งซ่อม · แจ้งซ่อมใหม่ · รายละเอียดใบแจ้ง · จัดการหมวดหมู่ · แดชบอร์ด) และมี 3 บทบาท (ผู้แจ้ง · ช่างซ่อม · ผู้ดูแลระบบ)

**ชี้ให้ดูตรงนี้:** อ่านข้อ 2 ออกเสียงทีละหน้า แล้วพูดว่า "ครบ 5 หน้าตรงกับที่ผมเขียนไว้ แปลว่า Spec ของผมชัดพอ ถ้าตรงนี้มันสรุปมาผิดหรือขาดไปหน้าหนึ่ง อย่าเพิ่งไปต่อนะครับ กลับไปแก้ Spec ก่อน เพราะปัญหาอยู่ที่เอกสาร ไม่ได้อยู่ที่ AI"

**ทำต่อ (สำคัญ):** commit ทันที

```
git add .
git commit -m "เพิ่มไฟล์ spec ของ FixIt"
```

**เชื่อมเข้า Workshop:** "ตอนบ่ายกลุ่มคุณจะทำแบบนี้กับ **Tech Spec ของกลุ่มเองจาก Module 1** — **ถ้าเป็น LeaveEasy ขั้นนี้จะได้สรุปว่ามี 5 หน้าจอและ 3 บทบาท** — **แล้วของกลุ่มคุณ AI สรุปได้กี่หน้าจอ ตรงกับที่กลุ่มเขียนไว้ไหม** ถ้าไม่ตรง อย่าเพิ่งไปต่อ กลับไปแก้ Tech Spec ก่อน"

> 🆘 **ถ้า Claude Code หาไฟล์ไม่เจอ:** พิมพ์ `dir` (Windows) หรือ `ls` (macOS) ให้ดูว่าไฟล์อยู่ในโฟลเดอร์จริงไหม · ใช้จังหวะนี้สอนว่า "AI เห็นเฉพาะไฟล์ที่อยู่ในโฟลเดอร์ที่เราเปิดมันขึ้นมา ไม่เห็นทั้งเครื่อง"

# บล็อก B — สร้างหน้าจอ FixIt ทีละหน้า ⏱ 28 นาที

### ขั้นที่ 4 — ทำให้หน้าแรกขึ้นในเบราว์เซอร์ ⏱ 8 นาที

**พูดว่า:** "เป้าหมายของขั้นนี้มีอย่างเดียว คือให้เบราว์เซอร์ขึ้นหน้าอะไรก็ได้ที่เป็นของเรา ยังไม่ต้องสวย ขอให้ขึ้นก่อน"

**จังหวะที่ 1 — สั่งสั้น · prompt ที่ใช้:**

> ผมอยากให้หน้าแรกของ FixIt เปิดดูในเบราว์เซอร์ได้
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**จังหวะที่ 2 — AI เขียนแผน** · **ผู้เรียนจะเห็น:** แผนเป็นข้อ ๆ ประมาณ 4 ข้อ ยังไม่มีไฟล์ไหนถูกสร้าง

**จังหวะที่ 3 — เราแก้แผน · prompt ที่ใช้:**

> ขอใช้ HTML CSS JavaScript ธรรมดา ไม่ต้องเพิ่มเครื่องมืออื่น
> และขอลิงก์ว่างไว้ 5 ลิงก์ตามชื่อหน้าจอใน spec
> ที่เหลือโอเค

**จังหวะที่ 4 — สั่งลงมือ · prompt ที่ใช้:**

> แผนโอเคแล้ว ลงมือได้ ทำหน้าแรกหน้าเดียวก่อน

**ผู้เรียนจะเห็น:** Claude Code สร้างไฟล์ `index.html` · แก้ `package.json` · ติดตั้งชิ้นส่วนสำหรับเปิดเว็บในเครื่อง (จะเห็นข้อความ `added ... packages` วิ่งขึ้นมา) ใช้เวลาประมาณ 1–2 นาที

**ทำ:** พิมพ์

```
npm run dev
```

แล้วเปิดเบราว์เซอร์ไปที่ที่อยู่ที่ terminal บอก (มักเป็น `http://localhost:3000` หรือ `http://127.0.0.1:8080`)

**ผู้เรียนจะเห็น:** หน้าเว็บพื้นขาว มีคำว่า **FixIt ระบบแจ้งซ่อมออนไลน์** ตัวใหญ่ และลิงก์สีน้ำเงิน 5 บรรทัดใต้ลงมา

**ชี้ให้ดูตรงนี้:** ⭐ **หยุดตรงนี้ 15 วินาที** ชี้ที่แถบ URL แล้วพูดว่า "คำว่า localhost แปลว่า เว็บนี้ยังอยู่ในเครื่องผมคนเดียว คนอื่นเปิดไม่ได้ สัปดาห์ที่ 8 เราจะทำให้มันมีที่อยู่จริงที่คนอื่นเปิดได้ วันนี้เราอยู่ในเครื่องตัวเองก่อน"

**ทำต่อ:** commit

```

```

**เชื่อมเข้า Workshop:** "ตรงนี้คือ Checkpoint 1 ของใบงานบ่ายนี้พอดีเลยครับ — **ถ้าเป็น LeaveEasy ขั้นนี้จะได้หน้าแรกที่เขียนว่า LeaveEasy ระบบขอลาออนไลน์** — **แล้วของกลุ่มคุณ หน้าแรกจะเขียนว่าอะไร**"

> 🆘 **ถ้า `npm run dev` ขึ้น error เรื่อง port ถูกใช้อยู่:** พูดว่า "แปลว่ามีเว็บอื่นจองช่องนี้อยู่แล้ว" แล้ววาง prompt นี้ > เปลี่ยนพอร์ตของ npm run dev เป็น 5500 แล้วบอกที่อยู่ใหม่ให้ผมด้วย

### ขั้นที่ 5 — ⭐ หน้ารายการใบแจ้งซ่อม (เดินครบวงจร 4 จังหวะ) ⏱ 8 นาที

> 🔑 **ขั้นนี้คือรอบเต็มของวงจร 4 จังหวะ ห้ามตัด** — ผู้เรียนต้องเห็นด้วยตาว่า **แผนที่ AI เขียนมาไม่ได้ถูกเสมอ** และเห็นว่าการแก้แผนใช้ประโยคเดียว

**พูดว่า:** "หน้านี้ผมจะทำให้ดูครบทั้ง 4 จังหวะที่เพิ่งสอนไป สั่งสั้น ให้ AI เขียนแผน เราตรวจแผน แล้วค่อยสั่งลงมือ ดูให้ดีนะครับ ตอนบ่ายคุณจะทำซ้ำ 5 รอบ"

#### จังหวะที่ 1 — สั่งสั้น

**prompt ที่ใช้:**

> ผมอยากได้หน้ารายการใบแจ้งซ่อม แสดงเป็นตาราง
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**ชี้ให้ดูตรงนี้:** ชี้ที่ prompt ก่อนกด Enter แล้วพูดว่า "สองบรรทัดครับ ผมยังไม่ได้บอกคอลัมน์ ไม่ได้บอกจำนวนข้อมูล เดี๋ยวผมไปบอกตอนเห็นแผนแล้ว"

#### จังหวะที่ 2 — AI เขียนแผน

**ผู้เรียนจะเห็น:** Claude Code ตอบเป็นข้อ ๆ ประมาณ 4–5 ข้อ **ไม่มีโค้ดสักบรรทัดและยังไม่มีไฟล์ถูกสร้าง** หน้าตาประมาณนี้

```
1. สร้างไฟล์ tickets.html
2. ทำตาราง คอลัมน์ หัวข้อ สถานะ วันที่แจ้ง
3. สถานะแสดงเป็นข้อความธรรมดา
4. ใส่ข้อมูลตัวอย่างในโค้ด 3 รายการ
5. ทำลิงก์จากหน้าแรกมาที่หน้านี้
```

**ชี้ให้ดูตรงนี้:** อ่านแผนออกเสียงทีละข้อ **แล้วหยุด** พูดว่า "อ่านตรงนี้ 20 วินาที ประหยัดการรื้อทีหลัง 20 นาทีครับ"

#### 💥 จุดที่แผนมาผิด — จงใจให้ผู้เรียนเห็น

แผนที่ AI เขียนมักขาดหรือไม่ตรงใจอย่างน้อย 1 ข้อเสมอ **อย่ารีบผ่านจุดนี้** ให้ชี้ทีละจุด

| ข้อในแผน | ปัญหาที่ผู้สอนต้องชี้ |
|:--:|---|
| ข้อ 2 | ขาดคอลัมน์ **หมวดหมู่** กับ **ผู้แจ้ง** ที่ระบบนี้ต้องใช้ |
| ข้อ 4 | ข้อมูลตัวอย่าง **3 รายการ** ผมอยากได้ **5** |

**พูดตอนนี้:** "ถ้าผมพิมพ์ว่าโอเคไปตอนนี้ ผมจะได้ตารางที่ขาดสองคอลัมน์ แล้วต้องมานั่งไล่แก้ทีหลัง — จังหวะที่สามมีไว้ตรงนี้เอง"

> 📌 **ถ้ารอบนั้นแผนออกมาถูกหมดจริง ๆ:** อย่าฝืนแกล้งหาที่ผิด ให้เปลี่ยนเป็นการ *เพิ่ม* แทน พูดว่า "แผนรอบนี้ดีครับ ผมจะขอเพิ่มอีกหนึ่งอย่าง" แล้วใช้จังหวะที่ 3 ตามปกติ — บทเรียนยังครบ

#### จังหวะที่ 3 — เราแก้แผน ⭐

**prompt ที่ใช้:**

> ข้อ 2 ขอเพิ่มคอลัมน์ หมวดหมู่ กับ ผู้แจ้ง
> ข้อ 4 ขอเป็น 5 รายการ ใช้ชื่อสมมติ สมชาย สมหญิง
> ที่เหลือโอเค

**ผู้เรียนจะเห็น:** AI เขียนแผนใหม่ที่แก้สองข้อนั้นแล้ว **ข้ออื่นเหมือนเดิมทุกตัวอักษร**

**ชี้ให้ดูตรงนี้:** ⭐ **หยุด 10 วินาที** ชี้ที่ประโยค **"ที่เหลือโอเค"** แล้วพูดว่า "ผมไม่ได้เขียนคำสั่งใหม่ทั้งฉบับนะครับ ผมบอกไปสองข้อที่ไม่ใช่ แล้วบอกว่าที่เหลือใช้ได้ — นี่คือสิ่งที่ผมบอกว่าทุกคนทำได้ คุณไม่ต้องเขียน prompt เก่ง คุณต้องอ่านแล้วบอกว่าข้อไหนไม่ใช่"

#### จังหวะที่ 4 — สั่งลงมือ

**prompt ที่ใช้:**

> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

**ผู้เรียนจะเห็น:** ไฟล์ใหม่ถูกสร้าง 2 ไฟล์ **ทีละไฟล์ พร้อมบอกว่าเสร็จข้อไหนแล้ว** · เบราว์เซอร์รีเฟรชเองแล้วขึ้นตาราง 5 แถว มีคอลัมน์ครบตามที่แก้แผนไว้

**ชี้ให้ดูตรงนี้:** ชี้ประโยค "เสร็จข้อไหนบอกผมก่อน" แล้วพูดว่า "ประโยคนี้ทำให้เราตรวจได้ทีละข้อ ไม่ใช่มารู้ตอนพังทั้งก้อน"

**ขั้นตรวจด้วยตา:** กลับไปหน้าแรก → กดลิงก์ → เข้าหน้ารายการ → กด Back → กลับหน้าแรก **ทำให้ดูจริง ๆ ทีละคลิก**

**พูดว่า:** "สังเกตนะครับ ผมไม่ได้อ่านโค้ดเลยสักบรรทัด ผมเปิดดูด้วยตาแล้วกดจริง นี่คือการตรวจที่ผมขอให้ทุกคนทำ"

**ขั้น commit:**

```
git add .
git commit -m "เพิ่มหน้ารายการใบแจ้งซ่อม พร้อมข้อมูลตัวอย่าง 5 รายการ"
```

**เชื่อมเข้า Workshop:** "ตรงนี้ของ FixIt คือหน้ารายการใบแจ้งซ่อม — **ถ้าเป็น LeaveEasy ขั้นนี้จะได้หน้ารายการใบลา คอลัมน์คือ หัวข้อ ประเภทการลา สถานะ ผู้ขอลา วันที่ลา** — **แล้วหน้ารายการของกลุ่มคุณ มีคอลัมน์อะไรบ้าง เปิด Tech Spec ของกลุ่มดูได้เลย**"

### ขั้นที่ 6 — หน้าแจ้งซ่อมใหม่ และวงจรแก้งาน ⏱ 7 นาที

**พูดว่า:** "หน้านี้ผมจะทำให้ดูอีกเรื่องหนึ่ง คือเวลาผลลัพธ์ออกมาไม่ตรงใจ เราคุยกับมันต่ออย่างไร"

**จังหวะที่ 1 — prompt ที่ใช้:**

> ผมอยากได้หน้าแจ้งซ่อมใหม่ 1 หน้า เป็นฟอร์มกรอก
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**จังหวะที่ 3 — แก้แผน · prompt ที่ใช้:**

> ช่องกรอกขอเป็น หัวข้อ รายละเอียด หมวดหมู่ ผู้แจ้ง
> ปุ่มบันทึกยังไม่ต้องทำงานจริง กดแล้วขึ้นข้อความพอ
> ที่เหลือโอเค

**จังหวะที่ 4 — prompt ที่ใช้:**

> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ

**ผู้เรียนจะเห็น:** หน้าฟอร์มขึ้นมา มีช่องกรอก 4 ช่อง และปุ่ม 2 ปุ่ม

**ทำ:** กดปุ่มบันทึกให้ดู → ขึ้นข้อความ

**พูดว่า:** "ผลออกมาใช้ได้ แต่ผมไม่ชอบที่ช่องรายละเอียดมันเตี้ยไป และหมวดหมู่ควรเป็นรายการให้เลือก ไม่ใช่ช่องพิมพ์ ผมจะสั่งแก้ต่อ ไม่ต้องรื้อทำใหม่"

**prompt ที่ใช้ (สั่งแก้ต่อ — งานเล็ก สั่งตรงได้ ไม่ต้องขอแผน):**

> ดูเฉพาะไฟล์หน้าแจ้งซ่อมใหม่
> ช่องรายละเอียดขอเป็นกล่องหลายบรรทัด และหมวดหมู่ขอเป็นรายการเลือก
> ไฟล์อื่นยังไม่ต้องแตะ

> 📌 **พูดตรงนี้ด้วย:** "งานที่เล็กกว่าหนึ่งขั้นแบบนี้ สั่งตรงได้เลยครับ ไม่ต้องขอแผน · กติกาคือ **งานที่ใหญ่กว่าหนึ่งขั้นเมื่อไร ให้กลับไปขอแผนก่อนเสมอ**"

**ผู้เรียนจะเห็น:** เบราว์เซอร์รีเฟรช ช่องรายละเอียดสูงขึ้นชัดเจน และหมวดหมู่กลายเป็นรายการเลื่อนลงที่กดแล้วเห็น 5 ตัวเลือก

**ชี้ให้ดูตรงนี้:** ชี้ประโยค **"ไฟล์อื่นยังไม่ต้องแตะ"** ใน prompt แล้วพูดว่า "ประโยคนี้ผมใส่ทุกครั้งครับ เพราะบางทีมันจะไปแก้ไฟล์อื่นที่เราไม่ได้ขอ แล้วเราจะไม่รู้ตัว"

**ขั้น commit:**

```
git add .
git commit -m "เพิ่มหน้าแจ้งซ่อมใหม่ และปรับช่องกรอกให้ใช้งานง่ายขึ้น"
```

**เชื่อมเข้า Workshop:** "**ถ้าเป็น LeaveEasy ขั้นนี้จะได้หน้ายื่นใบลาใหม่ ช่องเลือกคือประเภทการลา ลาพักร้อน ลาป่วย ลากิจ** — **แล้วฟอร์มหลักของกลุ่มคุณคือฟอร์มอะไร และมีช่องเลือกอะไรบ้าง**"

### ขั้นที่ 7 — สาธิตการย้อนของจริง · ตาข่าย 2 ชั้น ⏱ 6 นาที

**พูดว่า:** "ทีนี้ผมจะทำสิ่งที่ผู้เรียนกลัวที่สุดให้ดู คือสั่งอะไรมั่ว ๆ แล้วหน้าจอพัง แล้วจะกู้ยังไง"

> ⚠️ **prompt ข้างล่างนี้คือตัวอย่างที่ผิดโดยตั้งใจ** — ยาวรวดเดียว สั่ง 4 อย่างพร้อมกัน และ **ไม่ขอแผนก่อน** ให้บอกผู้เรียนออกเสียงก่อนกด Enter ว่า "อันนี้ผมกำลังทำสิ่งที่เพิ่งบอกว่าห้ามทำนะครับ ดูว่าจะเกิดอะไรขึ้น"

**prompt ที่ใช้ (ตั้งใจให้ผลลัพธ์เละ · ห้ามให้ผู้เรียนคัดลอกไปใช้):**

> เปลี่ยนหน้าตาทั้งเว็บให้เป็นธีมสีเข้ม
> และย้ายเมนูไปด้านซ้าย
> และเปลี่ยนฟอนต์ทั้งหมด
> และทำให้ตารางเป็นการ์ดแทน
> ทำทั้งหมดนี้พร้อมกันเลย

**ผู้เรียนจะเห็น:** หน้าเว็บเปลี่ยนไปมาก มักมีอย่างน้อย 1 จุดที่เสีย เช่น ตัวหนังสือสีเข้มบนพื้นเข้มจนอ่านไม่ออก หรือเมนูซ้อนทับเนื้อหา

**พูดตอนนี้:** "เห็นไหมครับ ผมสั่ง 4 อย่างพร้อมกัน แล้วตอนนี้ผมบอกไม่ได้เลยว่าอันไหนทำให้พัง — นี่คือเหตุผลที่ผมย้ำว่าสั่งทีละอย่าง"

#### 🥅 ตาข่ายชั้นที่ 2 — git (ชั้นที่ลึกที่สุด ใช้ได้เสมอ)

**ทำ:** กู้ด้วยสองคำสั่ง อ่านออกเสียงทีละบรรทัด

```
git log --oneline
git checkout .
```

**ผู้เรียนจะเห็น:** `git log` แสดงรายการ commit 5 บรรทัดเรียงจากใหม่ไปเก่า · หลัง `git checkout .` เบราว์เซอร์รีเฟรชแล้ว **หน้าเว็บกลับมาเหมือนเดิมทุกอย่าง**

**ชี้ให้ดูตรงนี้:** ⭐ **หยุด 10 วินาที** แล้วพูดว่า "ห้าวินาที กลับมาที่จุดที่ยังดี ถ้าเมื่อกี้ผมไม่ commit ไว้ ผมต้องนั่งไล่แก้เป็นชั่วโมง นี่คือคำตอบว่าทำไมผม commit บ่อยขนาดนั้น"

#### 🥅 ตาข่ายชั้นที่ 1 — กด `Esc` สองครั้ง (เร็วกว่า ใช้ตอนรู้ตัวทันที) ⏱ 1 นาที

**พูดว่า:** "เมื่อกี้ผมย้อนด้วย git ซึ่งเป็นชั้นที่ลึกที่สุดและใช้ได้เสมอ · แต่ในกรณีที่คุณรู้ตัวทันทีว่าคำสั่งที่เพิ่งสั่งไปไม่ใช่ มีของที่เร็วกว่านั้นอยู่ในหน้าต่างนี้เลย ไม่ต้องพิมพ์คำสั่งอะไร"

**ทำ:**
1. สั่งอะไรเล็ก ๆ ที่รู้อยู่แล้วว่าไม่เอา เพื่อให้มีของให้ย้อน เช่น

> เปลี่ยนสีพื้นหลังทุกหน้าเป็นสีชมพู

2. รอจนมันทำเสร็จ แล้วรีเฟรชเบราว์เซอร์ให้เห็นว่าเปลี่ยนไปจริง
3. กลับไปที่หน้าต่าง Claude Code แล้ว **กดปุ่ม `Esc` สองครั้งติดกัน** · หยุดค้างไว้ให้ห้องอ่านเมนู 10 วินาที
4. เลือกย้อนกลับไปจุดก่อนคำสั่งสีชมพูนั้น แล้วรีเฟรชเบราว์เซอร์

**ผู้เรียนจะเห็น:** เมนูย้อนกลับขึ้นมาในหน้าต่าง Claude Code แสดงรายการจุดที่ย้อนกลับไปได้ · หลังเลือกแล้ว หน้าเว็บกลับมาเป็นเหมือนก่อนสั่ง **โดยไม่ได้พิมพ์คำสั่งใน terminal เลยสักตัว**

**ชี้ให้ดูตรงนี้:** ⭐ **หยุด 10 วินาที** แล้วพูดว่า "กด `Esc` หนึ่งครั้ง คือหยุดมันกลางคัน · กดสองครั้ง คือเปิดเมนูย้อนกลับ เลือกได้ว่าจะย้อนโค้ด ย้อนบทสนทนา หรือย้อนทั้งสองอย่าง · ใครถนัดพิมพ์ ใช้คำสั่ง `/rewind` ได้ผลเหมือนกัน"

**พูดปิดท้ายให้ครบทั้งสองชั้น — ห้ามข้าม:** "สรุปว่าคุณมีตาข่ายรับสองชั้นนะครับ · ชั้นที่หนึ่ง `Esc Esc` ย้อนได้ทันทีระหว่างทำงาน ใช้ตอนรู้ตัวเดี๋ยวนั้น · ชั้นที่สอง `git` ย้อนได้ถึงจุดที่ commit ไว้ ใช้ได้แม้ปิดหน้าต่างไปแล้วหรือพังข้ามวัน · **นี่คือคำตอบของคำถามที่ทุกคนถามผมทุกรุ่นว่า ถ้า AI แก้แล้วพังจะทำยังไง**"

> ⚠️ **ถ้าเมนูที่ขึ้นมาหน้าตาไม่เหมือนที่เขียนไว้ตรงนี้ หรือกดแล้วไม่มีอะไรขึ้น:** อย่าไล่แก้สดหน้าห้อง · พูดว่า **"คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชันนะครับ ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ"** แล้วพิมพ์ `/help` ให้ดู 1 ครั้ง จากนั้นเดินต่อ · **บทเรียนยังครบ เพราะ git คือชั้นที่เราพึ่งจริงอยู่แล้ว**
>
> ⏱ **ถ้าเวลากระชั้น:** ข้ามการสั่งสีชมพูในข้อ 1–2 ไป แล้วกด `Esc Esc` เปิดเมนูให้ดูเฉย ๆ พร้อมอธิบาย 3 บรรทัด **อย่าตัดทั้งหัวข้อนี้ทิ้ง** เพราะเป็นคำตอบของความกลัวอันดับ 1 ของผู้เรียน

**เชื่อมเข้า Workshop:** "ในตาราง 🆘 ของใบงานบ่ายนี้ มีข้อนี้อยู่ครับ — Claude แก้แล้วหน้าจอพังกว่าเดิม ให้ใช้สองคำสั่งนี้ และมี `Esc Esc` อยู่ในตารางนั้นด้วย · **กติกาของกลุ่มคือ คนที่พิมพ์คำสั่งที่ทำให้พัง ไม่ต้องเป็นคนแก้คนเดียว ให้คนตรวจอ่าน error ออกเสียงให้ทั้งกลุ่มฟังก่อน**"

> 📌 **ถ้าผลลัพธ์บังเอิญออกมาสวยและไม่พัง:** อย่าฝืนหาที่พัง ให้พูดแทนว่า "รอบนี้โชคดีครับ แต่ผมก็ยังไม่รู้อยู่ดีว่าคำสั่งไหนทำอะไร ผมจะย้อนกลับแล้วสั่งใหม่ทีละอย่าง" แล้วรัน `git checkout .` ตามปกติ บทเรียนยังครบ

# บล็อก C — Context และ Token ⏱ 20 นาที

## 💥 จุดที่ตั้งใจให้พัง (Planned Failure) — ขั้นที่ 8 ⏱ 14 นาที

**ทำไมต้องมี:** ผู้เรียนที่ไม่มีพื้นฐาน IT จะตีความว่า "AI ตอบแย่ลง = ฉันสั่งไม่เป็น" ต้องเห็นกับตาว่าผู้สอนก็เจอ และเป็นอาการของเครื่องมือ ไม่ใช่ความบกพร่องของคน

**ทำให้พังอย่างไร:** คุยต่อในบทสนทนาเดิมที่ยาวมาแล้ว โดยสั่งงานกระจัดกระจายติดกันหลายรอบ **จนมันลืมข้อตกลงที่ทำไว้ตอนต้น**

**ทำ — สั่ง 3 รอบติดกันในบทสนทนาเดิม (ห้ามเปิดใหม่):**

> ⚠️ **สาม prompt ข้างล่างนี้ผิดโดยตั้งใจทั้งหมด** — ยาว กระจัดกระจาย และไม่ขอแผนสักรอบ · **ห้ามให้ผู้เรียนคัดลอกไปใช้** ใช้เพื่อทำให้เห็นอาการเท่านั้น

รอบที่ 1
> อ่านทุกไฟล์ในโปรเจกต์นี้แล้วอธิบายให้ผมฟังว่าแต่ละไฟล์ทำอะไร

รอบที่ 2
> สร้างหน้ารายละเอียดใบแจ้งซ่อม กับหน้าจัดการหมวดหมู่ กับหน้าแดชบอร์ด
> แล้วปรับหน้าตาทั้งหมดให้เหมือนกัน

รอบที่ 3
> หน้าแดชบอร์ดยังไม่ตรง แก้ใหม่
> แล้วก็ปรับหน้ารายการด้วย แล้วก็เช็กหน้าแรกให้หน่อย

**ผู้เรียนจะเห็น (อย่างน้อย 1 อาการต่อไปนี้ ซึ่งเกิดขึ้นเกือบทุกครั้ง):**
- ชื่อสถานะเพี้ยนไปจากที่ตกลงไว้ เช่น กลายเป็น `Pending` `Done` ทั้งที่ตกลงกันว่าใช้ภาษาไทย
- ชื่อหมวดหมู่ในหน้าใหม่ไม่ตรงกับ 5 ตัวที่ใส่ไว้ในหน้าแจ้งซ่อมใหม่
- หน้าที่เพิ่งแก้ให้ดีแล้วในขั้นที่ 6 กลับมาเตี้ยเหมือนเดิม
- ตอบยาวมากแต่วนซ้ำ ไม่ได้แก้สิ่งที่ขอ

**พูดตอนพัง:** "เห็นไหมครับ ผมเองก็เจอ — และผมเจอทุกสัปดาห์ ไม่ใช่วันนี้วันเดียว มาดูกันว่าจะไล่ยังไง"

**ชี้ให้ดูตรงนี้:** เปิดหน้าจอที่ผิดขึ้นมาเทียบกับ prompt เดิมที่ตกลงเรื่องสถานะภาษาไทยไว้ตอนขั้นที่ 5 **เลื่อนขึ้นไปให้เห็นข้อความเดิมจริง ๆ** แล้วพูดว่า "ผมบอกไว้ชัดเมื่อ 20 นาทีที่แล้ว มันไม่ได้ดื้อ มันจำไม่ได้แล้ว โต๊ะมันเต็ม"

### วิธีกู้ทีละขั้น ⏱ อยู่ในเวลา 14 นาทีนี้

**ขั้นกู้ที่ 1 — ย้อนกลับก่อน** (อย่าแก้ทับของพัง)

```
git checkout .
```
**จะเห็น:** หน้าจอกลับไปเป็นเวอร์ชันที่ commit ไว้ล่าสุดที่ยังดี

**ขั้นกู้ที่ 2 — ขอสรุปสถานะก่อนทิ้งบทสนทนา**

> สรุปสถานะโปรเจกต์ตอนนี้ให้ผมเป็นข้อ ๆ
> เขียนให้ผมคัดลอกไปเริ่มบทสนทนาใหม่ได้เลย

**จะเห็น:** สรุปเป็นข้อ ๆ ยาวประมาณ 15–25 บรรทัด

**ชี้ให้ดูตรงนี้:** อ่านสรุปแล้วถามห้องว่า "ขาดอะไรไหมครับ" — ถ้าขาด ให้ใช้จังหวะที่ 3 บอกกลับไปสั้น ๆ เช่น *"ขาดข้อตกลงเรื่องชื่อสถานะภาษาไทย ใส่เพิ่มให้ด้วย"* แล้วพูดว่า "เห็นไหมครับ จังหวะตรวจแผนใช้ได้กับทุกอย่างที่ AI เขียนกลับมา ไม่ใช่เฉพาะตอนขอแผน"

**ขั้นกู้ที่ 3 — คัดลอกสรุปเก็บไว้** วางในไฟล์ `บันทึกสถานะ.md` ในโปรเจกต์ **ให้ผู้เรียนเห็นการวาง**

> 💬 **แทรกตรงนี้ 40 วินาที — ทางเลือกกลางที่ชื่อ `/compact`**
>
> **พูดว่า:** "ก่อนจะทิ้งบทสนทนานี้ ผมขอบอกทางเลือกกลางไว้ก่อนครับ ถ้าอาการยังไม่หนักถึงขั้นนี้ คือมันเริ่มช้าลงแต่ยังทำเรื่องเดิมอยู่ ให้พิมพ์ `/compact` แทน · มันจะย่อบทสนทนาที่ผ่านมาให้สั้นลงเพื่อคืนพื้นที่ความจำ **แต่เราคุยต่อได้เลย ไม่ได้เริ่มใหม่** และเติมต่อท้ายได้ด้วยว่าให้เก็บเรื่องไหนไว้ เช่น `/compact เน้นเรื่องหน้าจอที่ทำไปแล้ว`"
>
> **ทำ (ถ้าเวลาพอ):** พิมพ์ `/compact` ให้ดู 1 ครั้ง แล้วชี้ว่าบทสนทนาสั้นลงแต่ยังคุยต่อได้ · **ถ้าเวลากระชั้นให้พูดอย่างเดียว ไม่ต้องรัน**
>
> **แล้วพูดต่อ:** "แต่วันนี้อาการของผมหนักกว่านั้นครับ มันลืมข้อตกลงไปแล้ว ผมเลยจะล้างทิ้งแล้วเริ่มใหม่ให้ดู"

**ขั้นกู้ที่ 4 — เริ่มบทสนทนาใหม่ด้วย `/clear`** พิมพ์ `/clear` ในหน้าต่างเดิม **ไม่ต้องปิดหน้าต่าง** (จะปิดหน้าต่างแล้วเปิด Claude Code ใหม่ก็ได้ผลเหมือนกัน) แล้ววาง

> ⭐ **หยุดชี้ตรงนี้ 10 วินาที ก่อนพิมพ์ `/clear`:** พูดว่า "คำว่าล้าง ทำให้หลายคนไม่กล้าพิมพ์ ผมยืนยันตรงนี้ว่า **ไฟล์ในโปรเจกต์ไม่ได้ถูกล้างไปด้วย** ไฟล์ทุกไฟล์ยังอยู่ครบในโฟลเดอร์ สิ่งที่หายคือความจำของบทสนทนาเท่านั้น" · **หลังพิมพ์เสร็จ ให้เปิด File Explorer ให้ดูว่าไฟล์ยังอยู่ครบจริง** ภาพนี้คือสิ่งที่ทำให้ผู้เรียนกล้าใช้คำสั่งนี้ตอนบ่าย

> นี่คือสถานะโปรเจกต์ FixIt ของผม
> (วางสรุปที่คัดลอกไว้ตรงนี้)
>
> ผมอยากได้หน้าแดชบอร์ด 1 หน้า
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**ทำต่อ:** อ่านแผนที่ได้ แล้วใช้ **จังหวะที่ 3** แก้แผนด้วยประโยคสั้น ๆ ต่อหน้าห้อง

> ขอนับแยกตามสถานะ 4 สถานะตามที่ตกลงไว้ข้างบน
> ใช้ข้อมูลปลอมในโค้ดไปก่อน ไฟล์อื่นยังไม่ต้องแตะ
> ที่เหลือโอเค ลงมือได้เลย

**ผู้เรียนจะเห็น:** ⭐ **จุดที่ต้องหยุดชี้** — ผลลัพธ์รอบนี้ **ใช้สถานะภาษาไทยถูกทั้ง 4 สถานะ** และหน้าตาเข้าชุดกับหน้าเดิม ทั้งที่บทสนทนานี้เพิ่งเปิดใหม่และไม่รู้จักโปรเจกต์มาก่อน

**พูดว่า:** "บทสนทนาใหม่นี้ไม่รู้จักโปรเจกต์ผมมาก่อนเลยนะครับ แต่ผลออกมาดีกว่าเมื่อกี้ที่คุยกันมาเป็นชั่วโมง — เพราะผมให้เฉพาะสิ่งที่มันต้องใช้ ไม่ได้ให้ทุกอย่าง"

**commit ปิดท้าย:**

```
git add .
git commit -m "เพิ่มหน้าแดชบอร์ด หลังเริ่มบทสนทนาใหม่พร้อมสรุปสถานะ"
```

**เชื่อมเข้า Workshop:** "ส่วน C ของใบงานบ่ายนี้คือให้กลุ่มคุณทำแบบนี้ด้วยตัวเอง คุยยาว ๆ จนสังเกตอาการ แล้วจดว่าเห็นอาการอะไร แล้วเริ่มใหม่ แล้วเทียบผล · **ให้คนที่ไม่ได้พิมพ์เป็นคนจับอาการ เพราะคนที่พิมพ์จะไม่ทันสังเกต**"

### ขั้นที่ 9 — ปิดการสาธิต ⏱ 7 นาที

**ทำ:** พิมพ์

```
git log --oneline
```

**ผู้เรียนจะเห็น:** รายการ commit ประมาณ 7–8 บรรทัด **ที่ทุกบรรทัดเป็นภาษาไทยและอ่านแล้วรู้เรื่อง**

![screenshot: ผลของ git log --oneline ที่มี commit ภาษาไทย 7–8 บรรทัด](assets/w6-04-git-log-final.png)

**ชี้ให้ดูตรงนี้:** เลื่อนเมาส์ไล่ทีละบรรทัดจากล่างขึ้นบน แล้วเล่าเป็นเรื่องว่า "เริ่มโปรเจกต์ → ใส่ spec → หน้าแรกขึ้น → หน้ารายการ → หน้าแจ้งใหม่ → แดชบอร์ด" แล้วพูดว่า "นี่คือประวัติการทำงานของผมทั้งเช้า ย้อนกลับไปจุดไหนก็ได้"

**ทำต่อ:** เปิดเบราว์เซอร์ กดไล่ทั้ง 5 หน้าให้ดูรวดเดียว **อย่าอธิบายอะไรระหว่างนั้น** ให้ผู้เรียนเห็นว่าของทั้งหมดนี้ใช้เวลาไม่ถึงหนึ่งชั่วโมง

**ทำต่อ — ปิดท้ายด้วย `/usage` ⏱ 1 นาที:** กลับไปที่หน้าต่าง Claude Code แล้วพิมพ์

```
/usage
```

**พูดว่า:** "เมื่อกี้ผมบอกว่า token คือเวลาและเงิน คำสั่งนี้คือวิธีเปิดดูว่าตัวเองใช้ไปเท่าไรแล้วครับ"

**ผู้เรียนจะเห็น:** หน้าจอสรุปการใช้งานของบัญชีผู้สอน

> ⚠️ **ห้ามบอกผู้เรียนว่าเขาจะเห็นตัวเลขแบบเดียวกับที่ผู้สอนเห็น** · **สิ่งที่เห็นขึ้นกับประเภทบัญชี** บางแบบแสดงเป็นปริมาณการใช้งานรายเดือน บางแบบแสดงเป็นเครดิตคงเหลือ
> **พูดตามนี้:** "ของผมแสดงแบบนี้ ของคุณอาจแสดงคนละแบบ เพราะเราใช้บัญชีคนละประเภทกัน · **ให้เปิดดูเองว่าของคุณแสดงอะไร แล้วจดไว้** ตอนบ่ายจะได้รู้ว่าเหลือเท่าไร"
> **แล้วปิดท้ายด้วยบรรทัดนี้:** "คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชันนะครับ ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ"

**เชื่อมเข้า Workshop:** "ที่คุณเพิ่งเห็นทั้งหมด คือสิ่งที่กลุ่มคุณจะทำเองกับ **โครงงานของกลุ่ม** ตอนบ่าย โดยมีใบงานที่มีทุก prompt ให้คัดลอก และมีเฉลยตัวอย่างของ LeaveEasy กำกับไว้ทุกขั้น"

| **Claude Code ค้าง ไม่ตอบเกิน 60 วินาที** | กด `Esc` 1 ครั้งเพื่อหยุดมันกลางคัน → ถ้าของที่มันทำไปแล้วไม่เอา กด `Esc` สองครั้งเพื่อย้อน → ถ้ายังค้าง ปิดหน้าต่างแล้วเปิดใหม่ · พูดว่า "เน็ตในคาบสดเป็นแบบนี้ครับ ระหว่างรอผมเล่าให้ฟังว่า..." แล้วเล่าตัวอย่างจากงานจริงของตัวเอง |
| **`npm run dev` ไม่ยอมเปิด / port ชน** | ไม่ต้องไล่แก้ · เปิดไฟล์ `index.html` ด้วยการดับเบิลคลิกตรง ๆ แทน แล้วบอกว่า "วิธีนี้ใช้ดูหน้าตาได้ แต่บางอย่างจะไม่ทำงาน เดี๋ยวผมกลับมาแก้ทีหลัง" |
| **หน้าเว็บขาวเปล่า ไม่มีอะไรขึ้น** | กด Ctrl+Shift+R (รีเฟรชแรง) 1 ครั้ง → ถ้ายังขาว รัน `git checkout .` แล้วรีเฟรชอีกครั้ง |
| **git ขึ้น error ที่ไม่รู้จัก** | อย่าไล่แก้สด · เปิดโฟลเดอร์ `fixit-backup` ทำต่อ แล้วพูดว่า "ผมขอใช้ของสำรองก่อน เดี๋ยวเราไปไล่เรื่องนี้กันในชั่วโมงปรึกษาวันอาทิตย์" |
| **AI สร้างของออกมาผิดจากที่พูดไว้หน้าห้อง** | ⭐ **อย่าปิดบัง ใช้เป็นบทเรียนทันที** · พูดว่า "นี่คือของจริงครับ ไม่ได้ตัดต่อ — และนี่คือเหตุผลที่ผมบอกว่าต้องเปิดดูด้วยตาทุกครั้ง" แล้วสั่งแก้ให้ดู 1 รอบ |
| **เกินเวลาไป 5 นาทีขึ้นไป** | ข้ามขั้นที่ 6 และขั้นที่ 9 ทันที · ห้ามข้ามขั้นที่ 8 (จุดที่ตั้งใจให้พัง) เด็ดขาด |

**แผนสำรองสุดท้าย:** แตกไฟล์ `fixit-week6-end.zip` ที่เตรียมไว้บน Desktop เปิดขึ้นมา แล้ว **เล่าย้อน** ว่าไปถึงจุดนั้นได้อย่างไรทีละ commit โดยใช้ `git log --oneline` เป็นสารบัญ · พูดตรง ๆ ว่า "เครื่องผมมีปัญหาครับ ผมเปิดของที่ทำไว้แล้วมาเล่าให้ฟังแทน คลิปเต็มจะอยู่ในบันทึกวิดีโอของคาบนี้"
