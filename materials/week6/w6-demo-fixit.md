## 🎬 บล็อก A — นำ prototype ของ FixIt เข้า repo ⏱ 10 นาที (ท้ายช่วงที่ 1)

> 📍 **จุดสลับจอ:** สไลด์หน้า **28** *(🎬 ดูของจริง — นำ prototype ของ FixIt เข้า repo)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **29** *(✅ ช่วงที่ 1 คุณต้องได้อะไรกลับไป)*

### ขั้นที่ A1 — คัดลอกเข้าโฟลเดอร์ใหม่ แล้วปักหมุดแรก ⏱ 4 นาที

**พูดว่า:** "FixIt ก็มี prototype จาก Module 1 เหมือนคุณครับ นี่คือโฟลเดอร์ของมัน ผมจะนำเข้าโปรเจกต์จริงใน 2 ขั้น — คัดลอก แล้วปักหมุด"

**ทำ:**
1. เปิด File Explorer สร้างโฟลเดอร์ใหม่ชื่อ `fixit` → คัดลอกไฟล์ทั้งหมดจาก `fixit-prototype/` เข้าไป (รวม `fixit-spec.md`)
2. เปิด Claude Code ในโฟลเดอร์ `fixit` แล้วสั่ง

**prompt ที่ใช้:**

> ช่วยเริ่มเก็บประวัติงานในโฟลเดอร์นี้ แล้วปักหมุดแรกให้ผม
> ตั้งข้อความหมุดว่า นำ prototype ของ FixIt เข้าโปรเจกต์

**ผู้เรียนจะเห็น:** Claude รายงานว่าเริ่มเก็บประวัติแล้วและปักหมุดแรกเรียบร้อย พร้อมบอกจำนวนไฟล์

**ชี้ให้ดูตรงนี้:** พูดว่า "สังเกตสองอย่างนะครับ — หนึ่ง **ผมไม่ได้พิมพ์คำสั่งอะไรเลย พิมพ์ภาษาไทยบอกมันเฉย ๆ** · สอง ผมปักหมุด**ก่อน**ให้ AI เข้ามาแตะไฟล์ เพราะเดี๋ยวถ้ามันแก้พัง ผมย้อนกลับมาที่หมุดนี้ได้เสมอ"

**เชื่อมกับ LeaveEasy:** "ตรงนี้ของ FixIt คือการนำ prototype เข้า repo — ตอนบ่ายส่วน A ของใบงาน คุณทำแบบเดียวกันกับ prototype ของตัวเอง และในใบงานมีเฉลยว่าถ้าเป็น LeaveEasy โฟลเดอร์จะหน้าตาแบบไหน"

### ขั้นที่ A2 — ให้ Claude ตั้งค่า `npm run dev` ⏱ 6 นาที

**พูดว่า:** "ต่อไปผมอยากเปิดเว็บนี้ดูในเครื่อง ผมจะไม่ตั้งค่าเอง ผมให้ Claude ทำ — แต่สังเกตนะครับ ผมขอแผนก่อนเสมอ นี่คือนิสัยที่เดี๋ยวช่วงถัดไปจะอธิบายเต็ม ๆ"

**ทำ:** เปิด Claude Code ในโฟลเดอร์ `fixit` แล้วพิมพ์:

**prompt ที่ใช้:**
> ผมเพิ่งนำเว็บ prototype เข้าโฟลเดอร์นี้
> ช่วยตั้งค่าให้สั่ง npm run dev แล้วเปิดดูในเบราว์เซอร์ได้
> เขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**ทำต่อ:** อ่านแผนที่ตอบกลับ**ออกเสียงทีละข้อ** แล้วพิมพ์:

> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

รอจนเสร็จ → พิมพ์ `npm run dev` ใน terminal → เปิดเบราว์เซอร์ตามที่อยู่ที่ terminal บอก (เช่น `http://localhost:3000`)

**ผู้เรียนจะเห็น:** terminal ขึ้นที่อยู่เว็บ 1 บรรทัด → เบราว์เซอร์แสดงหน้าแรกของ FixIt หน้าตาเดิมจาก Module 1

**ชี้ให้ดูตรงนี้:** เปิดหน้ารายการใบแจ้งซ่อม แล้วกดรีเฟรช 2 ครั้ง — "ข้อมูลเหมือนเดิมเป๊ะทุกครั้ง เพราะมันเป็น**ของปลอมที่พิมพ์ค้างไว้ในโค้ด** ยังไม่มีคลังเก็บข้อมูลจริง นี่คือสิ่งที่เราจะแก้กันช่วงสาย"

**ทำปิดท้าย:** ปักหมุดเก็บงาน — พิมพ์บอก Claude ว่า *"ปักหมุดเก็บงานให้ผมหน่อย ตั้งข้อความว่า ตั้งค่า npm run dev ได้แล้ว"*

**เชื่อมกับ LeaveEasy:** "ถึงตรงนี้ FixIt รันจาก repo ได้แล้ว — บ่ายนี้ Checkpoint 1 ของคุณคือภาพแบบเดียวกันนี้ เว็บของคุณขึ้นจาก repo ของคุณ"

## 🎬 บล็อก B — เดินวงจร 4 จังหวะเต็มรอบ ⏱ 13 นาที (ท้ายช่วงที่ 2)

> 📍 **จุดสลับจอ:** สไลด์หน้า **40** *(🎬 ดูของจริง — เดินวงจรเต็มรอบกับ FixIt)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **41** *(✅ ช่วงที่ 2 คุณต้องได้อะไรกลับไป)*

> ⭐ **บล็อกนี้ห้ามตัด และห้ามตัดตอนที่แผนมาไม่ตรงใจแล้วผู้สอนแก้ด้วยประโยคเดียว** — นี่คือภาพจำของทั้ง Module

### ขั้นที่ B1 — จังหวะที่ 1 และ 2: สั่งสั้น ขอแผน ⏱ 3 นาที

**พูดว่า:** "หน้ารายการใบแจ้งซ่อมตอนนี้คอลัมน์ยังไม่ตรงกับ DB Schema ที่ออกแบบไว้ ผมจะให้ AI ปรับ — ดูความยาวของสิ่งที่ผมพิมพ์นะครับ"

**prompt ที่ใช้ (จังหวะที่ 1):**
> หน้ารายการใบแจ้งซ่อมใน prototype คอลัมน์ยังไม่ตรง DB Schema
> ช่วยเขียนแผนปรับให้ผมดูก่อน อย่าเพิ่งลงมือ

**ผู้เรียนจะเห็น:** Claude ตอบกลับเป็นแผนข้อ ๆ (ประมาณ 3–5 ข้อ) **ยังไม่มีโค้ดสักบรรทัด**

**ชี้ให้ดูตรงนี้:** "สองบรรทัดครับที่ผมพิมพ์ แล้วดูสิ่งที่ได้กลับมา — แผนเป็นข้อ ๆ ที่อ่านรู้เรื่อง นี่คือจังหวะที่ 2 AI ยังไม่ได้แตะไฟล์อะไรเลย"

### ขั้นที่ B2 — จังหวะที่ 3: เราตรวจแผน ⭐ ⏱ 4 นาที

**พูดว่า:** "จังหวะนี้คือจังหวะของคุณครับ ผมจะอ่านแผนออกเสียงทีละข้อ แล้วหาข้อที่ไม่ตรงใจ"

**ทำ:** อ่านแผนออกเสียงทีละข้อ ชี้ข้อที่ไม่ตรงใจ (ส่วนใหญ่มีเสมอ เช่น สถานะไม่เป็นป้ายสี หรือจำนวนรายการตัวอย่างน้อยไป) แล้วพิมพ์แก้ด้วยประโยคเดียว:

**prompt ที่ใช้ (จังหวะที่ 3):**
> ข้อ 2 ขอเป็นป้ายสีตามสถานะ ข้อ 3 ขอ 5 รายการ
> ที่เหลือโอเค

> 🎭 **ถ้าแผนที่ได้มาดันตรงใจทุกข้อ** (เกิดได้ เพราะ AI ตอบไม่เหมือนกันทุกครั้ง) — อย่าข้ามจังหวะที่ 3 ให้เปลี่ยนใจ 1 ข้อให้ห้องดูแทน แล้วพูดว่า "แผนดีครับ แต่ผมขอเปลี่ยนใจข้อ 3 เป็น 5 รายการ — ผมแก้แผนได้ตลอด เพราะยังไม่มีโค้ดเกิดขึ้น"

**ผู้เรียนจะเห็น:** Claude ตอบกลับเป็นแผนฉบับแก้แล้ว ตรงตามที่บอก

**ชี้ให้ดูตรงนี้:** "ผมไม่ได้เขียนแผนใหม่ทั้งฉบับนะครับ บอกไปข้อที่ไม่ใช่ แล้วบอกว่าที่เหลือโอเค — แก้ตอนนี้ 1 บรรทัด ถ้าแก้ตอนโค้ดเสร็จแล้วคือรื้อ"

### ขั้นที่ B3 — จังหวะที่ 4: ลงมือทีละข้อ ตรวจ แล้ว commit ⏱ 4 นาที

**prompt ที่ใช้ (จังหวะที่ 4):**
> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

**ทำ:** เมื่อ Claude รายงานว่าเสร็จ → รีเฟรชเบราว์เซอร์ → ไล่ดูกับตาว่าคอลัมน์ครบ ป้ายสีขึ้น 5 รายการ → สั่ง *"ปักหมุดเก็บงานให้ผม ตั้งข้อความว่า ปรับหน้ารายการใบแจ้งซ่อมให้ตรง DB Schema"*

**ผู้เรียนจะเห็น:** หน้ารายการมีคอลัมน์ครบ · สถานะเป็นป้ายสี · 5 รายการ

**ชี้ให้ดูตรงนี้:** ประโยค "เสร็จข้อไหนบอกผมก่อน" — "ประโยคนี้ทำให้ผมตรวจได้ทีละข้อ ไม่ใช่มารู้ตอนพังทั้งก้อน" · แล้วชี้บรรทัด commit — "ทำสำเร็จ ปักหมุดทันที นี่คือกติกาทั้งเดือน"

### ขั้นที่ B4 — แถม: สั่งพลาดแล้วย้อนด้วย `Esc Esc` ⏱ 2 นาที

**พูดว่า:** "ทีนี้ผมจะทำสิ่งที่ทุกคนกลัวให้ดู — สั่งพลาด"

**prompt ที่ใช้ (ตั้งใจให้พลาด):**
> เปลี่ยนธีมสีทั้งเว็บเป็นสีชมพู

**ทำไมต้องมี:** ให้ผู้เรียนเห็นอาการ "AI ลืม" กับตาก่อนเจอเองตอนบ่าย และเห็นว่าการติดเป็นเรื่องปกติที่กู้ได้เป็นขั้นตอน ไม่ใช่ความล้มเหลว

### ทำให้พังอย่างไร ⏱ 5 นาที

**พูดว่า:** "ผมจะทำสิ่งที่ห้ามทำให้ดูนะครับ — บทสนทนานี้ลากยาวมาตั้งแต่ 9 โมง ผมจะสั่งงานต่อโดยไม่จัดการความจำเลย ดูอาการดี ๆ"

**ทำ:** ในบทสนทนาเดิมที่ใช้มาทั้งเช้า สั่งงานจิปาถะติดกันโดยไม่ตรวจ เช่น "อธิบายโค้ดทุกไฟล์แบบละเอียด" ตามด้วย "ปรับขนาดปุ่มทุกหน้าให้ใหญ่ขึ้น" แล้วปิดท้ายด้วย:

**prompt ที่ใช้:**
> เพิ่มคอลัมน์สถานที่ในหน้ารายการใบแจ้งซ่อม

**ผู้เรียนจะเห็น (อาการที่คาด):** AI เพิ่มคอลัมน์ให้ แต่**ลืมข้อตกลงเดิม** เช่น สถานะกลายเป็นภาษาอังกฤษ (`pending`) แทน 4 ค่าภาษาไทย หรือป้ายสีที่ตกลงไว้หายไป

**พูดตอนพัง:** "เห็นไหมครับ ผมเองก็เจอ — มันไม่ได้พังเสียงดัง มันพังแบบ**ลืม** สังเกต 3 สัญญาณจากสไลด์เมื่อกี้: ลืมข้อตกลง · แก้จุดหนึ่งจุดที่เคยดีพัง · ตอบวนซ้ำ"

> 🎭 **ถ้าอาการไม่เกิดสด ๆ** (AI ยังจำได้ — เกิดได้เพราะพฤติกรรมไม่คงที่): เปิด screenshot จากรอบซ้อมที่เตรียมไว้ แล้วพูดว่า "รอบซ้อมเมื่อวานผมเจอแบบนี้ครับ วันนี้มันรอด แต่คุณตอนบ่ายจะมีสักคนที่เจอแน่นอน" — ความซื่อสัตย์ตรงนี้สอนได้มากกว่าการแกล้งทำ

### วิธีกู้ทีละขั้น ⏱ 7 นาที

**ขั้นกู้ที่ 1 — เก็บความจำก่อนล้าง:**

**prompt ที่ใช้:**
> สรุปสถานะโปรเจกต์ตอนนี้ให้ผมเป็นข้อ ๆ
> เขียนให้ผมคัดลอกไปเริ่มบทสนทนาใหม่ได้เลย

**ขั้นกู้ที่ 2 — ตรวจสรุปด้วยจังหวะที่ 3:** อ่านสรุปออกเสียง — **ชี้ว่าขาดข้อตกลงเรื่องสถานะภาษาไทย 4 ค่า** แล้วพิมพ์:

> ขาดข้อตกลงเรื่องสถานะภาษาไทย 4 ค่า เติมให้ด้วย

**ขั้นกู้ที่ 3 — เก็บลงไฟล์:** คัดลอกสรุปใส่ไฟล์ `บันทึกสถานะ.md` ในโปรเจกต์ (สร้างไฟล์ให้ห้องเห็น)

**ขั้นกู้ที่ 4 — ล้างแล้วเริ่มใหม่:** พิมพ์ `/clear` → **ย้ำก่อนกด:** "ไฟล์ในโปรเจกต์ไม่หายสักไฟล์นะครับ หายเฉพาะความจำของบทสนทนา" → วางสรุปสถานะเป็นข้อความแรกของบทสนทนาใหม่ → สั่งงานเดิมอีกครั้ง:

> เพิ่มคอลัมน์สถานที่ในหน้ารายการใบแจ้งซ่อม ตามข้อตกลงในสรุปด้านบน

**ผู้เรียนจะเห็น:** คราวนี้คอลัมน์เพิ่มมา **โดยสถานะยังเป็นภาษาไทยครบ 4 ค่า** — กลับมาทำงานได้ดีกว่าเดิม

**ทำปิดท้าย:** พิมพ์ `/usage` โชว์หน้าปริมาณการใช้งาน 20 วินาที — "โควตาไม่ได้ไม่จำกัด บทสนทนาบวม ๆ กินเร็วกว่าที่คิด สิ่งที่เห็นบนจอขึ้นกับประเภทบัญชี เปิดดูของตัวเองแล้วจดไว้" · commit งานที่สำเร็จ

**ชี้ให้ดูตรงนี้:** "ทางเลือกมี 3 ทาง — คุยต่อ · `/compact` ย่อความจำแล้วคุยต่อ · `/clear` ล้างแล้วเริ่มใหม่พร้อมสรุป — วันนี้ผมโชว์ทางที่สุดโต่งที่สุด บ่ายนี้ใบงานมีจุดให้คุณใช้จริงอย่างน้อยหนึ่งครั้ง"

**เชื่อมกับ LeaveEasy:** "ตอนบ่ายให้คนที่ไม่ได้พิมพ์เป็นคนจับ 3 สัญญาณนี้ให้ เพราะคนที่พิมพ์จะไม่ทันสังเกต — ในใบงานมีตาราง 🆘 ที่เขียนวิธีกู้ชุดเดียวกันนี้ไว้แล้ว"

## 🆘 ถ้าเดโมพังจริงโดยไม่ได้ตั้งใจ

| อาการ | ทำอย่างไรภายใน 60 วินาที |
|---|---|
| `npm run dev` ไม่ขึ้น / error สีแดงเต็มจอ | อ่านบรรทัดสุดท้ายออกเสียง (สอนไปในตัว) → วางบรรทัดนั้นให้ Claude ถามว่าแก้ยังไง → ถ้าไม่จบใน 1 นาที สลับไปโฟลเดอร์สำรอง `fixit-week6-end/` |
| seed แล้ว Console ว่างเปล่า | เช็กว่า Console เปิดโปรเจกต์ `fixit-demo` ถูกตัว (มุมซ้ายบน) — ผิดโปรเจกต์คือสาเหตุอันดับหนึ่ง → รีเฟรชหน้า Data อีกครั้ง |
| หน้ารายการว่าง / ขึ้น `permission denied` | เปิด Console ดูก่อนว่าข้อมูลอยู่ไหม (ใช้วิธีคิดที่เพิ่งสอน) → ถ้าอยู่ กด F12 ดูข้อความ error → เกือบทั้งหมดคือโหมดทดสอบหมดอายุหรือยังไม่ได้เปิด Firestore |
| Claude Code ค้าง / ตอบไม่ตรงคำถามหนัก ๆ | กด `Esc` หยุด → ถ้ายังเพี้ยน ใช้ขั้นกู้ของบล็อก E ทันที (สรุปสถานะ → `/clear`) — กลายเป็นการสาธิตของจริงไปเลย |
| อินเทอร์เน็ต / Firebase Console เข้าไม่ได้ | ให้ TA แชร์จอแทนจากเครื่องสำรองที่เตรียมโปรเจกต์เดียวกันไว้ · ระหว่างนั้นผู้สอนเล่าลำดับขั้นจากสไลด์ |

**แผนสำรองสุดท้าย:** เปิดโฟลเดอร์ `fixit-week6-end/` (แท็ก `week6-end`) → `npm run dev` → เปิด Console คู่กัน แล้วเล่าย้อนทีละขั้นว่าไปถึงตรงนั้นได้อย่างไร — ผู้เรียนยังเห็นภาพปลายทางครบ

## ❓ คำถามที่ผู้เรียนมักถามตรงนี้

| คำถาม | ตอบสั้น ๆ ว่า |
|---|---|
| AI เขียนให้หมดแล้วเราได้เรียนอะไร | เราฝึกสิ่งที่ AI ทำแทนไม่ได้ — ตรวจแผน ตรวจผลลัพธ์ และตอบได้ว่าระบบทำงานยังไง ซึ่งเป็นเกณฑ์ผ่านรายบุคคลตอน Sprint 1 Review |
| ใช้ Excel / Google Sheets เป็นฐานข้อมูลได้ไหม | คนละหน้าที่กัน — Firestore ให้หน้าเว็บอ่านตรงได้ทันที และสัปดาห์ที่ 8 มียามเฝ้าข้อมูลให้ด้วย ซึ่ง Excel ทำไม่ได้ |
| โหมดทดสอบอันตรายไหม | ใช่ คลังยังไม่ล็อกกุญแจ — จึงห้ามใส่ข้อมูลจริง ใช้ชื่อสมมติเท่านั้น และกุญแจจริงมาสัปดาห์ที่ 7–8 ตามแผน |
| Firebase เสียเงินไหม | มีระดับใช้ฟรีที่พอสำหรับทั้ง Module แต่เงื่อนไขเปลี่ยนได้ **ตรวจสอบล่าสุดก่อนสอน** |
| ทำไมยังไม่ทำปุ่มบันทึก ทั้งที่ทำต่ออีกนิดเดียว | วันนี้ตัว R ตัวเดียวโดยตั้งใจ — ระบบที่โตทีละขั้นตรวจทัน ระบบที่โตรวดเดียวตรวจไม่ทัน ปุ่มเพิ่ม/แก้/ลบมีที่ทางของมันสัปดาห์ที่ 7 |
| สั่งเป็นภาษาไทยแล้ว AI จะเข้าใจหรือ | เข้าใจ — ทุก prompt ที่เห็นวันนี้เป็นภาษาไทยล้วน สิ่งที่ต้องเป็นอังกฤษมีอย่างเดียวคือชื่อโฟลเดอร์กับชื่อช่องข้อมูล |

## ✂️ ถ้าเวลาไม่พอ ตัดตามลำดับนี้

1. ขั้นที่ B4 (`Esc Esc`) — ยกไปพูดปากเปล่าประกอบสไลด์ตาข่าย 2 ชั้นแทน
2. ขั้นที่ C1 ย่อเหลือ 1 นาที (ตารางเดี่ยวเข้าใจเร็ว) เอาเวลาไปให้ C2 ที่เป็นหัวใจ
3. บล็อก E ตัดการสั่งงานจิปาถะ ใช้ screenshot รอบซ้อมเล่าอาการ แล้วสาธิตเฉพาะขั้นกู้ 1–4
4. **ห้ามตัด:** บล็อก D ทั้งบล็อก · จังหวะที่ 3 ของบล็อก B · การแก้ข้อมูลใน Console แล้วหน้าเว็บเปลี่ยนตาม
