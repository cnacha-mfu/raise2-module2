**พูดว่า:** "FixIt ก็มี prototype จาก Module 1 เหมือนคุณ ผมจะนำเข้าโปรเจกต์ใน 2 ขั้น — คัดลอก แล้วปักหมุด"

**ทำ:** สร้างโฟลเดอร์ `fixit` → คัดลอกไฟล์จาก `fixit-prototype/` เข้าไปทั้งหมด (รวม `fixit-spec.md`) → เปิด Claude Code ในโฟลเดอร์นั้น

**prompt ที่ใช้:**

**ผู้เรียนจะเห็น:** Claude รายงานว่าเริ่มเก็บประวัติและปักหมุดแรกแล้ว พร้อมจำนวนไฟล์

**ชี้ให้ดูตรงนี้:** "ผมไม่ได้พิมพ์คำสั่งเลย พิมพ์ภาษาไทยบอกเฉย ๆ · และผมปักหมุด**ก่อน**ให้ AI แตะไฟล์ เพราะถ้าพังผมย้อนกลับมาที่หมุดนี้ได้"

**เชื่อมกับ LeaveEasy:** "บ่ายนี้ส่วน A คุณทำแบบเดียวกัน แต่กด Fork แทน"

### A2 — ให้ Claude เปิดเว็บให้ดู ⏱ 6 นาที

**พูดว่า:** "ผมจะไม่ตั้งค่าเอง ให้ Claude ทำ — แต่สังเกตว่าผมขอแผนก่อนเสมอ"

**prompt ที่ใช้:**
> ผมเพิ่งนำเว็บ prototype เข้าโฟลเดอร์นี้
> ช่วยเปิดเว็บนี้ให้ผมดูในเบราว์เซอร์หน่อย บอกผมทีละขั้นว่าทำอะไรบ้าง
> เขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**ทำ:** อ่านแผนออกเสียงทีละข้อ → พิมพ์ *"แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน"* → เปิดเบราว์เซอร์ตามที่อยู่ที่มันบอก

**ผู้เรียนจะเห็น:** terminal ขึ้นที่อยู่เว็บ → เบราว์เซอร์แสดงหน้าแรก FixIt หน้าตาเดิมจาก Module 1

**ชี้ให้ดูตรงนี้:** เปิดหน้ารายการ กดรีเฟรช 2 ครั้ง — "ข้อมูลเหมือนเดิมเป๊ะ เพราะเป็นของปลอมที่พิมพ์ค้างในโค้ด ยังไม่มีคลังจริง นี่คือสิ่งที่เราจะแก้ช่วงสาย"

**ทำปิดท้าย:** *"ปักหมุดเก็บงานให้ผม ตั้งข้อความว่า เปิดเว็บในเครื่องได้แล้ว"*

**เชื่อมกับ LeaveEasy:** "นี่คือภาพเดียวกับ Checkpoint 1 ของบ่ายนี้"

## 🎬 บล็อก B — วงจร 4 จังหวะเต็มรอบ ⏱ 13 นาที (ท้ายช่วงที่ 2)

> 📍 สไลด์ **43** *(🎬 เดินวงจรเต็มรอบกับ FixIt)* → สาธิต → กลับเข้าสไลด์ **44** *(✅ ช่วงที่ 2)*
> ⭐ **ห้ามตัดบล็อกนี้ และห้ามตัดจังหวะที่ 3** — เป็นภาพจำของทั้ง Module

### B1 — จังหวะ 1–2: สั่งสั้น ขอแผน ⏱ 3 นาที

**พูดว่า:** "หน้ารายการคอลัมน์ยังไม่ตรง DB Schema ผมจะให้ AI ปรับ — ดูความยาวของสิ่งที่ผมพิมพ์"

**prompt ที่ใช้:**
> หน้ารายการใบแจ้งซ่อมใน prototype คอลัมน์ยังไม่ตรง DB Schema
> ช่วยเขียนแผนปรับให้ผมดูก่อน อย่าเพิ่งลงมือ

**ผู้เรียนจะเห็น:** แผน 3–5 ข้อ **ยังไม่มีโค้ดสักบรรทัด**

**ชี้ให้ดูตรงนี้:** "สองบรรทัดที่ผมพิมพ์ แลกกับแผนที่อ่านรู้เรื่อง — AI ยังไม่แตะไฟล์เลย"

### B2 — จังหวะ 3: เราตรวจแผน ⭐ ⏱ 4 นาที

**พูดว่า:** "จังหวะนี้เป็นของคุณ ผมจะอ่านแผนออกเสียงแล้วหาข้อที่ไม่ตรงใจ"

**prompt ที่ใช้:**
> ข้อ 2 ขอเป็นป้ายสีตามสถานะ ข้อ 3 ขอ 5 รายการ
> ที่เหลือโอเค

> 🎭 **ถ้าแผนตรงใจทุกข้อ** — อย่าข้ามจังหวะนี้ ให้เปลี่ยนใจ 1 ข้อให้ห้องดูแทน แล้วพูดว่า "ผมแก้แผนได้ตลอด เพราะยังไม่มีโค้ดเกิดขึ้น"

**ผู้เรียนจะเห็น:** แผนฉบับแก้แล้ว ตรงตามที่บอก

**ชี้ให้ดูตรงนี้:** "ผมไม่ได้เขียนแผนใหม่ทั้งฉบับ บอกเฉพาะข้อที่ไม่ใช่ — แก้ตอนนี้ 1 บรรทัด แก้ตอนโค้ดเสร็จคือรื้อ"

### B3 — จังหวะ 4: ลงมือทีละข้อ แล้ว commit ⏱ 4 นาที

**prompt ที่ใช้:**
> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

**ทำ:** เสร็จแล้วรีเฟรชเบราว์เซอร์ → ไล่ดูด้วยตาว่าคอลัมน์ครบ ป้ายสีขึ้น 5 รายการ → *"ปักหมุดเก็บงานให้ผม ตั้งข้อความว่า ปรับหน้ารายการให้ตรง DB Schema"*

**ผู้เรียนจะเห็น:** คอลัมน์ครบ · สถานะเป็นป้ายสี · 5 รายการ

**ชี้ให้ดูตรงนี้:** ประโยค "เสร็จข้อไหนบอกผมก่อน" — "ทำให้ผมตรวจได้ทีละข้อ ไม่ใช่มารู้ตอนพังทั้งก้อน" · แล้วชี้ commit — "ทำสำเร็จ ปักหมุดทันที กติกาทั้งเดือน"

### B4 — สั่งพลาดแล้วย้อนด้วย `Esc Esc` ⏱ 2 นาที

**พูดว่า:** "ทีนี้ผมจะทำสิ่งที่ทุกคนกลัวให้ดู — สั่งพลาด"

**prompt ที่ใช้ (ตั้งใจให้พลาด):**
> เปลี่ยนธีมสีทั้งเว็บเป็นสีชมพู

**ทำ:** พอเริ่มลงมือ กด `Esc` หยุด → กด `Esc Esc` เปิดเมนูย้อนกลับ → เลือกจุดก่อนคำสั่งนี้ (เวอร์ชันที่ไม่มีเมนู พิมพ์ `/rewind`)

**ผู้เรียนจะเห็น:** Claude หยุดกลางคัน → เมนูจุดย้อนกลับ → ไฟล์กลับเป็นเหมือนเดิม

**ชี้ให้ดูตรงนี้:** "รู้ตัวเร็วย้อนได้ใน 5 วินาที และยังมีหมุด commit เป็นตาข่ายชั้นสอง · เมนูไม่เหมือนของผมให้พิมพ์ `/help`"

**เชื่อมกับ LeaveEasy:** "วงจรนี้คือสิ่งที่คุณจะหมุนซ้ำตลอดบ่าย"

## 🎬 บล็อก D — สร้างคลัง · seed · ส่อง · ต่อหน้ารายการ ⭐ ⏱ 22 นาที (ช่วงที่ 4)

> 📍 สไลด์ **70** *(🎬 สร้างคลัง · seed · ส่อง · ต่อหน้ารายการ)* → สาธิต → กลับเข้าสไลด์ **71** *(!! ข้อมูลยังอยู่)*

### D1 — เปิด Firestore โหมดทดสอบ ⏱ 4 นาที

**ทำ:** Firebase Console ของ `fixit-demo` → **Firestore Database** → **Create database** → **โหมดทดสอบ** → เลือกตำแหน่ง → รอสร้างเสร็จ

**ผู้เรียนจะเห็น:** หน้า Data ที่**ว่างเปล่า**

**ชี้ให้ดูตรงนี้:** **ซูมที่วันหมดอายุของโหมดทดสอบ** — "คลังนี้ยังไม่ล็อกกุญแจ และมีวันหมดอายุ ถึงวันนั้นระบบจะเงียบใส่โดยไม่บอก · เพราะยังไม่ล็อก **ห้ามใส่ข้อมูลจริงของใคร** ใช้ชื่อสมมติเท่านั้น กุญแจจริงมาสัปดาห์ที่ 7–8"
⚠️ หน้าตาเมนู Firebase เปลี่ยนได้ **ตรวจสอบล่าสุดก่อนสอน**

### D2 — เชื่อมเว็บกับคลัง แล้ว seed ⏱ 8 นาที

**ทำ (เชื่อม):** Console → ⚙️ **Project settings → Your apps** → เพิ่ม Web app (`</>`) → คัดลอก `firebaseConfig`

**prompt ที่ใช้:**
> ผมอยากให้เว็บนี้ต่อกับ Firestore ของโปรเจกต์ fixit-demo
> เดี๋ยวผมจะวางค่า firebaseConfig ให้ ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ

อ่านแผน → สั่งลงมือ → วาง `firebaseConfig` เมื่อ Claude ขอ

**ผู้เรียนจะเห็น:** ไฟล์ตั้งค่าใหม่ (เช่น `js/firebase.js`) และ Claude รายงานว่าเชื่อมแล้ว

**พูดว่า (ก่อน seed):** "ต่อไปคือใส่ข้อมูลตัวอย่างชุดแรก ศัพท์เรียกว่า **seed** — และนี่คือ**ข้อยกเว้นเดียวของวันนี้ที่ prompt ยาวได้** เพราะเป็นรายการชื่อช่องที่สะกดผิดตัวเดียวพังเงียบ ๆ"

**prompt ที่ใช้ (ยาวได้ เพราะเป็นรายการชื่อ — อ่านทวนก่อนกด Enter):**
> ใส่ข้อมูลตัวอย่างลง Firestore ให้ผม ชื่อทุกตัวสะกดตามนี้เป๊ะ ๆ ห้ามเปลี่ยน
> โฟลเดอร์ users มีช่อง name, email, role — 3 คน: u001 สมชาย ใจดี (reporter) · u002 สมหญิง รักงาน (technician) · u003 สมศรี ตั้งใจ (admin) อีเมลใช้ @example.com
> โฟลเดอร์ categories มีช่อง name — c001 ไฟฟ้า · c002 ประปา · c003 เครื่องปรับอากาศ
> โฟลเดอร์ tickets 5 ใบ มีช่อง title, detail, location, status, reporterId, reporterName, assigneeId, assigneeName, categoryId, categoryName, createdAt — สถานะใช้ 4 ค่านี้เท่านั้น: แจ้งใหม่ / รับเรื่องแล้ว / กำลังซ่อม / เสร็จสิ้น
> โฟลเดอร์ย่อย comments ใต้ t001 มีช่อง authorId, authorName, message, createdAt
> เนื้อหาใช้ตามข้อมูลตัวอย่างใน fixit-spec.md หัวข้อ 7 เสร็จแล้วรันให้เลย

**ผู้เรียนจะเห็น:** Claude เขียนสคริปต์ seed แล้วรัน → ขึ้นข้อความทำนอง `เพิ่มข้อมูลครบแล้ว` ไม่มี error สีแดง

**ชี้ให้ดูตรงนี้:** ความยาวของ prompt — "ยาวเพราะเป็นรายการชื่อที่ห้ามสะกดผิด ไม่ใช่ยาวเพราะสั่งหลายงาน — งานอื่นกลับไปสั่งสั้นเหมือนเดิม"

### D3 — เปิด Console ส่องด้วยตา ⏱ 4 นาที

**พูดว่า:** "AI บอกว่าเสร็จ แต่เราไม่เชื่อจนกว่าจะเห็นกับตา — นี่คือทักษะสำคัญที่สุดของวันนี้"

**ทำ:** แท็บ Console → รีเฟรช → เปิด `tickets` → เปิด `t001` → เลื่อนดูทีละช่อง → ชี้โฟลเดอร์ย่อย `comments`

**ผู้เรียนจะเห็น:** โฟลเดอร์ครบ 3 · ในไฟล์ `t001` ช่องครบ · มี `comments` ซ้อนข้างใน

**ชี้ให้ดูตรงนี้:** `reporterId: "u001"` คู่กับ `reporterName: "สมชาย ใจดี"` — "นี่คือวงสีแดงบนกระดานเมื่อกี้ ตอนนี้เป็นของจริงแล้ว" · "Console ตอบคำถามสำคัญตอนพัง — ข้อมูลอยู่ในคลังไหม ถ้าอยู่แปลว่าพังตอนอ่าน ถ้าไม่อยู่แปลว่าพังตอนใส่"

### D4 — ต่อหน้ารายการให้อ่านจากคลังจริง ⏱ 6 นาที

**พูดว่า:** "ขั้นสุดท้าย ทำให้หน้ารายการเลิกใช้ของปลอม แล้วอ่านจากคลังจริง"

**prompt ที่ใช้:**
> เปลี่ยนหน้ารายการใบแจ้งซ่อม จากข้อมูลปลอมในโค้ด ให้อ่านจากโฟลเดอร์ tickets ใน Firestore แทน
> หน้าอื่นยังไม่ต้องแตะ ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ

**ทำ:** อ่านแผนออกเสียง — **ถ้าแผนแถมปุ่มบันทึก/แก้/ลบ ให้ตัดทิ้งต่อหน้าห้อง:**
> ข้อที่ทำปุ่มบันทึกตัดออก วันนี้อ่านอย่างเดียว ที่เหลือโอเค ลงมือได้ ทำทีละข้อ

**ทำ (พิสูจน์ — ห้ามตัด):**
1. แก้ `title` ของ `t001` ใน Console → รีเฟรชหน้าเว็บ → **ข้อความเปลี่ยนตาม**
2. ปิดเบราว์เซอร์ทั้งหน้าต่าง → เปิดใหม่ → **ข้อมูลยังอยู่**
3. ให้ห้องพิมพ์ 🎉 ในแชท แล้วสั่ง *"ปักหมุดเก็บงานให้ผม ตั้งข้อความว่า หน้ารายการอ่านจาก Firestore จริงแล้ว"*

**ผู้เรียนจะเห็น:** หน้ารายการแสดง 5 ใบ ชุดเดียวกับใน Console

**ชี้ให้ดูตรงนี้:** จังหวะที่แก้ใน Console แล้วเว็บเปลี่ยนตาม — "นาทีนี้ FixIt เปลี่ยนจากภาพนิ่งเป็นระบบที่มีความจำ"

**เชื่อมกับ LeaveEasy:** "4 ขั้นนี้คือส่วน C กับ D ของใบงานบ่ายนี้"
