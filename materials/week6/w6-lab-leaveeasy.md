## ส่วน B — เขียนโครงสร้างข้อมูลลงกระดาษ ⏱ ~25 นาที

> ✍️ **ส่วนนี้ไม่ใช้คอมพิวเตอร์** — ใช้กระดาษกับปากกา เพราะการวาดด้วยมือทำให้เห็นว่าอะไรขาด

### B1 — เขียนกติกา 4 ข้อไว้หัวกระดาษ (5 นาที)

1. 📁 **Collection = โฟลเดอร์** · 📄 **Document = ไฟล์** · ✏️ **Field = ช่องข้อมูลในไฟล์**
2. **ไม่มี JOIN** — ต่อตารางแบบที่เคยทำใน Module 1 ไม่ได้
3. เพราะไม่มี JOIN จึงต้อง **จดชื่อซ้ำไว้ในไฟล์เลย** (เรียกว่า denormalize) เช่นเก็บ `requesterName` ไว้ในใบลาตรง ๆ
4. ของที่เป็นของใบลาใบนั้นโดยเฉพาะ ให้เป็น **โฟลเดอร์ย่อย (subcollection)** เช่นความเห็นการอนุมัติ

### B2 — วาดโฟลเดอร์ 3 + โฟลเดอร์ย่อย 1 (12 นาที)

วาดตามนี้ แล้ว **เขียนชื่อช่องข้อมูลให้ครบทุกช่อง**

```
📁 users            → name · email · role
📁 leaveTypes       → name
📁 leaveRequests    → title · reason · startDate · endDate · status
                      requesterId · requesterName · approverId · approverName
                      leaveTypeId · leaveTypeName · createdAt
   └ 📁 approvals   → authorId · authorName · message · createdAt
```

**วงกลมสีแดง** รอบช่องที่เป็นชื่อจดซ้ำ (`requesterName` · `approverName` · `leaveTypeName` · `authorName`) แล้วเขียนข้าง ๆ ว่า *"จดซ้ำเพราะไม่มี JOIN"*

### B3 — ตอบคำถาม 2 ข้อลงกระดาษ (8 นาที)

1. ถ้าสมชายเปลี่ยนชื่อ ต้องไปแก้กี่ที่?
2. ทำไม `approvals` จึงเป็นโฟลเดอร์ย่อย ไม่ใช่โฟลเดอร์แยก?

**จะเห็น:** กระดาษของคุณมีโฟลเดอร์ 3 + โฟลเดอร์ย่อย 1 · ช่องข้อมูลครบ · วงแดงครบ 4 จุด · คำตอบ 2 ข้อ

→ 🚩 **Checkpoint 2: กระดาษเสร็จ ชื่อช่องครบ วงแดงครบ**
📸 ถ่ายรูปกระดาษโพสต์ในแชท · 🔁 สลับคนนำจอ

## ส่วน C — สร้าง Firestore แล้วใส่ข้อมูลตัวอย่าง ⏱ ~40 นาที

### C1 — เปิดตู้ Firestore ในโหมดทดสอบ (10 นาที)

เข้า Firebase Console → สร้างโปรเจกต์ชื่อ `leaveeasy-<ชื่อคุณ>` → เมนู **Firestore Database** → **Create database** → เลือก **Test mode** → เลือกที่ตั้ง `asia-southeast1`

**จะเห็น:** หน้าจอ Firestore ว่างเปล่า มีปุ่ม **Start collection** ตรงกลาง

> ⚠️ **โหมดทดสอบเปิดให้ใครก็อ่านเขียนได้ และหมดอายุใน 30 วัน** — สัปดาห์ที่ 7–8 จะปิดให้เรียบร้อย
> วันนี้จึง **ห้ามใส่ข้อมูลจริงของคนอื่น** ใช้ชื่อสมมติ สมชาย สมหญิง สมศรี เท่านั้น

### C2 — เชื่อมเว็บของคุณกับตู้ (10 นาที)

ใน Firebase Console กด ⚙️ → Project settings → เลื่อนลงหา **Your apps** → กดไอคอน `</>` → ตั้งชื่อแอป → **คัดลอกกล่อง `firebaseConfig`**

```prompt
นี่คือค่า firebaseConfig ของผม <วางที่คัดลอกมา>
ช่วยเขียนแผนว่าจะเชื่อมเว็บ LeaveEasy กับ Firestore อย่างไร ขอดูแผนก่อน อย่าเพิ่งลงมือ
```

อ่านแผนที่ได้ ถ้าข้อไหนไม่ตรงให้บอกกลับ เช่น *"ข้อ 2 ผมอยากให้ค่าตั้งค่าอยู่ไฟล์แยก"* แล้วค่อยสั่งลงมือ

**จะเห็น:** มีไฟล์ตั้งค่า Firebase เพิ่มในโฟลเดอร์ `js/` · เปิดเว็บแล้ว Console (F12) ไม่มีข้อความสีแดง

> 🆘 ขึ้น `Firebase: Error (auth/invalid-api-key)` → คัดลอกค่ามาไม่ครบ ให้คัดลอกใหม่ทั้งกล่อง

### C3 — ใส่ข้อมูลตัวอย่าง 5 ใบ (15 นาที)

> ⚠️ **prompt ข้างล่างยาวกว่าปกติโดยตั้งใจ** เพราะเป็น**รายการชื่อช่องข้อมูล** ที่สะกดผิดแล้วระบบจะพังแบบเงียบ ๆ — Firestore แยกตัวพิมพ์เล็กใหญ่

```prompt
ช่วยเขียนสคริปต์ใส่ข้อมูลตัวอย่างลง Firestore ให้ผม ตามนี้
- users 3 ไฟล์: u001 สมชาย ใจดี employee, u002 สมหญิง รักงาน manager, u003 สมศรี ตั้งใจ hr (ช่อง name, email, role)
- leaveTypes 3 ไฟล์: lt001 ลาพักร้อน, lt002 ลาป่วย, lt003 ลากิจ (ช่อง name)
- leaveRequests 5 ไฟล์ ช่อง title, reason, startDate, endDate, status, requesterId, requesterName, approverId, approverName, leaveTypeId, leaveTypeName, createdAt
  ให้ 3 ใบเป็น รอพิจารณา 1 ใบ อนุมัติ 1 ใบ ไม่อนุมัติ
เขียนแผนให้ผมดูก่อน แล้วรอผมสั่งค่อยลงมือ
```

**จะเห็น:** สคริปต์รันแล้วขึ้นข้อความว่าใส่ข้อมูลสำเร็จ

### C4 — เปิด Console ส่องด้วยตา (5 นาที)

กลับไป Firebase Console → Firestore Database

**จะเห็น:** โฟลเดอร์ `users` · `leaveTypes` · `leaveRequests` · กดเข้า `leaveRequests` เห็นไฟล์ 5 ไฟล์ · กดเข้าไฟล์หนึ่งเห็นช่องข้อมูลตรงกับกระดาษของคุณ

> 🆘 ไม่เห็นข้อมูล → กด Refresh หน้า Console ก่อน · ยังไม่มาให้ดู Console ของเบราว์เซอร์ (F12) ว่ามีข้อความสีแดงหรือไม่

→ 🚩 **Checkpoint 3: Firebase Console เห็นใบลา 5 ใบ**
📸 โพสต์ screenshot หน้า Console จากเครื่องคุณ · 🔁 สลับคนนำจอ

## ส่วน D — หน้ารายการอ่านจากตู้จริง ⏱ ~30 นาที

### D1 — ต่อหน้ารายการเข้ากับ Firestore (15 นาที)

```prompt
ตอนนี้หน้า leave-requests.html ยังใช้ข้อมูลสมมติในไฟล์อยู่
ผมอยากให้มันอ่านจากโฟลเดอร์ leaveRequests ใน Firestore แทน
ขอดูแผนก่อน อย่าเพิ่งลงมือ
```

อ่านแผน ตรวจว่ามีข้อ *"เรียงจากใหม่ไปเก่า"* หรือยัง ถ้าไม่มีให้บอกเพิ่ม แล้วค่อยสั่งลงมือทีละข้อ

**จะเห็น:** หน้ารายการแสดงใบลา 5 แถว ตรงกับที่เห็นใน Console

> 🆘 หน้าว่างเปล่า แต่ Console ของเบราว์เซอร์ไม่มีสีแดง → มักสะกดชื่อโฟลเดอร์ผิด ตรวจว่าเป็น `leaveRequests` ตัว R ใหญ่

### D2 — พิสูจน์ว่าระบบมีความจำจริง (10 นาที)

1. เปิด Firebase Console แก้ `title` ของใบลาใบหนึ่ง
2. กลับมาที่หน้าเว็บ กด F5

**จะเห็น:** ข้อความบนหน้าเว็บเปลี่ยนตามที่แก้ใน Console — แปลว่าหน้าเว็บอ่านจากฐานข้อมูลจริงแล้ว
จากนั้นปิดเบราว์เซอร์ เปิดใหม่ ข้อมูลยังอยู่ครบ

### D3 — เก็บงาน (5 นาที)

```prompt
ช่วย commit งานวันนี้ให้ผม ตั้งข้อความ commit ให้สื่อว่าทำอะไรไป
```

**จะเห็น:** ประวัติมี commit อย่างน้อย 3 รายการ ชื่อคุณทั้งหมด

→ 🚩 **Checkpoint 4: หน้ารายการอ่านจาก Firestore จริง + แก้ใน Console แล้วหน้าเว็บเปลี่ยนตาม**
📸 โพสต์ screenshot คู่กัน (หน้าเว็บ + Console) 🎥 มีคลิปสั้น 2 นาทีของขั้นนี้ในธนาคารคำตอบสด
