## 🔁 วิธีสั่งงาน AI ที่ใช้ทั้งใบงานนี้ — วงจร 4 จังหวะ

**อ่านหัวข้อนี้ให้จบก่อนเริ่ม 2 นาที** — **ทุกขั้นในใบงานนี้ใช้วิธีเดียวกันหมด** ไม่มีขั้นไหนที่ต่างออกไป

```
1️⃣ สั่งสั้น 1–3 บรรทัด  →  2️⃣ AI เขียนแผน  →  3️⃣ คุณตรวจและแก้แผน  →  4️⃣ สั่งลงมือทีละข้อ
```

| จังหวะ | ใครทำ | พิมพ์แบบนี้ |
|:---:|---|---|
| 1 | คุณ | *"ผมอยากได้หน้ารายการใบลา ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ"* |
| 2 | AI | เขียนแผนออกมาเป็นข้อ ๆ — **อ่านให้ครบทุกข้อก่อนตอบ** |
| 3 | **คุณ** ⭐ | *"ข้อ 3 ไม่ใช่ ผมอยากได้ ______ ที่เหลือโอเค"* |
| 4 | คุณ | *"แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน"* |

- ⭐ **จังหวะที่ 3 คืองานของคุณ** — คุณไม่ต้องเขียนคำสั่งยาว ๆ ให้ครบถ้วน คุณต้องอ่านแผนแล้วบอกว่าข้อไหนไม่ใช่ เท่านั้น
- **prompt ทุกอันในใบงานนี้สั้น 1–3 บรรทัด** ถ้าคุณเห็นตัวเองกำลังพิมพ์ยาว 10 บรรทัด แปลว่าคุณกำลังข้ามจังหวะที่ 2 กับ 3 ไป
- **งานที่ใหญ่กว่าหนึ่งขั้น ขอแผนก่อนเสมอ** · งานเล็กอย่างเปลี่ยนสีหรือแก้ข้อความ สั่งตรงได้เลย
- ⚠️ **prompt ยาวไม่ได้แปลว่าดีกว่า** — การสั่งยาวรวดเดียวคือสาเหตุที่โปรเจกต์พังบ่อยที่สุด

### 📄 หลักการเดียวกันนี้ใช้กับไฟล์ด้วย

**คุณไม่ต้องนั่งพิมพ์ไฟล์ยาว ๆ เอง** — สั่งให้ AI ร่างให้ แล้วคุณอ่านและบอกว่าอะไรขาด

- ⌨️ การพิมพ์ยาว ๆ ไม่ใช่ทักษะที่หลักสูตรนี้สอน และพิมพ์ผิดง่ายมาก โดยเฉพาะชื่อภาษาอังกฤษ
- ✅ **สิ่งที่คุณต้องฝึกคือ "อ่านแล้วรู้ว่าอะไรขาด"** ไม่ใช่ "พิมพ์ได้ครบ"
- ⚠️ **แต่ต้องอ่านจริงทุกครั้ง** — ทุกจุดที่ AI ร่างอะไรมา ใบงานนี้จะมีบรรทัด **"อ่านแล้วตอบว่าอะไรขาด"** ต่อท้ายเสมอ **ห้ามข้าม** เพราะตอนนำเสนอคุณต้องตอบได้ว่าระบบตัวเองทำงานอย่างไร

# ส่วน A — สร้างโปรเจกต์และปุ่มย้อนเวลา ⏱ ~46 นาที

> 🎯 **ส่วนนี้จบเมื่อ:** หน้าแรกของ LeaveEasy ขึ้นในเบราว์เซอร์ และมี commit แล้วอย่างน้อย 3 ครั้ง

### A1. สร้างโฟลเดอร์และเริ่มต้นโปรเจกต์ ⏱ ~8 นาที

1. เปิด **terminal** (หน้าต่างสีเข้มที่พิมพ์คำสั่ง)
2. พิมพ์ทีละบรรทัด กด Enter ทีละบรรทัด

```
cd Desktop
mkdir leaveeasy
cd leaveeasy
npm init -y
```

**จะเห็น:** หลังบรรทัดสุดท้าย terminal พิมพ์ข้อความสีเทาออกมาประมาณ 12 บรรทัด ขึ้นต้นด้วย `Wrote to ...package.json` · เปิดโฟลเดอร์ `Desktop/leaveeasy` ดูจะเห็น **ไฟล์ใหม่ 1 ไฟล์ชื่อ `package.json`**

> 💡 `mkdir` = สร้างโฟลเดอร์ · `cd` = เดินเข้าโฟลเดอร์ · `npm init -y` = ประกาศว่าโฟลเดอร์นี้เป็นโปรเจกต์เว็บ

> 🆘 **ขึ้นว่า `npm is not recognized` หรือ `command not found`** → ปิด terminal แล้วเปิดใหม่ 1 ครั้ง แล้วพิมพ์ใหม่ · ถ้ายังไม่ได้ พิมพ์ `🔴` ในแชททันที **อย่านั่งงมเกิน 10 นาที**

---

### A2. ติดปุ่มย้อนเวลาก่อนทำอะไรต่อ ⏱ ~8 นาที

> 💡 **ทำไมต้องทำตอนนี้:** เดี๋ยว AI จะเข้ามาแก้ไฟล์จริงในโฟลเดอร์นี้ ถ้ายังไม่มีปุ่มย้อน พังแล้วกลับไม่ได้ · **นี่คือกฎข้อแรกของเดือนนี้**

1. พิมพ์ทีละบรรทัด

```
git init
git add .
git commit -m "เริ่มต้นโปรเจกต์ LeaveEasy"
```

**จะเห็น:**
- บรรทัดแรก ขึ้นข้อความ `Initialized empty Git repository in ...`
- บรรทัดที่สาม ขึ้นข้อความประมาณ `[main (root-commit) a1b2c3d] เริ่มต้นโปรเจกต์ LeaveEasy` และบรรทัดว่า `1 file changed`

2. ตรวจว่าหมุดแรกติดแล้ว พิมพ์

```
git log --oneline
```

**จะเห็น:** 1 บรรทัด เป็นรหัสสั้น ๆ ตามด้วยข้อความ `เริ่มต้นโปรเจกต์ LeaveEasy` · กด `q` เพื่อออก ถ้ามันค้างอยู่

> 🆘 **ขึ้นว่า `Please tell me who you are`** → เป็นเรื่องปกติของเครื่องที่ใช้ git ครั้งแรก พิมพ์ 2 บรรทัดนี้ (ใส่ชื่อกับอีเมลของคุณ) แล้วสั่ง `git commit` ใหม่
> ```
> git config --global user.name "ชื่อของคุณ"
> git config --global user.email "อีเมลของคุณ"
> ```

#### 🥅 อ่านตรงนี้ก่อนไปต่อ — คุณมีตาข่ายรับ 2 ชั้น ไม่ใช่ชั้นเดียว

คำถามที่ผู้เรียนถามมากที่สุดคือ **"ถ้า AI แก้แล้วพังจะทำยังไง"** — คำตอบอยู่ตรงนี้ **อ่าน 1 นาทีแล้วไปต่อ**

| ชั้น | ใช้เมื่อ | ทำอย่างไร |
|:---:|---|---|
| 🥅 **ชั้นที่ 1** | รู้ตัวทันทีว่าคำสั่งที่เพิ่งสั่งไปไม่ใช่ | ในหน้าต่าง Claude Code **กดปุ่ม `Esc` สองครั้งติดกัน** |
| 🥅 **ชั้นที่ 2** | พังสะสมหลายรอบ หรือปิดหน้าต่างไปแล้ว | พิมพ์ `git checkout .` ใน terminal |

**ชั้นที่ 1 ทำงานอย่างไร**

```
Esc         หยุด Claude กลางคัน ตอนมันกำลังทำงานอยู่
Esc Esc     เปิดเมนูย้อนกลับ เลือกจุดที่จะย้อน
/rewind     คำสั่งที่ทำงานเหมือนกด Esc สองครั้ง
```

**จะเห็น:** เมนูขึ้นมาแสดงรายการจุดที่ย้อนกลับไปได้ · เลือกได้ว่าจะย้อนโค้ดที่มันแก้ไป ย้อนบทสนทนาที่คุยไป หรือย้อนทั้งสองอย่าง · เลือกแล้วรีเฟรชเบราว์เซอร์

> ⚠️ **คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ** · ถ้ายังไม่ได้ ให้ใช้ชั้นที่ 2 (`git checkout .`) ซึ่งใช้ได้เสมอ **อย่านั่งงมกับชั้นที่ 1 เกิน 5 นาที**

> 💡 **ทำไมยังต้อง commit ทั้งที่มี `Esc Esc` แล้ว:** ชั้นที่ 1 อยู่ในหน้าต่างที่เปิดอยู่ตอนนั้น · ปิดหน้าต่างแล้วหรือข้ามวันไปแล้ว เหลือชั้นที่ 2 อย่างเดียว — **`commit` คือชั้นที่คุณพึ่งได้จริงตลอดทั้งเดือน**

# ส่วน C — ฝึกวงจรแก้งาน 3 รอบ ⏱ ~30 นาที

> 🎯 **ส่วนนี้จบเมื่อ:** คุณคุยกับ AI แก้หน้าจอไปแล้ว 3 รอบ และ commit ครบ 3 ครั้ง
>
> 💡 **ทำไมต้องฝึก:** งานจริงเกือบทั้งหมดคือการ *แก้ต่อจากของที่มีอยู่* ไม่ใช่การสร้างใหม่ · การสั่งแก้ให้ตรงจุดคือทักษะที่ใช้ทั้งเดือน

**เลือกหน้าจอ 1 หน้าที่คุณคิดว่ายังไม่ถูกใจ** แล้วสั่งแก้ทีละรอบ **รอบละ 1–2 เรื่องเท่านั้น**

### C1. รอบที่ 1 — แก้เรื่องหน้าตา ⏱ ~10 นาที

> 💡 **งานเล็กแบบนี้สั่งตรงได้เลย ไม่ต้องขอแผน** — กติกาคือ **งานที่ใหญ่กว่าหนึ่งขั้นเมื่อไร ให้กลับไปขอแผนก่อนเสมอ**

**prompt ที่ใช้ได้ (ปรับชื่อไฟล์และสิ่งที่อยากแก้เป็นของคุณ):**
> ดูเฉพาะไฟล์ leave-requests.html
> ขอให้แถวตารางสลับสีอ่อนเข้ม และสถานะแสดงเป็นป้ายสี
> ไฟล์อื่นยังไม่ต้องแตะ

**จะเห็น:** ตารางแถวสลับสี · สถานะกลายเป็นป้ายสีกลม ๆ

> 💡 **ประโยค "ไฟล์อื่นยังไม่ต้องแตะ" สำคัญมาก** — ใส่ทุกครั้ง เพราะบางทีมันจะไปแก้ไฟล์อื่นที่คุณไม่ได้ขอ

```
git add .
git commit -m "ปรับหน้ารายการใบลาให้อ่านง่ายขึ้น ใส่ป้ายสีสถานะ"
```

### C2. รอบที่ 2 — แก้เรื่องเนื้อหา ⏱ ~10 นาที

เลือก 1 อย่างที่คุณอยากได้เพิ่ม แล้วเขียน prompt เอง โดยใช้โครงนี้

**โครง prompt (เติมช่องว่างเอง):**
> ดูเฉพาะไฟล์ ______
> เพิ่ม ______ เข้าไป
> ให้หน้าตาเข้าชุดกับของเดิม
> ไฟล์อื่นยังไม่ต้องแตะ

**ตัวอย่างสิ่งที่เพิ่มได้:** จำนวนวันลาที่คำนวณจากวันเริ่มถึงวันสิ้นสุด · แถบค้นหาหัวข้อ (ยังไม่ต้องทำงานจริง) · ปุ่มกลับหน้าแรกทุกหน้า

```
git add .
git commit -m "เพิ่ม ______ ในหน้า ______"
```

### C3. รอบที่ 3 — สั่งแก้แล้วผลไม่ถูกใจ สั่งแก้ต่อ ⏱ ~10 นาที

1. สั่งแก้อะไรก็ได้ 1 อย่าง
2. **ดูผลแล้วบอกความรู้สึกจริง ๆ กลับไป** โดยใช้โครงนี้

   **prompt ที่ใช้ได้:**
   > ผลที่ได้ยังไม่ตรงที่ผมต้องการ
   > สิ่งที่ผมเห็นตอนนี้คือ ______
   > สิ่งที่ผมอยากเห็นคือ ______
   > แก้เฉพาะจุดนั้น ส่วนอื่นที่ดีอยู่แล้วอย่าไปแตะ

3. ดูผลอีกครั้ง แล้ว commit

> 💡 **นี่คือ prompt ที่มีประโยชน์ที่สุดของทั้งวัน** — บอกสิ่งที่เห็น กับสิ่งที่อยากเห็น เทียบกันตรง ๆ · เก็บไว้ใช้ทั้งเดือน

```
git add .
git commit -m "แก้ ______ ตามที่ตรวจด้วยตาแล้วยังไม่ถูกใจ"
```

> 🆘 **Claude แก้แล้วหน้าจอพังกว่าเดิม** → อย่าพยายามแก้ทับ ให้ย้อนกลับไปจุดที่ยังดี
>
> **ถ้าเพิ่งสั่งไปเมื่อกี้และรู้ตัวทันที** → กดปุ่ม `Esc` **สองครั้งติดกัน** ในหน้าต่าง Claude Code → เลือกจุดที่จะย้อนจากเมนูที่ขึ้นมา → รีเฟรชเบราว์เซอร์ (นี่คือตาข่ายชั้นที่ 1 จากข้อ A2)
>
> **ถ้าพังสะสมมาหลายรอบ หรือปิดหน้าต่างไปแล้ว** → ใช้ตาข่ายชั้นที่ 2
> ```
> git checkout .
> ```
> แล้วรีเฟรชเบราว์เซอร์ · หน้าจอจะกลับไปเหมือนตอน commit ล่าสุด · **จากนั้นสั่งใหม่ให้เจาะจงขึ้น ทีละเรื่องเดียว**

- ⏳ รอนานกว่าเดิมชัดเจน

### D2. กู้กลับ แล้วเริ่มบทสนทนาใหม่ ⏱ ~17 นาที

1. **ย้อนกลับก่อน**

```
git checkout .
```
**จะเห็น:** รีเฟรชเบราว์เซอร์แล้วหน้าจอกลับไปเป็นเวอร์ชันที่ commit ไว้ล่าสุด

2. **ขอสรุปสถานะก่อนทิ้งบทสนทนา**

   **prompt ที่ใช้ได้:**
   > สรุปสถานะโปรเจกต์ตอนนี้ให้ผมเป็นข้อ ๆ
   > เขียนให้ผมคัดลอกไปเริ่มบทสนทนาใหม่ได้เลย

**จะเห็น:** สรุปเป็นข้อ ๆ ยาวประมาณ 15–25 บรรทัด

**📖 อ่านสรุปแล้วตอบว่าอะไรขาด — ห้ามข้าม** ตรวจ 3 ข้อนี้
- [ ] มีชื่อสถานะภาษาไทยครบ 4 ตัวที่คุณตกลงไว้ตอน B1
- [ ] มีชื่อประเภทการลาครบ 3 ตัว
- [ ] บอกว่ามีหน้าจอไหนทำเสร็จแล้วบ้าง

> ถ้าขาดข้อไหน ให้บอกกลับไปสั้น ๆ เช่น *"ขาดชื่อสถานะภาษาไทย ใส่เพิ่มให้ด้วย"* — **นี่คือจังหวะที่ 3 เหมือนตอนตรวจแผน** ใช้ได้กับทุกอย่างที่ AI เขียนกลับมา

3. **คัดลอกสรุปนั้นไปวางต่อท้ายไฟล์ `บันทึกสถานะ.md`**

> 💬 **ก่อนไปข้อ 4 — รู้จักทางเลือกกลางไว้ด้วย: `/compact`**
>
> วันนี้อาการของคุณหนักถึงขั้นต้องเริ่มใหม่ แต่ไม่ใช่ทุกครั้งที่ต้องถึงขั้นนั้น
>
> ```
> /compact                            ย่อบทสนทนาให้สั้นลง คืนพื้นที่ความจำ
> /compact เน้นเรื่องหน้าจอที่ทำไปแล้ว    บอกได้ว่าให้เก็บเรื่องไหนไว้
> ```
>
> **ต่างกับ `/clear` ตรงที่ `/compact` ยังคุยต่อได้เลย ไม่ได้เริ่มใหม่** ของที่ตกลงกันไว้ยังอยู่ในรูปแบบย่อ
>
> **เลือกอย่างไร**
>
> | ทางเลือก | เลือกเมื่อ | บริบทเดิม |
> |---|---|---|
> | คุยต่อ | เพิ่งเริ่ม ยังตอบตรงอยู่ | อยู่ครบ |
> | `/compact` | เริ่มช้าลง แต่ยังทำเรื่องเดิม | เหลือแบบย่อ |
> | `/clear` | เปลี่ยนไปทำเรื่องใหม่ หรือมันลืมข้อตกลงแล้ว | ไม่เหลือ |
>
> 🧪 **ทำตอนนี้ 1 นาที:** พิมพ์ `/compact` ดู 1 ครั้ง แล้วจดใน `บันทึกสถานะ.md` ว่าคำตอบหลังจากนั้นต่างจากเดิมไหม · **แล้วค่อยไปข้อ 4**

4. **ล้างบทสนทนาแล้วเริ่มใหม่ — พิมพ์ `/clear`** ในหน้าต่าง Claude Code

   ```
   /clear
   ```

   **จะเห็น:** บทสนทนาว่างเปล่าเหมือนเพิ่งเปิดโปรแกรม

   > ⭐ **ไฟล์ในโปรเจกต์ไม่ได้ถูกล้างไปด้วย** — เปิดโฟลเดอร์ `leaveeasy` ดูตอนนี้เลย **ไฟล์ยังอยู่ครบทุกไฟล์** สิ่งที่หายคือความจำของบทสนทนาเท่านั้น · ข้อนี้ทำให้หลายคนไม่กล้าพิมพ์ ทั้งที่ปลอดภัย
   >
   > 🆘 **พิมพ์ `/clear` แล้วไม่ได้ผล** → คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ · หรือใช้วิธีเดิมคือ **ปิดหน้าต่าง Claude Code แล้วเปิดใหม่** (พิมพ์ `claude` อีกครั้ง) ซึ่งได้ผลเหมือนกัน

5. **วาง prompt นี้เป็นข้อความแรกของบทสนทนาใหม่**

   **prompt ที่ใช้ได้ (จังหวะที่ 1):**
   > นี่คือสถานะโปรเจกต์ LeaveEasy ของผม
   > (วางสรุปที่คัดลอกไว้ตรงนี้)
   >
   > ผมอยากให้ทุกหน้ามีเมนูด้านบนเหมือนกัน
   > ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

6. **อ่านแผนแล้วตอบว่าอะไรขาด** แล้วใช้ **จังหวะที่ 3** แก้ด้วยประโยคสั้น ๆ

   **prompt ที่ใช้ได้ (จังหวะที่ 3 และ 4):**
   > เมนูขอลิงก์ครบ 5 หน้า และใช้ชื่อตามที่ตกลงไว้ข้างบนเท่านั้น
   > ที่เหลือโอเค ลงมือได้ ทำทีละข้อ

7. commit
