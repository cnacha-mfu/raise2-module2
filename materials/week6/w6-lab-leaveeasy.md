## 🔁 วิธีสั่งงาน AI ที่ใช้ทั้งใบงาน — วงจร 4 จังหวะ (จากคาบเช้า)

```
1️⃣ สั่งสั้น 1–3 บรรทัด → 2️⃣ AI เขียนแผน → 3️⃣ เราตรวจและแก้แผน ⭐ → 4️⃣ สั่งลงมือทีละข้อ → ตรวจด้วยตา → commit
```

- จังหวะที่ 3 คือหน้าที่ของ **คนตรวจ** ไม่ใช่คนพิมพ์ — คนพิมพ์อ่านแผนออกเสียง คนตรวจบอกว่าข้อไหนไม่ใช่
- ทุก prompt ในใบงานนี้เป็น**ตัวอย่างของ LeaveEasy** — เปลี่ยนชื่อระบบ ชื่อหน้า ชื่อโฟลเดอร์ เป็นของโครงงานกลุ่มคุณก่อนใช้
- **commit** (กดเซฟหนึ่งครั้งพร้อมข้อความกำกับ ย้อนกลับมาได้เสมอ) ทุกครั้งที่ทำอะไรสำเร็จ — ข้อความต้องอ่านรู้เรื่อง เช่น "เพิ่มหน้ารายการ" ไม่ใช่ "update"

## ส่วน A — นำเว็บ prototype ของกลุ่มเข้า repo ⏱ ~35 นาที

> ⌨️ คนคุมคีย์บอร์ดรอบ 1 ลงมือ — แนะนำให้เป็นเจ้าของเครื่องหลัก (เพราะรอบนี้ยังไม่ต้องใช้ Remote Control)

### A1 — สร้างโฟลเดอร์โปรเจกต์แล้วคัดลอก prototype เข้าไป (10 นาที)

1. บนเครื่องหลัก สร้างโฟลเดอร์ใหม่ ตั้งชื่อโครงงานกลุ่มเป็น**ภาษาอังกฤษ ไม่มีเว้นวรรค** เช่น `farmtrack`
2. คัดลอกไฟล์ prototype ทั้งหมดจาก Module 1 เข้าไปในโฟลเดอร์นี้ (ไฟล์ `.html` ทุกไฟล์ รวมโฟลเดอร์ `css/` `js/` ถ้ามี)
3. เปิดโฟลเดอร์ดู **จะเห็น:** ไฟล์ `.html` ของทุกหน้าจอเรียงอยู่ครบ

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** โฟลเดอร์ `leaveeasy` ที่ข้างในมี `index.html` · `leave-requests.html` · `new-leave-request.html` · `leave-request-detail.html` · `leave-types.html` · `dashboard.html` — **แล้วของกลุ่มคุณล่ะ มีไฟล์อะไรบ้าง?**

### A2 — ปักหมุดแรกด้วย git (10 นาที)

**ทำไมต้องทำก่อนเรียก AI:** อีกสักครู่ Claude Code จะเข้ามาแก้ไฟล์จริงของกลุ่มคุณ — ต้องมีหมุดให้ย้อนกลับก่อน ถึงจะปล่อยให้แก้ได้อย่างสบายใจ

1. เปิด **terminal** (หน้าต่างพิมพ์คำสั่ง) ในโฟลเดอร์โปรเจกต์
2. บอก git ว่าใครคือคนเซฟรอบนี้ — พิมพ์ 2 บรรทัดนี้ ใส่ชื่อจริงและอีเมลของ**คนคุมคีย์บอร์ดรอบ 1**:

```
git config user.name "ชื่อ-นามสกุลของคนคุมรอบนี้"
git config user.email "อีเมลของคนคุมรอบนี้"
```

   **จะเห็น:** ไม่มีข้อความอะไรขึ้น — เงียบคือสำเร็จ
3. พิมพ์ทีละบรรทัด:

```
git init
git add .
git commit -m "นำ prototype เข้าโปรเจกต์"
```

   **จะเห็น:** บรรทัดแรกขึ้น `Initialized empty Git repository` · บรรทัดสุดท้ายขึ้น `[main (root-commit) ...]` ตามด้วยจำนวนไฟล์

> 🆘 **ขึ้นว่า `Please tell me who you are`** → ข้อ 2 ยังไม่ได้ทำหรือพิมพ์ผิด — พิมพ์ 2 บรรทัด `git config` ใหม่ แล้วสั่ง `git commit` อีกครั้ง · เจอข้อความนี้ถือว่าปกติ เครื่องที่ใช้ git ครั้งแรกเจอกันทุกคน

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** commit แรกชื่อ "นำ prototype เข้าโปรเจกต์" ในชื่อของสมชาย (คนคุมรอบ 1) — **แล้วกลุ่มคุณ commit แรกเป็นชื่อใคร?**

### A3 — ให้ Claude ตั้งค่าให้รันได้ แล้วเปิดดู (15 นาที)

1. เปิด **Claude Code** ในโฟลเดอร์โปรเจกต์ แล้วพิมพ์ (เปลี่ยนข้อความให้เป็นของกลุ่มคุณ):

   **prompt ที่ใช้ได้ — จังหวะที่ 1:**
   > ผมเพิ่งนำเว็บ prototype เข้าโฟลเดอร์นี้
   > ช่วยตั้งค่าให้สั่ง npm run dev แล้วเปิดดูในเบราว์เซอร์ได้
   > เขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

   **จะเห็น:** แผนเป็นข้อ ๆ ยังไม่มีการแก้ไฟล์
2. 🔍 **คนตรวจอ่านแผนทีละข้อ** — ถ้ามีข้อที่ไม่เข้าใจหรือดูเกินจำเป็น (เช่น จะติดตั้งเครื่องมือแปลก ๆ เพิ่ม) ให้ถามหรือตัดออกก่อน แล้วค่อยพิมพ์:

   **prompt ที่ใช้ได้ — จังหวะที่ 4:**
   > แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

3. เสร็จแล้วพิมพ์ `npm run dev` ใน terminal → เปิดเบราว์เซอร์ตามที่อยู่ที่ terminal บอก (เช่น `http://localhost:3000` — ที่อยู่เว็บภายในเครื่องเราเอง)

   **จะเห็น:** หน้าเว็บ prototype ของกลุ่มคุณ หน้าตาเดิมจาก Module 1 ขึ้นในเบราว์เซอร์
4. commit เก็บหมุด:

```
git add .
git commit -m "ตั้งค่า npm run dev ได้แล้ว"
```

> 🆘 **`node -v` ไม่ขึ้นเลขเวอร์ชัน / `npm` ไม่รู้จักคำสั่ง** → Node.js ยังไม่ได้ติดตั้งบนเครื่องหลัก — พิมพ์ 🔴 ในแชท แล้วสลับเครื่องหลักไปเครื่องของสมาชิกที่ `node -v` ขึ้น (ย้ายโฟลเดอร์โปรเจกต์ตามไป) ระหว่างรอ TA ช่วยติดตั้งเครื่องเดิม

→ 🚩 **Checkpoint 1: เว็บ prototype ของกลุ่มขึ้นในเบราว์เซอร์ โดยรันจากโฟลเดอร์ repo**
📸 คนจดโพสต์ screenshot หน้าเว็บ + terminal ที่เห็น `npm run dev` ลงแชท พร้อมชื่อกลุ่มและไฟจราจร 🟢🟡🔴

## ส่วน B — แปลง DB Schema เป็นแบบโฟลเดอร์/ไฟล์ **บนกระดาษ** ⏱ ~30 นาที

> ✋ **ปิดคอม ทั้งกลุ่มช่วยกันบนกระดาษ** (เปิดได้อย่างเดียวคือไฟล์ DB Schema กับ Zoom) — แบบที่คิดไม่เสร็จ สร้างยังไงก็พัง และการแก้บนกระดาษใช้ยางลบ การแก้ในฐานข้อมูลใช้เวลาทั้งบ่าย
> 🎬 เมื่อเช้าผู้สอนแปลง Schema ของ FixIt สดบนกระดานด้วย**กติกา 4 ข้อ** — ตอนนี้ถึงตาแบบของกลุ่มคุณ

### B1 — เขียนกติกา 4 ข้อไว้หัวกระดาษ (5 นาที)

```
1) ตาราง            → 📁 โฟลเดอร์
2) แถว → 📄 ไฟล์  ·  คอลัมน์ → ✏️ ช่องข้อมูลในไฟล์
3) ช่องที่ชี้ไปตารางอื่น → เก็บรหัส (ID) + จดชื่อซ้ำ (Name)
4) ตารางลูกที่ห้อยกับแม่ → 📁 โฟลเดอร์ย่อยในไฟล์แม่
```

### B2 — แปลงทีละตาราง (15 นาที)

1. เปิด DB Schema ของกลุ่ม อ่านชื่อตารางทีละตาราง — สมาชิก**ผลัดกันตอบ**ว่าตารางนี้กลายเป็นอะไรตามกติกาข้อไหน แล้วคนถือปากกา (คนคุมรอบ 2) วาดลงกระดาษ
2. ทุกช่องที่ชี้ไปตารางอื่น: เขียนทั้งช่องรหัสและช่องชื่อ แล้ว**วงกลมสีแดงตรงช่องชื่อที่จดซ้ำ** — จุดนี้คือจุดที่ถ้าลืม หน้าจอจะขึ้นรหัสประหลาดแทนชื่อคน
3. เขียน**ชื่อช่องข้อมูลเป็นภาษาอังกฤษ ตัวพิมพ์เล็ก-ใหญ่ชัดเจน ครบทุกตัว** — `status` กับ `Status` เป็นคนละช่องใน Firestore และสะกดผิดจะพังแบบเงียบ ๆ ไม่มี error ให้เห็น
4. 🔍 คนตรวจอ่านชื่อช่องบนกระดาษ**ออกเสียงทีละตัว** ให้อีกคนดูตามในไฟล์ Schema — ตรวจข้ามคน ห้ามคนเขียนตรวจของตัวเอง

   **จะเห็น:** กระดาษที่มีโฟลเดอร์ทุกโฟลเดอร์ ไฟล์ตัวอย่าง 1 ไฟล์ต่อโฟลเดอร์ ชื่อช่องครบ และวงกลมสีแดงตรงทุกช่องที่จดซ้ำ

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้ (กระดาษหน้าตาประมาณนี้):**
> ```
> 📁 users/          📄 u001 { name, email, role }
> 📁 leaveTypes/     📄 lt001 { name }
> 📁 leaveRequests/  📄 lr001 { title, reason, status,
>                       requesterId, (requesterName) ← วงแดง
>                       approverId,  (approverName)  ← วงแดง
>                       leaveTypeId, (leaveTypeName) ← วงแดง
>                       startDate, endDate, createdAt }
>       📁 approvals/  📄 ap001 { authorId, (authorName) ← วงแดง, message, createdAt }
> ```
> — **แล้วของกลุ่มคุณล่ะ โฟลเดอร์ชื่ออะไร และช่องไหนต้องวงแดงบ้าง?**

### B3 — เติมตารางเทียบ 3 ช่อง (10 นาที)

ลอกตารางนี้ลงท้ายกระดาษ แล้วเติม**ช่องขวาสุดของกลุ่มคุณ** — ห้ามลอกช่องกลาง เพราะโครงงานคุณไม่ใช่ระบบขอลา:

| | 🎬 FixIt | 🔧 LeaveEasy | 👥 โครงงานกลุ่มคุณ |
|---|---|---|---|
| 📁 โฟลเดอร์หลัก | `tickets` | `leaveRequests` | ____________ |
| 📁 โฟลเดอร์ประเภท | `categories` | `leaveTypes` | ____________ |
| 📁 โฟลเดอร์ย่อย | `comments` | `approvals` | ____________ |
| ✏️ ช่องที่จดซ้ำ | `reporterName` | `requesterName` | ____________ |
| 🚦 ค่าในช่อง `status` | 4 ค่า (แจ้งใหม่→เสร็จสิ้น) | 3 ค่า (รอพิจารณา→อนุมัติ/ไม่อนุมัติ) | ____________ |

> 💡 สังเกตว่า FixIt กับ LeaveEasy มีจำนวนสถานะไม่เท่ากัน — เทียบกันได้ไม่ได้แปลว่าเหมือนกัน โครงงานคุณอาจมี 2 ค่าหรือ 5 ค่าก็ได้ ขอให้ตอบได้ว่า**ทำไม**

→ 🚩 **Checkpoint 2: แบบโครงสร้างบนกระดาษเสร็จ ชื่อช่องครบ วงแดงครบ ตารางเทียบเติมครบ**
📸 คนจดถ่ายรูปกระดาษโพสต์ลงแชท พร้อมชื่อกลุ่มและไฟจราจร
🔄 **หมุนบทบาท:** คนคุมคีย์บอร์ดรอบ 2 ขอ Remote Control เครื่องหลักให้เรียบร้อยก่อนเริ่มส่วน C

> 🏁 **ถึง Checkpoint 2 = ผ่านขั้นต่ำของวันนี้แล้ว** — ถ้าเวลาเหลือน้อยหรือกลุ่มติดหนัก ให้เดินส่วน C ไปให้ไกลที่สุดโดยไม่ต้องเครียด ที่เหลือมีที่เก็บตก (ดูตาราง 🆘 แถว "ทำไม่ทัน")

## ส่วน C — สร้าง Firestore ตามแบบ · seed · หน้ารายการอ่านจากฐานจริง ⏱ ~75 นาที

> ⌨️ คนคุมคีย์บอร์ดรอบ 2 เริ่ม — ก่อนพิมพ์อะไร ให้เปลี่ยนชื่อคนเซฟใน terminal ก่อน:
> ```
> git config user.name "ชื่อ-นามสกุลของคนคุมรอบ 2"
> git config user.email "อีเมลของคนคุมรอบ 2"
> ```
> commit ตั้งแต่บรรทัดนี้ไปจะเป็นชื่อคนใหม่ — นี่คือวิธีที่ทุกคนได้ commit ในชื่อตัวเองแม้ใช้เครื่องเดียวกัน (**วันนี้ต้องมี commit จากอย่างน้อย 2 คน**)

### C1 — เปิดตู้ Firestore ในโหมดทดสอบ (10 นาที)

1. เข้า [console.firebase.google.com](https://console.firebase.google.com) → เลือกโปรเจกต์ของกลุ่ม → เมนู **Firestore Database** (ถ้าหาไม่เจอ ใช้ช่องค้นหาพิมพ์ Firestore — หน้าตาเมนูเปลี่ยนได้ตามเวอร์ชัน)
2. กด **Create database** → เลือก **โหมดทดสอบ (test mode)** = ตู้ที่ยังไม่ล็อกกุญแจ ใครมีที่อยู่ก็อ่านเขียนได้ → เลือกตำแหน่งเซิร์ฟเวอร์ (ใกล้เอเชียยิ่งดี) → รอสร้างเสร็จ

   **จะเห็น:** หน้า Data ของ Firestore ที่ว่างเปล่า ยังไม่มีโฟลเดอร์อะไรเลย
3. 📝 คนจด**เขียนวันหมดอายุของโหมดทดสอบลงบนกระดาษแบบ** — ถึงวันนั้นตู้จะเงียบใส่โดยไม่บอกอะไร (กุญแจจริงคือล็อกอิน+กฎ ซึ่งมาสัปดาห์ที่ 7–8)

> ⚠️ **ตู้ยังไม่ล็อกกุญแจ = ห้ามใส่ข้อมูลจริงของคนจริงเด็ดขาด** — ใช้ชื่อสมมติเท่านั้น เช่น สมชาย สมหญิง สมศรี และอีเมลลงท้าย `@example.com`

> 🆘 **Console บังคับให้เลือกแผน/ผูกบัตร** → เลือกแผนฟรี (Spark) ให้ได้ก่อน ถ้าไม่มีตัวเลือก ให้โพสต์คิวถามกลางทันที — เงื่อนไขของ Firebase เปลี่ยนได้ อย่าเดา

### C2 — เชื่อมเว็บของกลุ่มกับตู้ (10 นาที)

1. ใน Console เปิด ⚙️ **Project settings → Your apps** → ถ้ายังไม่มีแอป กดไอคอน `</>` เพิ่ม Web app (ตั้งชื่อตามโครงงาน) → **จะเห็น:** กล่องโค้ด `firebaseConfig` (ชุดที่อยู่และกุญแจสำหรับให้เว็บรู้จักตู้ของเรา) → คัดลอกทั้งกล่องไว้
2. ใน Claude Code พิมพ์:

   **prompt ที่ใช้ได้ — จังหวะที่ 1:**
   > ผมอยากให้เว็บนี้ต่อกับ Firestore ของโปรเจกต์กลุ่มผม
   > เดี๋ยวผมจะวางค่า firebaseConfig ให้ ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ

3. 🔍 คนตรวจอ่านแผน → โอเคแล้วสั่งลงมือ ("แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน") → วาง `firebaseConfig` เมื่อ Claude ขอ

   **จะเห็น:** ไฟล์ตั้งค่าใหม่ในโปรเจกต์ (เช่น `js/firebase.js`) และ Claude รายงานว่าเชื่อมเสร็จ

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** ไฟล์ `js/firebase.js` ที่มี config ของโปรเจกต์ LeaveEasy — **ของกลุ่มคุณ config มาจากโปรเจกต์ Firebase ชื่ออะไร?** (เช็กมุมซ้ายบนของ Console ว่าเป็นโปรเจกต์กลุ่มคุณจริง ไม่ใช่โปรเจกต์ทดลองเก่า)

### C3 — seed: ใส่ข้อมูลตัวอย่างตามแบบบนกระดาษ (15 นาที)

**seed (ข้อมูลตัวอย่าง)** = ข้อมูลชุดเริ่มต้นที่ใส่ไว้ก่อน เพื่อให้แยกออกว่า "อ่านไม่ได้" หรือ "ไม่มีอะไรให้อ่าน"

> 📏 **นี่คือข้อยกเว้นเดียวของวันนี้ที่ prompt ยาวได้** — เพราะเนื้อหาคือรายการชื่อโฟลเดอร์และชื่อช่องข้อมูลจากกระดาษของกลุ่มคุณ ซึ่งสะกดผิดตัวเดียวพังแบบเงียบ ๆ ต้องระบุเองให้ครบ ห้ามให้ AI เดา · งานอื่นทั้งหมดกลับไปสั่งสั้นเหมือนเดิม

1. คนคุมคีย์บอร์ดพิมพ์ prompt โดย**เปิดกระดาษแบบวางข้างจอ** เขียนตามโครงนี้ (แทนที่ทุกช่องว่างด้วยของกลุ่มคุณ):

   **prompt ที่ใช้ได้ (ยาวได้ เพราะเป็นรายการข้อมูล):**
   > ใส่ข้อมูลตัวอย่างลง Firestore ให้ผม ชื่อทุกตัวสะกดตามนี้เป๊ะ ๆ ห้ามเปลี่ยน
   > โฟลเดอร์ ______ มีช่อง ______ — ใส่ ___ รายการ: (เขียนข้อมูลสมมติทีละรายการ)
   > โฟลเดอร์ ______ มีช่อง ______ — ใส่ ___ รายการ: …
   > โฟลเดอร์หลัก ______ ใส่ 5 รายการ มีช่อง ______ ทุกช่องตามนี้ — ค่าในช่อง status ใช้ได้เฉพาะ: ______
   > โฟลเดอร์ย่อย ______ ใต้รายการแรก มีช่อง ______
   > ใช้ชื่อคนสมมติ เช่น สมชาย สมหญิง สมศรี เสร็จแล้วรันให้เลย

2. 🔍 **ก่อนกด Enter — คนตรวจอ่านชื่อโฟลเดอร์และชื่อช่องใน prompt ออกเสียง เทียบกระดาษทีละตัว** ตัวพิมพ์เล็ก-ใหญ่ต้องตรงทุกตำแหน่ง
3. กด Enter — Claude จะเขียนสคริปต์ seed แล้วรัน

   **จะเห็น:** terminal ขึ้นข้อความทำนอง "เพิ่มข้อมูลเรียบร้อย" ไม่มีบรรทัด error สีแดง

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้ prompt จะเป็น:**
> > ใส่ข้อมูลตัวอย่างลง Firestore ให้ผม ชื่อทุกตัวสะกดตามนี้เป๊ะ ๆ ห้ามเปลี่ยน
> > โฟลเดอร์ users มีช่อง name, email, role — 3 คน: สมชาย ใจดี (employee) · สมหญิง รักงาน (manager) · สมศรี ตั้งใจ (hr) อีเมลใช้ @example.com
> > โฟลเดอร์ leaveTypes มีช่อง name — ลาพักร้อน · ลาป่วย · ลากิจ
> > โฟลเดอร์ leaveRequests ใส่ใบลา 5 ใบ มีช่อง title, reason, status, requesterId, requesterName, approverId, approverName, leaveTypeId, leaveTypeName, startDate, endDate, createdAt — status ใช้ได้เฉพาะ: รอพิจารณา / อนุมัติ / ไม่อนุมัติ
> > โฟลเดอร์ย่อย approvals ใต้ใบแรก มีช่อง authorId, authorName, message, createdAt
> > ใช้ชื่อคนสมมติ เสร็จแล้วรันให้เลย
>
> — **แล้วของกลุ่มคุณ โฟลเดอร์และช่องชื่ออะไรบ้าง? เปิดกระดาษตอบ**

### C4 — เปิด Console ส่องด้วยตา (10 นาที)

**ทำไมห้ามข้าม:** AI บอกว่าเสร็จ ไม่ได้แปลว่าเสร็จ — ทักษะสำคัญที่สุดของวันนี้คือส่องตู้ด้วยตาตัวเอง

1. สลับไปแท็บ Firebase Console → รีเฟรชหน้า Data

   **จะเห็น:** โฟลเดอร์ของกลุ่มคุณโผล่ครบทุกโฟลเดอร์ตามกระดาษ
2. กดเปิดโฟลเดอร์หลัก → เปิดไฟล์รายการแรก → 🔍 คนตรวจไล่ชื่อช่องบนจอเทียบกระดาษทีละช่อง โดยเฉพาะ**ช่องที่วงแดงไว้** (ชื่อคนต้องเป็นภาษาไทย ไม่ใช่รหัส)
3. commit ในชื่อคนคุมรอบ 2:

```
git add .
git commit -m "ต่อ Firestore และใส่ข้อมูลตัวอย่างแล้ว"
```

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** Console แสดง `users` `leaveTypes` `leaveRequests` และเปิด `lr001` แล้วเห็น `requesterName: "สมชาย ใจดี"` คู่กับ `requesterId` — **Console ของกลุ่มคุณ เปิดไฟล์แรกแล้วเห็นช่องอะไรบ้าง?**

☕ **ถึงเวลาพัก (14:35–14:45) ให้พักจริง** — กลับมาแล้ว**คนคุมคีย์บอร์ดรอบ 3 รับช่วง** อย่าลืม `git config user.name / user.email` เป็นชื่อตัวเองก่อนพิมพ์อะไรต่อ

### C5 — ต่อหน้ารายการให้อ่านจากตู้จริง (20 นาที)

1. พิมพ์ (เปลี่ยนชื่อหน้าและชื่อโฟลเดอร์เป็นของกลุ่มคุณ):

   **prompt ที่ใช้ได้ — จังหวะที่ 1:**
   > เปลี่ยนหน้ารายการ จากข้อมูลปลอมในโค้ด ให้อ่านจากโฟลเดอร์ ______ ใน Firestore แทน
   > หน้าอื่นยังไม่ต้องแตะ ช่วยเขียนแผนให้ดูก่อน อย่าเพิ่งลงมือ

2. 🔍 **จุดตรวจแผนที่สำคัญที่สุดของวันนี้:** ถ้าแผนมีข้อที่แถมปุ่มบันทึก / แก้ / ลบ / ล็อกอิน — **ตัดออก** ด้วยประโยคเดียว:

   **prompt ที่ใช้ได้ — จังหวะที่ 3:**
   > ข้อที่ทำปุ่มบันทึกตัดออก วันนี้อ่านอย่างเดียว
   > ที่เหลือโอเค ลงมือได้ ทำทีละข้อ

3. เสร็จแล้วรีเฟรชเบราว์เซอร์

   **จะเห็น:** หน้ารายการแสดงข้อมูลชุดเดียวกับที่เห็นใน Console — ไม่ใช่ข้อมูลปลอมชุดเดิม

> 🆘 **หน้ารายการว่างเปล่า** → เปิด Console ก่อนเสมอ: ข้อมูลอยู่ในตู้ไหม · อยู่ = พังตอนอ่าน (กด F12 ดูข้อความ error แดง แล้ววางให้ Claude ดู) · ไม่อยู่ = พังตอนใส่ (กลับไป C3) — วิธีคิดนี้ตอบได้ใน 10 วินาทีว่าต้องไปแก้ฝั่งไหน ขั้นนี้คนติดกันเยอะ เจอแล้วถือว่าปกติ

### C6 — พิสูจน์ว่าระบบมีความจำจริง (10 นาที)

1. ใน Console แก้ข้อความ 1 ช่องของรายการแรก (เช่น เติมคำว่า "(ทดสอบ)" ท้ายหัวข้อ) → รีเฟรชหน้าเว็บ

   **จะเห็น:** ข้อความบนหน้าเว็บเปลี่ยนตามทันที — หน้าจอกับตู้ต่อกันแล้วจริง
2. แก้กลับให้เหมือนเดิม แล้วปิดเบราว์เซอร์**ทั้งหน้าต่าง** → เปิดใหม่ เข้าหน้ารายการ

   **จะเห็น:** ข้อมูลยังอยู่ครบ — นี่คือ "ระบบเริ่มมีความจำ" ของโครงงานกลุ่มคุณ 🎉
3. commit ในชื่อคนคุมรอบ 3:

```
git add .
git commit -m "หน้ารายการอ่านจากฐานข้อมูลจริงแล้ว"
```

4. พิมพ์ `git log --oneline` **จะเห็น:** รายการ commit อย่างน้อย 5 บรรทัด อ่านแล้วรู้ว่าแต่ละหมุดคืออะไร

→ 🚩 **Checkpoint 3: Console เห็นข้อมูล seed + หน้ารายการอ่านจากฐานจริง + commit จากอย่างน้อย 2 คน**
📸 คนจดโพสต์ 3 ภาพลงแชท: ① Console ที่เห็นโฟลเดอร์และข้อมูล ② หน้ารายการบนเว็บ ③ ผลของ `git log` — พร้อมชื่อกลุ่มและไฟจราจร
