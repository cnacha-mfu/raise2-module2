🧪 ช่วงที่ 1 — ให้ AI ทดสอบระบบแทนเรา · 1 ชม. 20 นาที

🗒️ เริ่มด้วยคำถามให้ห้องคิด — "หลังแก้โค้ดครั้งล่าสุด ใครไล่กดครบทุกหน้าบ้างครับ" · มักไม่มีใครยกมือ แล้วพูดว่า "นั่นแหละคือปัญหาที่ช่วงนี้แก้"

ทำไมต้องทดสอบอัตโนมัติ

  • ทุกครั้งที่แก้อะไร ควรไล่กดใหม่ทั้งระบบ
  • ระบบมีหลายหน้า หลายเส้นทาง — กดเองทุกรอบไม่ไหว
  • บั๊กที่หลุดถึงผู้ใช้ แพงกว่าบั๊กที่เจอในเครื่องเรา
  • ให้หุ่นยนต์กดแทน แล้วเราไปทำอย่างอื่น
🗒️ พูดว่า "เราไม่ได้ทดสอบเพราะอยากได้ใบรับรอง เราทดสอบเพราะไม่มีเวลากดเองทุกรอบ" · บอกว่าชุดทดสอบนี้เป็น 1 ใน 5 ของส่งมอบให้ Module 3

สัปดาห์ที่แล้วเรามี 🔍 Reviewer แล้ว

  • สัปดาห์ที่ 8 เราตั้ง Reviewer ให้อ่านโค้ดแล้วรายงาน
  • Reviewer เห็นโค้ด แต่ไม่เคยกดปุ่มในเว็บของเราเลย
  • รายงานที่บอกว่าผ่าน ไม่ใช่ใบรับประกัน
  • สัปดาห์นี้เราเติมอีกตัว — 🧪 Tester
🗒️ ทวน Reviewer สั้น ๆ 1 นาที ห้ามสอนซ้ำ เพราะทำไปแล้วสัปดาห์ที่ 8 · พูดว่า "Reviewer อ่านแบบแปลนบ้าน Tester เดินเข้าไปในบ้านแล้วลองเปิดประตูทุกบาน" · ย้ำว่าสองตัวนี้เจอปัญหาคนละแบบ

Sub-Agent แปลว่าอะไร — ทวน 1 นาที

  • Sub-agent = ผู้ช่วย AI อีกตัวที่มีหน้าที่เฉพาะ
  • เราตั้งชื่อ ตั้งหน้าที่ และตั้งขอบเขตให้มัน
  • ตั้งค่าด้วยไฟล์ที่วางไว้ในโฟลเดอร์โครงงาน
  • เราไม่พิมพ์ไฟล์นี้เอง — สั่ง Claude สร้างให้
🗒️ พูดว่า "ไม่ใช่ AI ตัวใหม่ที่ต้องไปสมัคร มันคือ Claude Code ตัวเดิมที่เราสั่งให้สวมหมวกคนละใบ" · อ้างกลับสัปดาห์ที่ 8 ว่าเราทำแบบนี้มาแล้วครั้งหนึ่งตอนตั้ง Reviewer

ทำไมการมี context แยกกันถึงได้ผล

  • Context = "ความจำ" ของ AI ในหนึ่งบทสนทนา
  • ตัวที่เขียนโค้ด มีเหตุผลของตัวเองค้างอยู่ในความจำ
  • sub-agent เริ่มด้วยความจำเปล่า
  • จึงเจอสิ่งที่ตัวเขียนมองข้าม
🗒️ พูดว่า "นี่คือเหตุผลที่มันได้ผลจริง ไม่ใช่การตั้งชื่อใหม่ให้ดูดี" · เชื่อมกลับสัปดาห์ที่ 6 เรื่อง context บวมและ /clear

MCP คืออะไร

  • MCP = ช่องทางให้ AI ใช้เครื่องมือภายนอกได้
  • ปกติ AI พิมพ์ข้อความและแก้ไฟล์ได้เท่านั้น
  • มี MCP แล้ว AI หยิบเครื่องมืออื่นมาใช้ได้
  • เปรียบเทียบ: เหมือนต่อมือให้ AI
🗒️ พูดว่า "เหมือนเมื่อก่อน AI พูดได้อย่างเดียว ตอนนี้มันหยิบของได้แล้ว" · ไม่ต้องลงรายละเอียดว่ามันทำงานเบื้องหลังอย่างไร ห้องนี้ไม่ต้องรู้

Playwright คืออะไร

  • Playwright = หุ่นยนต์ที่กดใช้เว็บแทนคน
  • เปิดเบราว์เซอร์จริง · พิมพ์จริง · กดปุ่มจริง
  • แล้วบอกกลับมาว่าเห็นอะไรบนหน้าจอ
  • Playwright MCP = ต่อหุ่นยนต์ตัวนี้เข้ากับ Claude Code
🗒️ พูดว่า "เดี๋ยวจะได้เห็นเบราว์เซอร์เปิดขึ้นมาเองแล้วกดปุ่มเองสด ๆ ตรงนี้แหละที่ห้องมักจะฮือฮา" · บอกว่าเราสั่งเป็นภาษาไทย ไม่ต้องเขียนโค้ดเทสต์เอง

🗒️ พูดว่า "นาทีนี้คือนาทีที่คนส่วนใหญ่ตัดสินใจผิด — รีบแก้โค้ดให้เทสต์เขียว แล้วระบบพังเงียบ ๆ" · บอกว่าเดี๋ยวจะให้ดูของจริงตอนสาธิต

🗒️ ชี้กล่องแรก "ตรงนี้ยังไม่ต้องแก้อะไรทั้งนั้น" · หยุดค้างที่กล่องเข้มกล่องที่สอง พูดว่า "ทุกอย่างขึ้นอยู่กับกล่องนี้ เปิดเว็บกดเองด้วยมือ 30 วินาที" · แล้วชี้สองกล่องขวาทีละกล่อง "พังเหมือนกัน แปลว่าโค้ดผิด ไปแก้โค้ด · กดเองใช้ได้ปกติ แปลว่าเทสต์เขียนผิด ไปแก้เทสต์" · ย้ำว่าห้ามข้ามกล่องที่สองไปเดาเอง

  • ให้เพื่อนอีกกลุ่มลองเปิด แล้วบอกว่าเห็นอะไร
  • ต้องเก็บข้อมูลลง Firestore ได้จริง ไม่ใช่ข้อมูลปลอม
  • 🆘 เปิดไม่ได้ → กลับไปที่ขั้นตอน deploy สัปดาห์ที่ 8
🗒️ พูดว่า "URL ที่เปิดได้เฉพาะบนเครื่องตัวเอง ยังไม่นับว่าออนไลน์" · ให้จับคู่กลุ่มสลับกันเปิด URL ของอีกกลุ่มเดี๋ยวนี้ 1 นาที แล้วรายงานในแชท

2️⃣ repo — และ 👤 commit ของทุกคน

  • ใน repo ต้องมี CLAUDE.md ที่ตรงกับระบบจริง
  • ทุกคนในกลุ่มต้องมี commit ในชื่อตัวเอง
  • คนที่ไม่มี commit เลย ถือว่ายังไม่ผ่าน Module
  • ตรวจได้จากหน้าประวัติของ repo บน GitHub
🗒️ พูดตรง ๆ ว่า "ข้อนี้เป็นเกณฑ์รายบุคคล ไม่ใช่รายกลุ่ม" · ให้ทุกกลุ่มเปิดหน้าประวัติ commit ของ repo ตัวเองเดี๋ยวนี้ แล้วนับว่าเห็นชื่อครบทุกคนไหม · ใครยังไม่มี ให้แก้ตั้งแต่บ่ายนี้ อย่ารอถึงศุกร์

👤 ยังมีคนไม่มี commit ทำอย่างไร

  • ให้คนนั้นเป็นคนคุมคีย์บอร์ดในช่วงถัดไปทันที
  • ทำงานจริง 1 ก้อน แล้ว commit ในชื่อตัวเอง
  • ❌ ห้ามให้คนอื่น commit แทนแล้วใส่ชื่อให้
  • ปัญหานี้แก้บ่ายนี้ได้ แต่แก้วันศุกร์ไม่ทัน
🗒️ พูดว่า "ผมรู้ว่าบางกลุ่มมีคนหนึ่งที่พิมพ์เร็วกว่าคนอื่นมาก และมันเลยกลายเป็นแบบนี้ ไม่ใช่ความผิดใคร แต่ต้องแก้วันนี้" · บอกว่า TA จะเดินตรวจหน้าประวัติ commit ของทุกกลุ่มในช่วง 15:35 ตามที่นัดไว้

3️⃣ ชุดทดสอบ Playwright ที่ผ่าน

  • เทสต์อยู่ใน repo ไม่ใช่อยู่ในหน้าจอที่เพิ่งรันอย่างเดียว
  • ต้องรันแล้วผ่าน ณ วันที่ส่ง
  • เทสต์ที่ยัง fail → เขียนลงข้อ 5 อย่าลบทิ้ง
  • ⚠️ ห้ามแก้โค้ดระบบเพื่อให้เทสต์ผ่าน
🗒️ ย้ำประโยคสุดท้ายเป็นครั้งที่สองของวัน · พูดว่า "เทสต์ที่ fail และเราจดไว้ มีค่ามากกว่าเทสต์ที่เราลบทิ้งเพื่อให้รายงานสวย"

4️⃣ Backlog Sprint 2

  • มาจาก feedback จริงในบ่ายนี้ ไม่ใช่คิดเอง
  • เขียนเป็นประโยคที่ทำได้ ไม่ใช่ความรู้สึก
  • เรียงลำดับว่าอันไหนควรทำก่อน
  • ⭐ ต้องมีข้อค้างจาก ส.8: เปลี่ยนคีย์ AI ไปใช้ตัวกลาง
  • นี่คือจุดเริ่มของ Module 3 ในวันแรก
🗒️ พูดว่า "ถ้าเขียนว่า ปรับ UI ให้ดีขึ้น Module 3 หยิบไปทำต่อไม่ได้ ต้องเขียนว่า ทำให้ปุ่มบันทึกอยู่ในจอบนมือถือ" · ให้กลุ่มเขียนอย่างน้อย 5 ข้อ

📌 Module 3 คืออะไร

  • Module 3 = AI-Integrated
  • Data Analytics · หน้าสรุป · กราฟ · AI ขั้นลึกกว่านี้
  • อยากทำหน้าสรุป หรือต่อยอดผู้ช่วย AI → ใส่ Backlog Sprint 2
  • ไม่ใช่ทำในสัปดาห์นี้
🗒️ พูดว่า "ผมรู้ว่าหลายกลุ่มอยากทำหน้าสรุปหรือกราฟตั้งแต่วันนี้ ขอให้เก็บไว้ก่อน เพราะ Module 3 สอนเรื่องนี้ทั้ง Module และจะทำได้ดีกว่ามาก" · ย้ำว่าจดลง Backlog ถือว่าไม่เสียของ

5️⃣ บันทึกสิ่งที่ยังไม่เสร็จ

บันทึกส่งต่อ Module 3 — <ชื่อโครงงานของกลุ่ม>

▸ เสร็จแล้ว
- แจ้งเรื่อง / มอบหมาย / อัปเดตสถานะ / ปิดงาน
- ล็อกอิน · กฎเฝ้าข้อมูล · เทสต์เส้นทางหลัก

▸ ยังไม่เสร็จ
- แจ้งเตือนทางอีเมลเมื่อมอบหมายผู้รับผิดชอบ

▸ รู้ตัวว่าทำลวกไว้
- หน้ารายการยังโหลดข้อมูลทั้งหมดทีเดียว ถ้าข้อมูลเยอะจะช้า
- ยังไม่มีเทสต์ของหน้าจัดการประเภท
🗒️ พูดว่า "เขียนสามหัวข้อนี้ ครึ่งหน้ากระดาษพอ" · ย้ำว่า "ข้อ 5 ไม่ใช่การสารภาพผิด — กลุ่มที่รู้ว่าตัวเองทำลวกตรงไหน คือกลุ่มที่ควบคุมงานอยู่" · บอกว่าไฟล์นี้ทำให้ผู้สอน Module 3 ช่วยได้ตรงจุดตั้งแต่วันแรก
