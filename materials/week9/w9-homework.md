## 📋 ทำตามนี้

### A — 🚀 สั่งทีเดียวจบจากสเปคของคุณ *(เหมือนใบงานส่วน A)*

**1. เขียนสเปคของคุณให้พร้อมก่อน** — รวม `SCOPE.md` กับสิ่งที่ทำมา 3 สัปดาห์ ให้อยู่ในไฟล์เดียว

```prompt
อ่าน SCOPE.md กับโค้ดในโปรเจกต์นี้ แล้วเขียนไฟล์ spec.md ให้ผม
บอกว่ามีหน้าจออะไรบ้าง โครงสร้างข้อมูลชื่ออะไร บทบาทผู้ใช้มีใคร
และมีอะไรบ้างที่ไม่ทำใน Module นี้
เขียนเสร็จให้ผมอ่านก่อน
```

⭐ **อ่านแล้วแก้ให้ตรงกับระบบจริงของคุณ** — สเปคไม่ชัด สั่งทีเดียวก็ได้ของไม่ตรง

**2. ให้ AI เสนอทีมผู้ช่วย แล้วคุณตรวจ**

```prompt
อ่าน spec.md แล้วเสนอว่าควรแบ่งงานให้ผู้ช่วยกี่ตัว
แต่ละตัวทำอะไร และควรใช้โมเดลไหนเพื่อไม่ให้เปลืองโทเคน
ขอดูแผนก่อน อย่าเพิ่งสร้าง
```

⭐ **อ่านแผนแล้วตรวจ 3 ข้อ** — งานครบทุกก้อนไหม · **งานทำตามแบบใช้โมเดลเล็กหรือยัง** · มีข้อกำกับห้ามทำงานนอกสเปคไหม
ครบแล้วสั่ง *"แผนโอเคแล้ว สร้างผู้ช่วยให้เลย"* — **โมเดลที่เลือกคือค่าใช้จ่ายของคุณ**

**3. สั่งทีเดียวจบ แล้วตรวจกับสเปค**

```prompt
ให้ผู้ช่วยทุกตัวสร้างระบบตาม spec.md ให้ครบ
เสร็จแต่ละส่วนให้รายงานผมทีละตัว
```

✅ **ตรวจ:** เปิดสเปคเทียบทีละข้อ — ชื่อช่องตรงไหม · สถานะครบไหม · **มีของแถมที่สเปคไม่ได้ขอไหม** → สั่งแก้เฉพาะข้อนั้น

> 💡 **ทำในโฟลเดอร์ใหม่ก็ได้** ถ้าอยากเก็บของเดิมไว้เทียบ · แต่ส่งการบ้านด้วย repo เดิมของคุณเสมอ

### B — 🧪 เทสต์ 5 ตัวให้ผ่าน *(เหมือนใบงานส่วน B)*

พิมพ์ `/mcp` ตรวจว่า playwright ต่ออยู่ → สั่งสร้าง sub-agent ชื่อ `tester` (ใช้โมเดล `sonnet`) → **เปิดไฟล์อ่าน** → ให้เปิด URL ของคุณ

```prompt จังหวะที่ 1 — ขอแผนก่อน
ให้ tester เสนอแผนทดสอบเว็บของผมที่ <URL ของคุณ> 5 ตัวนี้ อย่าเพิ่งเขียน
1 <เส้นทางหลักของคุณ>
2 <ปุ่มเปลี่ยนสถานะของคุณ>
3 กรอกไม่ครบแล้วต้องไม่บันทึก
4 ไม่ล็อกอินแล้วอ่านข้อมูลไม่ได้
5 บัญชีที่สองเปิดข้อมูลของบัญชีแรกไม่ได้
```

> ⚠️ prompt นี้ยาวได้ เพราะเป็น**รายการเทสต์ที่ห้ามตกข้อ** — ตกข้อ 4 หรือ 5 แปลว่าไม่ได้ทดสอบเรื่องข้อมูลรั่วเลย

⭐ **อ่านแผนแล้วตอบว่าอะไรขาด** แล้วค่อยสั่ง *"แผนโอเคแล้ว เขียนแล้วรันให้ผม"*

> 🚫 **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน** — แยกก่อนเสมอว่า *โค้ดผิด* หรือ *เทสต์เขียนผิด*
> ⚠️ ถ้าเทสต์ 4 หรือ 5 ไม่ผ่าน แปลว่า **ข้อมูลของคุณรั่วจริง** ให้กลับไปแก้กฎตาม [การบ้านที่ 3](../week8/w8-homework.html) ส่วน A ก่อนทำอย่างอื่น

### C — 📊 รายงานผล + ส่งงาน *(เหมือนใบงานส่วน C)*

**`BACKLOG.md` ต้องมีอย่างน้อย:**
- ย้ายคีย์ AI ไปไว้ฝั่งที่ผู้ใช้แตะไม่ได้
- ฟีเจอร์จาก Feature List ของ Module 1 ที่ยังไม่ได้ทำ
- สิ่งที่เทสต์จับได้แต่ยังไม่ได้แก้

```prompt
ช่วยรันเทสต์ทั้งหมดอีกรอบ แล้วสรุปผลเป็นไฟล์ test-results.md ให้ผม
บอกว่าเทสต์แต่ละตัวทดสอบอะไร ผ่านหรือไม่ผ่าน และรันเมื่อไร
ข้อที่ไม่ผ่านให้บอกด้วยว่าติดตรงไหน
```

⭐ **เปิดอ่านจริง ๆ ว่าครบ 4 ข้อไหม** — ทดสอบอะไร · ผ่านหรือไม่ · รันเมื่อไร · ข้อที่ไม่ผ่านติดตรงไหน
🚫 **ข้อที่ไม่ผ่านให้เขียนตามจริง** ห้ามแก้รายงานให้สวยกว่าผลจริง แล้วจดข้อนั้นลง `BACKLOG.md`

**🔴 ก่อน push ทุกครั้ง — กันคีย์ AI หลุด**

```prompt
ผมกำลังจะส่งงานขึ้น GitHub
ช่วยย้ายคีย์ AI ออกจากโค้ด ไปไว้ในไฟล์แยกที่ .gitignore กันไว้
แล้วเขียน URL เว็บออนไลน์กับลิงก์ไปที่ test-results.md ไว้บนสุดของ README.md
จากนั้นแสดงรายการไฟล์ที่กำลังจะส่งขึ้น GitHub ให้ผมดู
```

⭐ **อ่านรายการนั้นด้วยตาเอง** — เห็นชื่อไฟล์ที่มีคีย์เมื่อไร **หยุดทันที อย่า push**
