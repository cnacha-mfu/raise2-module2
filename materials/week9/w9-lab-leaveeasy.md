#### ข้อ 1 — เพิ่มแดชบอร์ดสรุปใบลา ⏱ 20 นาที

**ข้อนี้เป็นงานใหญ่ — เดินครบทั้ง 4 จังหวะ**

**prompt จังหวะที่ 1 — ขอแผนก่อน:**

> ผมอยากได้หน้าแดชบอร์ดสรุปใบลาของ LeaveEasy
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**จะเห็น:** Claude **ไม่แตะไฟล์เลย** แต่เขียนแผนออกมาเป็นข้อ ๆ ประมาณนี้
1. สร้างหน้าแดชบอร์ดใหม่
2. นับใบลาแยกตามสถานะ แสดงเป็นตัวเลขใหญ่
3. แสดงรายการที่รอพิจารณาใต้ตัวเลข

> ✍️ **จังหวะที่ 3 — อ่านแผนแล้วตอบก่อนไปต่อ (ห้ามข้าม)**
> อ่านทีละข้อ แล้วตอบ 2 คำถามนี้กับตัวเอง
> 1. *"แผนบอกไหมว่าตัวเลขต้องนับจากข้อมูลจริงใน Firestore"* — ถ้าไม่บอก AI มักพิมพ์ตัวเลขสวย ๆ ค้างไว้ในโค้ด
> 2. *"แผนบอกไหมว่าระหว่างโหลดข้อมูลจะให้ผู้ใช้เห็นอะไร"* — ถ้าไม่บอก หน้าจอจะว่างเปล่าแล้วผู้ใช้กดซ้ำ
>
> เกือบทุกคนจะพบว่าแผน**ขาดทั้งสองข้อ**

**prompt จังหวะที่ 3 — แก้แผน:**

> ข้อ 2 ตัวเลขทุกตัวต้องนับจากข้อมูลจริงใน Firestore ห้ามพิมพ์ค้างไว้ในโค้ด
> เพิ่มข้อว่าระหว่างโหลดให้แสดงคำว่า "กำลังโหลด..." แทนตัวเลข

**prompt จังหวะที่ 4 — ลงมือ:**

> แผนโอเคแล้ว ลงมือทีละข้อ เสร็จข้อไหนบอกผมก่อน
> อย่าเปลี่ยนพฤติกรรมของหน้าอื่นที่ทำงานได้อยู่แล้ว

**จะเห็น:**
- Claude Code ไล่อ่านไฟล์ประมาณ 20–40 วินาที แล้วแสดงรายการไฟล์ที่จะสร้างและแก้
- รีเฟรชเว็บแล้วเปิดหน้าแดชบอร์ด → **ตัวเลข 3 ช่อง** และรายการใบที่รอพิจารณาข้างล่าง

**ตรวจด้วยตาว่าถูกจริง:**
1. เปิด **Firebase Console → Firestore → `leaveRequests`**
2. นับไฟล์ที่สถานะ "รอพิจารณา" ด้วยตา
3. ตัวเลขต้อง **ตรงกัน**

> 🆘 **ตัวเลขขึ้น 0 ทุกช่อง** → ชื่อสถานะในโค้ดสะกดไม่ตรงกับที่เก็บใน Firestore
> พิมพ์ต่อว่า: *"ตัวเลขขึ้นเป็นศูนย์ทุกช่อง ช่วยเปิดดูค่าจริงของฟิลด์สถานะใน Firestore แล้วบอกผมว่าสะกดตรงกับในโค้ดไหม"*

> 🆘 **ตัวเลขไม่ตรงกับที่นับเอง** → มักเป็นเพราะนับใบที่ถูกลบไปแล้วรวมด้วย
> พิมพ์ต่อว่า: *"ตัวเลขในแดชบอร์ดมากกว่าที่ผมนับใน Console อยู่ 2 ใบ ช่วยตรวจว่าโค้ดนับใบที่ถูกลบไปแล้วรวมด้วยหรือไม่"*

#### ข้อ 2 — เพิ่มการแนบเอกสารประกอบใบลา ⏱ 25 นาที

**ทำความเข้าใจก่อน 1 นาที:** **Firebase Storage** (🗄️ ตู้เก็บไฟล์ของ Firebase) เก็บ**ตัวไฟล์** · **Firestore** (📁 ตู้เก็บข้อมูลแบบโฟลเดอร์/ไฟล์) เก็บ**ลิงก์**ของไฟล์นั้น

```code
🗄️ Storage
   leaveRequests/lr001/medical-cert.pdf     ← ไฟล์จริงอยู่ที่นี่

📁 Firestore
   📁 leaveRequests
      📄 lr001 { หัวข้อ, สถานะ, attachmentUrl: "https://.../medical-cert.pdf" }
```

**prompt จังหวะที่ 1 — ขอแผนก่อน:**

> ผมอยากให้ใบลาแนบเอกสารประกอบได้ 1 ไฟล์

#### ข้อ 5 — ตั้ง 🔍 Reviewer แล้วสั่งตรวจทั้งโปรเจกต์ ⏱ 12 นาที

> 🚫 **คุณไม่ต้องนั่งเขียนไฟล์ตั้งค่าเอง และไม่ต้องไปหาเมนูตั้งค่าที่ไหน** — ให้ AI สร้างไฟล์ให้ **แล้วงานของคุณคืออ่านว่ามีบรรทัดสำคัญครบไหม**

**เดิน 3 จังหวะนี้ตามลำดับ ห้ามข้ามจังหวะที่ 3**

```code
จังหวะที่ 1  สั่งให้ Claude สร้าง sub-agent ชื่อ reviewer
จังหวะที่ 3  เปิดไฟล์ที่มันสร้างขึ้นมาอ่าน แล้วตอบว่าครบไหม   ← ห้ามข้าม
จังหวะที่ 4  สั่งให้เริ่มตรวจทั้งโปรเจกต์
```

**prompt จังหวะที่ 1 — สั่งให้สร้าง (กรณียกเว้น — ยาวได้ เพราะเป็นรายการที่ต้องตรวจ ตกข้อเดียวคือมีรูที่ไม่มีใครดู):**

> ช่วยตั้ง sub-agent ชื่อ reviewer ให้โปรเจกต์ LeaveEasy
> หน้าที่: อ่านโค้ดในโปรเจกต์แล้วรายงานจุดที่น่าจะมีปัญหา
>
> ให้ตรวจเฉพาะ 5 เรื่องนี้เท่านั้น
> 1. กฎความปลอดภัยของข้อมูลที่เปิดกว้างเกินจำเป็น
> 2. จุดที่รับข้อมูลจากผู้ใช้แล้วบันทึกโดยไม่ตรวจก่อน
> 3. จุดที่ไม่ได้จัดการกรณีหาข้อมูลไม่เจอหรือเรียกข้อมูลไม่สำเร็จ
> 4. ค่าที่ไม่ควรอยู่ในโค้ด เช่น กุญแจหรือรหัสผ่าน
> 5. การตั้งชื่อฟิลด์ในฐานข้อมูลที่ไม่สม่ำเสมอ
>
> กติกาของรายงาน
> - แต่ละข้อบอก: ไฟล์และบรรทัด · ปัญหาคืออะไร · ผลกระทบถ้าไม่แก้
> - จัดระดับเป็น แดง / เหลือง / ขาว
> - ห้ามแก้ไขโค้ดเอง ให้รายงานอย่างเดียว
> - เขียนรายงานเป็นภาษาไทย

**จะเห็น:** Claude สร้างไฟล์ตั้งค่า sub-agent ในโฟลเดอร์โครงงาน แล้วบอกว่าตั้งชื่อ `reviewer` เรียบร้อย

> ✍️ **จังหวะที่ 3 · ขั้นตรวจ — ห้ามข้าม** ⭐
> **เปิดไฟล์ตั้งค่าที่ AI เพิ่งสร้างขึ้นมาอ่านด้วยตาตัวเอง** (ถามกลับไปได้ว่า *"ไฟล์ตั้งค่าที่สร้างให้ อยู่ที่ไหน ชื่ออะไร"*) แล้วตอบ 3 ข้อนี้
> 1. *"มีบรรทัดที่เขียนว่า **ห้ามแก้ไขโค้ดเอง** ไหม"* — ถ้าไม่มี คุณจะได้โค้ดที่เปลี่ยนไปโดยที่คุณไม่เคยอ่าน
> 2. *"รายการที่ให้ตรวจอยู่ครบ 5 ข้อไหม"* — ตกไปข้อไหน แปลว่าเรื่องนั้นจะไม่มีใครตรวจเลย
> 3. *"เขียนไว้ไหมว่าให้รายงานเป็นภาษาไทย"* — ถ้าไม่มี คุณจะได้รายงานภาษาอังกฤษยาว ๆ ที่อ่านช้า
>
> ขาดข้อไหนให้พิมพ์กลับไปว่า *"ในไฟล์ตั้งค่ายังไม่มี … ช่วยเพิ่มให้ด้วย"*
> **ถ้าคุณไม่เปิดไฟล์นี้อ่าน คุณจะตอบไม่ได้ว่า Reviewer ของตัวเองตรวจอะไรอยู่** — และนั่นคือคำถามที่ถูกถามบ่อยที่สุดตอนนำเสนอ

**prompt จังหวะที่ 4 — สั่งให้เริ่มตรวจ (กลับมาสั้นแล้ว เพราะหน้าที่ทั้งหมดอยู่ในไฟล์ตั้งค่าแล้ว):**

> ให้ reviewer ตรวจทั้งโปรเจกต์
> แล้วเขียนผลลงไฟล์ `review-notes.md` แยกเป็น แดง เหลือง ขาว

**จะเห็น:** ข้อความไล่ชื่อไฟล์ขึ้นเรื่อย ๆ ประมาณ **1–3 นาที** · **30 วินาทีแรกอาจเงียบ ถือว่าปกติ** · จบด้วยไฟล์ `review-notes.md` โผล่ในโฟลเดอร์ **ที่จัดกองมาให้แล้ว**

#### ข้อ 8 — เชื่อม 🤖 Playwright MCP แล้วพิสูจน์ว่าเชื่อมติด ⏱ 8 นาที

```code
คุณ → Claude Code → [MCP] → 🤖 Playwright → 🌐 เบราว์เซอร์จริง เปิด LeaveEasy
```

**ข้อนี้มี 2 ขั้น — ขั้นตรวจก่อน แล้วค่อยยืนยันซ้ำ**

**8.1 — 🚩 ขั้นตรวจก่อน: พิมพ์ `/mcp` แล้วดูสถานะ**

พิมพ์คำสั่งนี้ในหน้าต่าง Claude Code แล้วกด Enter

```code
/mcp
```

**จะเห็น:** รายชื่อ MCP server ที่เครื่องคุณตั้งไว้ พร้อม**สถานะของแต่ละตัว** · เทียบกับตารางนี้แล้วทำตามช่องขวา

| สิ่งที่เห็นบนจอ | แปลว่า | ทำอย่างไรต่อ |
|---|---|---|
| **ไม่มี server เลยสักตัว** | **ยังไม่ได้ติดตั้ง** MCP | กลับไปทำตามคู่มือติดตั้ง หรือใช้ไฟล์ตั้งค่าสำเร็จรูปที่ผู้สอนแจก |
| **เชื่อมต่อแล้ว** | พร้อมใช้งาน | ไปทำข้อ 8.2 ต่อได้เลย |
| **ต้องยืนยันตัวตนก่อน** | ยังไม่ได้ยืนยันตัวตน | เลือก server นั้น แล้วทำตามที่หน้าจอบอก |
| **เชื่อมต่อไม่สำเร็จ** | ตั้งไว้แล้วแต่ต่อไม่ติด | เลือก server นั้นแล้วสั่งเชื่อมใหม่ · ยังไม่ได้ให้ปิด Claude Code แล้วเปิดใหม่ |
| **รอการอนุมัติ** | ยังไม่ได้อนุมัติให้ใช้ | อนุมัติให้ใช้งาน server นั้นก่อน |

> 💡 **แถวแรกมีค่าที่สุด** — มันแยกให้คุณเห็นระหว่าง *ยังไม่ได้ติดตั้ง* กับ *ติดตั้งแล้วแต่เชื่อมไม่ติด* ซึ่งสองอย่างนี้แก้คนละทางกัน
> ถ้าไม่ถามด้วย `/mcp` ก่อน คุณจะไล่แก้ผิดจุดและเสียเวลาไปหลายสิบนาที

> ⚠️ **คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ**
> ในห้องนี้ทุกคนติดตั้งกันคนละวัน เวอร์ชันจึงไม่เท่ากัน · หน้าจอของคุณกับของเพื่อนไม่เหมือนกันเป๊ะ ถือว่าปกติ

**prompt ที่ใช้ได้:**

> ให้ tester เปิดหน้าแรกของ LeaveEasy ที่ URL นี้ `<ใส่ URL จริงของคุณ>`
> แล้วบอกเป็นภาษาไทยว่าเห็นอะไรบนหน้าจอบ้าง
> ยังไม่ต้องเขียนเทสต์

**จะเห็น:**
1. **หน้าต่างเบราว์เซอร์เปิดขึ้นมาเอง** โดยที่คุณไม่ได้แตะเมาส์

> สถานะขึ้นว่าเชื่อมต่อแล้วแต่ยังไม่เปิด → **ปิด Claude Code แล้วเปิดใหม่ 1 ครั้ง** (ไฟล์ตั้งค่า MCP อ่านตอนเปิดโปรแกรมเท่านั้น)
> ยังไม่ขึ้น → ใช้ **ไฟล์ตั้งค่าสำเร็จรูป**ที่ผู้สอนแจก แล้วเปิดใหม่อีกครั้ง

#### ข้อ 9 — ตั้ง 🧪 Tester แล้วเขียนเทสต์เส้นทางหลัก ⏱ 17 นาที

**เดินแบบเดียวกับข้อ 5 — สั่งให้สร้าง → เปิดไฟล์อ่าน → สั่งลงมือ · ไม่ต้องเข้าเมนูตั้งค่าใด ๆ**

**prompt จังหวะที่ 1 — สั่งให้สร้าง (กรณียกเว้น — ยาวได้ เพราะ URL บัญชีทดสอบและกติกาห้ามตกข้อ สะกดผิดบรรทัดเดียวล็อกอินไม่ได้ทั้งชุด):**

> ช่วยตั้ง sub-agent ชื่อ tester ให้โปรเจกต์ LeaveEasy
> หน้าที่: ใช้ Playwright MCP เปิดเบราว์เซอร์จริงแล้วทดสอบระบบแทนคน
>
> ข้อมูลที่ใช้
> - URL ของระบบ: `<ใส่ URL จริงของคุณ>`
> - บัญชีทดสอบผู้ขอลา: somchai.test@example.com
> - บัญชีทดสอบหัวหน้า: somying.test@example.com
>
> กติกา
> 1. ทดสอบตาม Acceptance Criteria (เงื่อนไขว่าฟีเจอร์นี้ถือว่าเสร็จเมื่อไร) ที่เขียนไว้ในไฟล์ spec เท่านั้น
> 2. เขียนเทสต์ให้แต่ละตัวทดสอบเรื่องเดียว และตั้งชื่อเป็นภาษาไทย
> 3. ทุกครั้งที่รอหน้าเว็บ ให้รอจนกว่าองค์ประกอบที่ต้องการจะขึ้น ห้ามใช้การรอแบบนับเวลาเฉย ๆ
> 4. ห้ามแก้ไขโค้ดของระบบเพื่อให้เทสต์ผ่านเด็ดขาด ถ้าเทสต์ไม่ผ่านให้รายงานว่าไม่ผ่านเพราะอะไร
> 5. รายงานผลเป็นภาษาไทย

**จะเห็น:** Claude สร้างไฟล์ตั้งค่า sub-agent ชื่อ `tester` ในโฟลเดอร์โครงงาน แล้วบอกว่าตั้งเรียบร้อย

> ✍️ **จังหวะที่ 3 · ขั้นตรวจ — ห้ามข้าม** ⭐
> **เปิดไฟล์ตั้งค่า tester ที่ AI เพิ่งสร้างขึ้นมาอ่าน** แล้วตอบ 3 ข้อนี้
> 1. *"URL ในไฟล์ ตรงกับ URL จริงของ LeaveEasy ของผมไหม"* — ผิดตัวเดียว เทสต์จะไปทดสอบเว็บของคนอื่น
> 2. *"บัญชีทดสอบครบทั้ง 2 บัญชีและสะกดถูกไหม"* — สะกดผิด ล็อกอินไม่ได้ทั้งชุด
> 3. *"มีบรรทัด **ห้ามแก้ไขโค้ดของระบบเพื่อให้เทสต์ผ่าน** ไหม"* — ถ้าไม่มี AI จะไปแก้ระบบให้เทสต์เขียว
>
> ขาดหรือผิดข้อไหน ให้พิมพ์กลับไปว่า *"ในไฟล์ตั้งค่า tester ยังไม่ถูก … ช่วยแก้ให้ด้วย"*
> 📤 พิมพ์ในแชทกลุ่มว่า **"ผมเปิดไฟล์ตั้งค่า tester อ่านแล้ว ข้อที่ต้องแก้คือ …"** (ถ้าครบหมด ให้พิมพ์ว่า "ครบทั้ง 3 ข้อ")

> 🚫 **คุณไม่ต้องนั่งเขียนไฟล์เทสต์เอง และไม่ต้องพิมพ์รายการเทสต์ยาว ๆ ด้วย**
> ให้ AI **เสนอมาก่อน** ว่าควรทดสอบอะไรบ้าง แล้วงานของคุณคือ **เทียบกับ Acceptance Criteria ที่คุณเขียนไว้เดือนที่ 1**
> *(Acceptance Criteria = เงื่อนไขว่าฟีเจอร์นี้ถือว่าเสร็จเมื่อไร)*

**prompt จังหวะที่ 1 — ขอรายการก่อน:**

> ให้ tester เสนอมาว่าควรทดสอบเส้นทางหลักของ LeaveEasy อะไรบ้าง
> ทำเป็นรายการให้ผมดูก่อน อย่าเพิ่งเขียนเทสต์

**จะเห็น:** รายการเทสต์ที่เสนอมา 4–6 ตัว เช่น ล็อกอิน · ยื่นใบลา · หัวหน้าอนุมัติ · ดูรายการ

> ✍️ **จังหวะที่ 3 — เปิดไฟล์ spec ของคุณวางข้าง ๆ แล้วไล่เทียบทีละบรรทัด (ห้ามข้าม)**
> ตอบคำถามนี้: **"รายการที่ AI เสนอ ครบตาม Acceptance Criteria ของคุณไหม ขาดข้อไหน"**
> คนส่วนใหญ่จะพบว่าขาด 1–2 ข้อ เช่น **ไม่ได้ตรวจว่าความเห็นการอนุมัติถูกบันทึกจริง** หรือ **ไม่ได้ตรวจว่าตัวเลขแดชบอร์ดขยับตาม**
> 📤 พิมพ์ในแชทกลุ่มว่า **"รายการที่ AI เสนอขาดข้อ … ผมเพิ่มเข้าไปแล้ว"**

**prompt จังหวะที่ 3 — แก้รายการ:**

> เพิ่มอีก 2 ข้อ — ตรวจว่าความเห็นการอนุมัติถูกบันทึกและแสดงจริง
> และปิดใบลาแล้วตัวเลขแดชบอร์ดช่อง "อนุมัติ" ต้องเพิ่มขึ้น 1

**prompt จังหวะที่ 4 — ลงมือ:**

> รายการโอเคแล้ว เขียนแล้วรันได้เลย ทีละตัว
> ไม่ผ่านตรงไหน ให้บอกว่าไม่ผ่านที่ขั้นไหนและเห็นอะไรแทน
