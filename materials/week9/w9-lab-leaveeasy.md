## ส่วน A — เชื่อม Playwright + ตั้ง 🧪 Tester ⏱ ~30 นาที

> 🎯 **จบส่วนนี้ Claude Code ของกลุ่มจะเปิดเบราว์เซอร์จริงเข้าโครงงานของกลุ่มได้เอง**

### A1. ตรวจว่า Playwright MCP เชื่อมต่ออยู่ ⏱ ~5 นาที

**ทำ:** เปิด Claude Code ในโฟลเดอร์โครงงานของกลุ่ม → พิมพ์

```code
/mcp
```

**จะเห็น:** รายชื่อ MCP server ในเครื่อง พร้อมสถานะของแต่ละตัว — ต้องเห็น **Playwright ขึ้นว่าเชื่อมต่อแล้ว**

| สิ่งที่เห็นบนจอ | แปลว่า | ทำอย่างไรต่อ |
|---|---|---|
| ไม่มี server เลยสักตัว | ยังไม่ได้ติดตั้ง | เปิด `shared/templates/playwright-mcp-setup.md` ทำขั้นที่ 2–3 |
| เชื่อมต่อแล้ว | พร้อมใช้งาน | ไปข้อ A2 ต่อได้เลย |
| ต้องยืนยันตัวตนก่อน | ยังไม่ได้ยืนยันตัวตน | เลือก server นั้นแล้วทำตามที่หน้าจอบอก |
| เชื่อมต่อไม่สำเร็จ | ตั้งไว้แล้วแต่ต่อไม่ติด | เลือก server นั้นแล้วสั่งเชื่อมใหม่ · ยังไม่ได้ → ปิด-เปิด Claude Code ใหม่ 1 ครั้ง |
| รอการอนุมัติ | ยังไม่ได้อนุมัติให้ใช้ | อนุมัติให้ใช้งาน server นั้นก่อน |

> ⚠️ **คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน** ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ — ห้องนี้ 40 คนติดตั้งกันคนละวัน หน้าจอไม่เหมือนเพื่อนเป๊ะถือว่าปกติ

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** `/mcp` ขึ้นว่า Playwright เชื่อมต่อแล้ว — **แล้วของกลุ่มคุณล่ะ**

### A2. ตั้ง 🧪 Tester sub-agent (ผู้ช่วย AI อีกตัวที่มีหน้าที่เฉพาะ) ⏱ ~15 นาที

> 🚫 **คุณไม่ต้องเข้าเมนูตั้งค่าใด ๆ** — พิมพ์สั่งเป็นภาษาไทยให้ Claude สร้างไฟล์ตั้งค่าให้ แล้วเปิดไฟล์นั้นอ่านเอง วิธีนี้ได้ผลเหมือนกันทุกเวอร์ชัน

**ทำ:** วาง prompt ด้านล่าง โดยแก้ 3 จุดที่มีวงเล็บ `< >` ให้เป็นของกลุ่มคุณ

**prompt ที่ใช้ได้ (กรณียกเว้น — ยาวได้ เพราะมี URL บัญชีทดสอบและกติกาที่ห้ามตกข้อ สะกดผิดบรรทัดเดียวล็อกอินไม่ได้ทั้งชุด):**
> ตั้ง sub-agent ชื่อ tester ให้โครงงานของผม ชื่อระบบ `<ชื่อโครงงานของกลุ่มคุณ>`
> หน้าที่: ใช้ Playwright MCP เปิดเบราว์เซอร์จริงแล้วทดสอบแทนคน
> ข้อมูลที่ใช้
> - URL ของระบบ: `<URL จริงของโครงงานกลุ่มคุณ>`
> - บัญชีทดสอบที่ 1: `<อีเมลบัญชีทดสอบที่ 1>`
> - บัญชีทดสอบที่ 2: `<อีเมลบัญชีทดสอบที่ 2 — ต้องเป็นคนละเจ้าของข้อมูลกับบัญชีที่ 1>`
> กติกา
> 1. ทดสอบตาม Acceptance Criteria ในไฟล์ spec ของโครงงานเท่านั้น
> 2. เทสต์หนึ่งตัวทดสอบเรื่องเดียว ตั้งชื่อเป็นภาษาไทย
> 3. รอจนกว่าองค์ประกอบที่ต้องการจะขึ้นจริง ห้ามใช้การรอแบบนับเวลาเฉย ๆ
> 4. ห้ามแก้ไขโค้ดของระบบเพื่อให้เทสต์ผ่านเด็ดขาด
> 5. รายงานผลเป็นภาษาไทย

**จะเห็น:** Claude สร้างไฟล์ตั้งค่าลงในโฟลเดอร์โครงงาน แล้วตอบกลับว่าตั้ง tester เรียบร้อย

**✍️ จังหวะที่ต้องไม่ข้าม — เปิดไฟล์ที่มันสร้างมาอ่าน**

**ทำ:** เปิดไฟล์ตั้งค่า tester ให้เห็นเต็มจอ แล้วไล่อ่านออกเสียง 3 อย่างนี้

| อ่านหาอะไร | ถ้าไม่ตรงต้องทำอย่างไร |
|---|---|
| **URL ของระบบ** สะกดถูกและเปิดได้จริงไหม | พิมพ์บอกให้แก้เป็น URL ที่ถูก |
| **บัญชีทดสอบ** ครบทั้ง 2 บัญชี และเป็นคนละเจ้าของข้อมูลจริงไหม | พิมพ์บอกว่าขาดหรือผิดตรงไหน ให้แก้ |
| มีบรรทัด **"ห้ามแก้ไขโค้ดของระบบเพื่อให้เทสต์ผ่าน"** ไหม | พิมพ์ว่า *"ในไฟล์ตั้งค่ายังไม่มีข้อห้ามนี้ ช่วยเพิ่มให้ด้วย"* |

**📤 ต้องตอบในแชทกลุ่มย่อยก่อนไปต่อ:** *"เปิดไฟล์ตั้งค่า tester อ่านแล้ว — ครบ/ไม่ครบข้อไหน"* คำตอบว่า "ครบแล้ว" เฉย ๆ ไม่นับ ต้องบอกได้ว่าเช็คแต่ละข้อจากบรรทัดไหน

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** ไฟล์ตั้งค่า tester ที่มี URL ของ LeaveEasy บัญชีผู้ขอลากับบัญชีหัวหน้า และบรรทัดห้ามแก้โค้ด — **แล้วของกลุ่มคุณล่ะ**

## ส่วน B — เขียนเทสต์อย่างน้อย 5 ตัวให้ผ่าน ⏱ ~45 นาที

### B1. เทสต์เส้นทางหลักตาม Acceptance Criteria จาก Module 1 ⏱ ~15 นาที

**ทำ:** เปิดไฟล์ spec/Acceptance Criteria ของกลุ่มไว้ข้างจอ แล้ววาง prompt จังหวะที่ 1

**prompt จังหวะที่ 1 — ขอแผนก่อน:**

**✍️ อ่านร่างแล้วเทียบกับไฟล์ spec ทีละบรรทัด (ห้ามข้าม):** *"ร่างนี้ครอบคลุมทุกขั้นของเส้นทางหลักไหม โดยเฉพาะขั้นสุดท้ายที่ตรวจว่าข้อมูลเปลี่ยนจริงในฐานข้อมูล ไม่ใช่หน้าจอเด้งเฉย ๆ"*

**prompt จังหวะที่ 3 และ 4 — แก้แผนแล้วลงมือ:**
> เพิ่มข้อตรวจว่าเปิดรายการอีกครั้งแล้วเห็นข้อมูลที่เปลี่ยนแปลงจริง
> แผนโอเคแล้ว รันได้ ไม่ผ่านตรงไหนบอกว่าเห็นอะไรแทน

**จะเห็น:** เบราว์เซอร์เปิดขึ้นแล้วกรอกฟอร์มเอง กดปุ่มเอง สลับบัญชีทดสอบเอง จบด้วยตารางสรุปผลภาษาไทยว่าผ่านครบทุกขั้นหรือไม่

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** เทสต์เส้นทางหลัก ยื่นใบลา → หัวหน้าอนุมัติ → เปิดดูอีกครั้งแล้วสถานะเป็น "อนุมัติ" จริง — **แล้วเส้นทางหลักของกลุ่มคุณคืออะไร**

### B2. 🟠 เทสต์กรอกไม่ครบ / กรอกผิดรูปแบบ ⏱ ~8 นาที

**prompt จังหวะที่ 1 — ขอแผนก่อน:**
> ให้ tester วางแผนเทสต์ว่ากดบันทึกโดยปล่อยช่องบังคับว่างไว้ แล้วบันทึกไม่ได้
> ร่างให้ผมดูก่อน ยังไม่ต้องรัน

**✍️ อ่านร่างแล้วตรวจ:** ร่างมักตรวจว่า*ไม่บันทึก*อย่างเดียว แต่ไม่ได้ตรวจว่า**มีข้อความเตือนภาษาไทยขึ้นด้วย** — หน้าจอที่เงียบเฉย ๆ ผู้ใช้จะงงว่ากดแล้วเกิดอะไรขึ้น

**prompt จังหวะที่ 3 และ 4 — แก้แผนแล้วลงมือ:**
> เพิ่มข้อตรวจว่าต้องเห็นข้อความเตือนภาษาไทยด้วย
> แผนโอเคแล้ว รันได้

**จะเห็น:** เบราว์เซอร์กดบันทึกทั้งที่ช่องว่าง → รายงานว่าระบบไม่บันทึก และเห็นข้อความเตือนใต้ช่องที่ยังว่าง → ผ่าน

### B3. 🔒 เทสต์ความปลอดภัย — ตัวที่ "เข้าไม่ได้ = ผ่าน" ⭐ ⏱ ~10 นาที

> ⚠️ **เทสต์ตัวนี้กลับหัวกับตัวอื่น** — เราต้องการให้ระบบ**ปฏิเสธ** ถ้าเปิดได้ แปลว่าข้อมูลรั่วจริง และเกณฑ์ปิด Module บังคับให้ทุกกลุ่มมีเทสต์นี้

**prompt จังหวะที่ 1 — ขอแผนก่อน:**
> ให้ tester วางแผนเทสต์ว่าบัญชีทดสอบที่ 1 เปิดข้อมูลของบัญชีทดสอบที่ 2 ไม่ได้
> ร่างให้ผมดูก่อน ยังไม่ต้องรัน

**✍️ อ่านร่างแล้วตอบก่อนไปต่อ:** ตรวจว่าร่างเขียนกำกับชัดไหมว่า **"เทสต์นี้ผ่านเมื่อระบบไม่ยอมให้เข้า"** ไม่งั้นรายงานจะถูกอ่านกลับด้าน

**prompt จังหวะที่ 3 และ 4 — แก้แผนแล้วลงมือ:**
> เทสต์นี้ผ่านเมื่อระบบไม่ยอมให้เข้า และมีข้อความบอกผู้ใช้
> ถ้าเปิดดูได้ ให้รายงานว่าไม่ผ่าน พร้อมบอกว่าเห็นข้อมูลอะไร
> แผนโอเคแล้ว รันได้

**จะเห็น:** เบราว์เซอร์ล็อกอินเป็นบัญชีทดสอบที่ 1 → พยายามเปิดข้อมูลของบัญชีทดสอบที่ 2 → ระบบปฏิเสธ → รายงานว่า **ผ่าน เพราะเข้าไม่ได้**

![screenshot: รายงานผลเทสต์ความปลอดภัยที่ขึ้นว่า "ผ่าน" เพราะเข้าไม่ได้](assets/w9-41-security-test.png)

> 🔧 **ถ้าเป็น LeaveEasy ขั้นนี้จะได้:** ผู้ขอลาคนหนึ่งเปิดใบลาของอีกคนไม่ได้ — **แล้วข้อมูลห้องใครห้องมันของกลุ่มคุณคืออะไร**

### B4. 🤖 เทสต์ปุ่ม AI — เรียกไม่สำเร็จแล้วต้องไม่ค้าง ⏱ ~8 นาที

> ถ้าโครงงานของกลุ่มยังไม่มีปุ่มผู้ช่วย AI ให้ข้ามข้อนี้ แต่ต้องมีเทสต์อย่างน้อย 5 ตัวจากข้ออื่นแทน และเทสต์ความปลอดภัย (B3) ห้ามหาย

**ทำ:** ทำให้เรียก AI ไม่สำเร็จแบบปลอดภัย — เปิดไฟล์เก็บคีย์ แล้ววาง**คีย์ปลอม**ทับชั่วคราว (จดคีย์จริงไว้ก่อน)

**prompt จังหวะที่ 1 — ขอแผนก่อน:**
> ให้ tester วางแผนเทสต์ว่าถ้าเรียก AI ไม่สำเร็จ ระบบต้องไม่ค้าง
> ร่างให้ผมดูก่อน ยังไม่ต้องรัน

**✍️ อ่านร่างแล้วตรวจ:** ร่างมักไม่ได้ตรวจว่า**มีข้อความภาษาไทยบอกผู้ใช้** และ**ปุ่มอื่นยังกดได้** — "ไม่ค้าง" ต้องแปลว่าผู้ใช้ไปต่อได้จริง ไม่ใช่หน้าจอนิ่งเฉย

**prompt จังหวะที่ 3 และ 4 — แก้แผนแล้วลงมือ:**
> เพิ่มข้อตรวจว่าต้องเห็นข้อความภาษาไทย และปุ่มอื่นยังกดได้
> แผนโอเคแล้ว รันได้

**จะเห็น:** เบราว์เซอร์กดปุ่มผู้ช่วย AI → ขึ้นข้อความว่าเรียกไม่สำเร็จเป็นภาษาไทย → เทสต์ลองกดปุ่มอื่นต่อ ยังทำงานได้ → ผ่าน

**ทำต่อ:** ใส่**คีย์จริงกลับ**ทันทีต่อหน้าคู่หูของคุณ อย่าลืมขั้นนี้ ไม่งั้นปุ่ม AI จะพังยาวไปถึงตอนนำเสนอ

### B5. เจอเทสต์ fail จริง — แยกโค้ดผิด หรือเทสต์เขียนผิดก่อนเสมอ ⏱ ~4 นาที (แทรกเมื่อเจอ)

> เช้านี้เห็นผู้สอนเจอเทสต์ fail ต่อหน้าห้องแล้วไล่หาสาเหตุสด — บ่ายนี้กลุ่มคุณจะเจอเองแน่นอน ให้เดินตามลำดับนี้เสมอ **อย่าเพิ่งแก้อะไรทั้งนั้น**

```flow chain
เทสต์ fail | *กดเองแล้วพังไหม | พังจริง = โค้ดผิด | ไม่พัง = เทสต์ผิด
```

1. **อ่านรายงาน** — คาดว่าจะเห็นอะไร และเห็นอะไรจริง
2. **กดเองด้วยมือ 30 วินาที** — คนที่ไม่ได้เป็นคนพิมพ์ในรอบนี้เป็นคนกด
3. **พังเหมือนกัน = โค้ดผิด** ไปแก้โค้ด · **กดเองใช้ได้ปกติ = เทสต์เขียนผิด** ไปแก้เทสต์
4. เปิด spec ของกลุ่มเป็นกรรมการตัดสิน ไม่ใช่ความจำ

> ⚠️ **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่านเด็ดขาด** — เทสต์มีไว้จับปัญหา ไม่ได้มีไว้ให้ผ่าน · แก้ไม่ทันจริง ๆ ให้จดลงบันทึกสิ่งที่ยังไม่เสร็จ อย่าลบเทสต์ทิ้ง

> 🆘 **เทสต์ผ่านบ้างไม่ผ่านบ้างโดยไม่ได้แก้อะไร** → มักเป็นเพราะหน้าเว็บโหลดไม่ทัน สั่งว่า *"ให้เทสต์รอจนกว่าองค์ประกอบที่ต้องการจะขึ้นจริงก่อนกด"* อย่านั่งรันซ้ำหวังให้หาย
