## ส่วน A — 🚀 สั่งทีเดียวจบจากสเปค ⏱ ~45 นาที

> 🧾 **สัปดาห์ที่ 6–8 เราสร้าง LeaveEasy ทีละขั้นมา 3 สัปดาห์** · วันนี้เริ่มจากศูนย์ใหม่ แล้ว**สั่งทีเดียวจบ**จากสเปคใบเดิม เพื่อดูว่าทำได้แค่ไหน และต้องตรวจอะไรบ้าง

### A1 — เริ่มโปรเจกต์ใหม่จากต้นแบบ (10 นาที)

```prompt
ช่วยโหลด repo https://github.com/cnacha-mfu/leaveeasy-start
ลงมาไว้ในโฟลเดอร์ใหม่ชื่อ leaveeasy-oneshot
แล้วสร้าง repo ใหม่ชื่อเดียวกันบน GitHub ของผม พร้อมส่งขึ้นไปให้ด้วย
```

**จะเห็น:** โฟลเดอร์ `leaveeasy-oneshot` ที่มี **prototype กับ `leaveeasy-spec.md`** และ repo ใหม่บน GitHub ที่มี commit ชื่อคุณ

> 📌 **repo ใหม่ใบนี้คือสิ่งที่คุณจะส่งเป็นใบงานที่ 4** — คนละใบกับ repo ที่ทำมา 3 สัปดาห์ ซึ่งยังเก็บไว้เหมือนเดิม

### A2 — ให้ AI เสนอทีมผู้ช่วย แล้วเราตรวจ (10 นาที)

```prompt
อ่าน leaveeasy-spec.md แล้วเสนอว่าควรแบ่งงานให้ผู้ช่วยกี่ตัว
แต่ละตัวทำอะไร และควรใช้โมเดลไหนเพื่อไม่ให้เปลืองโทเคน
ขอดูแผนก่อน อย่าเพิ่งสร้าง
```

⭐ **อ่านแผนที่มันเสนอ แล้วตรวจ 3 ข้อ** — ขาดข้อไหนบอกกลับไปสั้น ๆ

| ต้องมีในแผน | ที่มักไม่ตรง |
|---|---|
| งานครบทั้ง **หน้าจอ · ข้อมูล+ล็อกอิน · ปุ่ม AI** | มักรวบเป็นตัวเดียว |
| **งานทำตามแบบใช้โมเดลเล็ก** งานที่ต้องคิดใช้ตัวใหญ่ | **มักให้ทุกตัวใช้ตัวเดียวกัน** |
| มีข้อกำกับว่า **ห้ามทำงานนอกสเปค** | มักไม่มี |

ครบแล้วสั่ง *"แผนโอเคแล้ว สร้างผู้ช่วยให้เลย"*

**จะเห็น:** ไฟล์ตั้งค่าผู้ช่วยในโฟลเดอร์ `.claude/agents/` และ **บรรทัด `model:` ไม่เหมือนกันทุกตัว**

> 💰 **ทำไมต้องระบุโมเดล** — งานทำตามแบบอย่างการสร้างหน้าจอ ใช้โมเดลเล็ก (`haiku`) ก็จบ · งานที่ต้องคิดเรื่องข้อมูลกับ AI ใช้ตัวใหญ่ขึ้น (`sonnet`) · **บรรทัดเดียวนี้คือค่าใช้จ่ายของคุณทั้งเดือน**

### A3 — สั่งทีเดียวจบ (15 นาที)

```prompt
ให้ผู้ช่วยทุกตัวสร้างระบบตาม leaveeasy-spec.md ให้ครบ
เสร็จแต่ละส่วนให้รายงานผมทีละตัว
```

**จะเห็น:** Claude แบ่งงานให้ผู้ช่วยทีละตัว · รายงานกลับเป็นช่วง ๆ · ไฟล์ในโปรเจกต์เพิ่มขึ้นเรื่อย ๆ

> 🆘 รันเกิน 15 นาทีแล้วยังไม่จบ → **หยุดไว้แค่ส่วนที่เสร็จ** แล้วไปต่อ A4 ด้วยของเท่าที่มี · ส่วนที่ขาดจดไว้ทำในการบ้าน
> 🔑 คีย์ AI ใช้ใบเดิมของหลักสูตร · **ก่อน push ต้องย้ายคีย์ออกจากโค้ดเหมือนสัปดาห์ที่แล้ว** (ทำในส่วน C)

### A4 — ⭐ ตรวจกับสเปคทีละข้อ แล้วสั่งแก้เฉพาะที่ขาด (10 นาที)

เปิด `leaveeasy-spec.md` ไว้ครึ่งจอ เปิดเว็บที่เพิ่งได้อีกครึ่งจอ แล้วไล่ออกเสียง

| ไล่อะไร | ที่มักไม่ตรง |
|---|---|
| หน้าจอครบตามสเปค | มักครบ |
| ชื่อช่องข้อมูลตรงสเปค | **มักสะกดไม่ตรง 1–2 ช่อง** |
| สถานะใช้ได้ 3 ค่าตามสเปค | มักใส่ค่าเกินมา |
| ของที่สเปคบอกว่าไม่ทำใน Module นี้ | **มักแถมมา** |

```prompt
ช่องที่สะกดไม่ตรงสเปคให้แก้ตามสเปค
และเอาส่วนที่สเปคบอกว่าไม่ทำใน Module นี้ออก
ที่เหลือโอเค
```

**จะเห็น:** แก้เฉพาะจุดที่บอก ไม่ได้สร้างใหม่ทั้งชุด · เว็บยังเปิดได้เหมือนเดิม

> ⭐ **สั่งทีเดียวไม่ได้แปลว่าคุณหายไป — งานของคุณย้ายมาอยู่ตอนจบ** ถ้าไม่ตรวจตรงนี้ คุณจะได้ระบบที่อธิบายไม่ได้

→ 🚩 **Checkpoint 1: ระบบขึ้นจากสเปคในรอบเดียว + ผู้ช่วย 3 ตัวมีโมเดลไม่เหมือนกัน + ตรวจกับสเปคแล้ว**
🟢 พิมพ์ผ่านในแชท · 🔁 สลับคนนำจอ

## ส่วน B — 🧪 เทสต์ด้วย Playwright ⏱ ~35 นาที

> ⚠️ **กฎเหล็กของส่วนนี้: ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน**
> เทสต์ fail แปลว่ามีสองอย่างที่เป็นไปได้ — **โค้ดผิด** หรือ **เทสต์เขียนผิด** · แยกให้ออกก่อนแก้เสมอ

### B1 — ตั้ง 🧪 Tester แล้วยืนยันว่าเชื่อมต่อจริง (10 นาที)

พิมพ์ `/mcp` ในหน้าต่าง Claude Code — ต้องเห็น **playwright** ขึ้นว่า **เชื่อมต่อแล้ว**

```prompt
ช่วยสร้าง sub-agent ชื่อ tester ให้ผม ใช้โมเดล sonnet
หน้าที่คือใช้ Playwright MCP เปิดเบราว์เซอร์จริงแล้วทดสอบแทนคน
ทดสอบตาม leaveeasy-spec.md ห้ามแก้โค้ดของระบบเพื่อให้เทสต์ผ่าน
เสร็จแล้วให้ผมอ่านไฟล์ก่อน
```

⭐ **เปิดไฟล์อ่าน** — ต้องมี URL ของระบบคุณ · บัญชีทดสอบ · และบรรทัด **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน**

```prompt
ช่วยเปิดเบราว์เซอร์ไปที่ <URL ของคุณ> แล้วบอกผมว่าเห็นอะไรบนหน้าจอ
```

**จะเห็น:** หน้าต่างเบราว์เซอร์เปิดขึ้นมาเองโดยคุณไม่ได้กด · Claude เล่าว่าเห็นอะไรบนหน้าเว็บของคุณ

> 🆘 `/mcp` ไม่ขึ้น playwright → ปิด Claude Code เปิดใหม่ · ยังไม่ขึ้นให้โพสต์คิวถามกลางทันที **อย่ารอ**

### B2 — เทสต์เส้นทางหลัก 2 ตัว (10 นาที)

```prompt จังหวะที่ 1 — ขอแผนก่อน
ผมอยากได้เทสต์ 2 ตัว — ยื่นใบลาแล้วเห็นในรายการ · กดอนุมัติแล้วสถานะเปลี่ยน
ให้ tester เสนอมาก่อนว่าจะทดสอบแต่ละตัวกี่ขั้น อย่าเพิ่งเขียน
```

⭐ **อ่านแผนแล้วตอบให้ได้ว่าอะไรขาด** — มีขั้น "รีเฟรชแล้วยังอยู่" หรือยัง? ขาดให้บอกเพิ่ม

```prompt จังหวะที่ 4 — สั่งลงมือ
แผนโอเคแล้ว เขียนแล้วรันให้ผม รายงานผลเป็นข้อ ๆ
```

**จะเห็น:** รายงานว่าตัวไหนผ่าน ตัวไหนไม่ผ่าน พร้อมบอกว่าไปติดตรงขั้นไหน

### B3 — เทสต์กรอกไม่ครบ 1 ตัว (5 นาที)

```prompt
เพิ่มเทสต์ กรอกฟอร์มยื่นใบลาโดยเว้นช่องหัวข้อไว้ แล้วกดบันทึก
ระบบต้องไม่บันทึกและต้องขึ้นข้อความบอก
```

**จะเห็น:** เทสต์ผ่านเมื่อระบบปฏิเสธการบันทึกจริง

### B4 — 🔒 เทสต์ความปลอดภัย 2 ตัว ⭐ (10 นาที)

> **ตัวนี้สำคัญที่สุดของสัปดาห์** — เป็นเทสต์ที่ **"เข้าไม่ได้ = ผ่าน"**
> ⚠️ prompt นี้ยาว 4 บรรทัดโดยตั้งใจ เพราะเป็น**รายการเงื่อนไขที่ห้ามตกข้อ** ตกข้อเดียวแปลว่าไม่ได้ทดสอบเรื่องนั้น

```prompt
เพิ่มเทสต์ความปลอดภัย 2 ตัว
1 ไม่ล็อกอินแล้วเปิดหน้ารายการ ต้องอ่านข้อมูลไม่ได้
2 ล็อกอินด้วยบัญชีที่สอง แล้วเปิดใบลาของบัญชีแรก ต้องเปิดไม่ได้
ทั้งสองตัวถือว่าผ่านเมื่อเข้าไม่ได้
```

**จะเห็น:** เทสต์ทั้งสองผ่าน · ถ้าตัวใดตัวหนึ่ง **ไม่ผ่าน แปลว่าข้อมูลของคุณรั่วจริง** ให้กลับไปแก้ก่อนทำอย่างอื่น

รวมแล้วได้เทสต์ **5 ตัว** — เส้นทางหลัก 2 · กรอกไม่ครบ 1 · ความปลอดภัย 2 · จากนั้นสั่ง *"ปักหมุดเก็บชุดทดสอบให้ผม"*

> 🆘 **เจอเทสต์ fail จริง** → ถามตัวเองก่อนว่า *ระบบทำงานผิด* หรือ *เทสต์เขียนคาดหวังผิด* · สั่ง Claude ว่า *"ช่วยบอกว่าตัวนี้ fail เพราะโค้ดผิดหรือเทสต์ผิด อธิบายให้ฟังก่อน อย่าเพิ่งแก้"*

→ 🚩 **Checkpoint 2: ⭐ เทสต์ 5 ตัวผ่านทั้งหมด รวมเทสต์ความปลอดภัย**
🟢 พิมพ์ผ่านในแชท · 🔁 สลับคนนำจอ

## ส่วน C — 📊 รายงานผล + ส่งงาน ⏱ ~15 นาที

### C1 — ให้ AI สรุปผลการทดสอบเป็นรายงาน (8 นาที)

```prompt
ช่วยรันเทสต์ทั้งหมดอีกรอบ แล้วสรุปผลเป็นไฟล์ test-results.md ให้ผม
บอกว่าเทสต์แต่ละตัวทดสอบอะไร ผ่านหรือไม่ผ่าน และรันเมื่อไร
ข้อที่ไม่ผ่านให้บอกด้วยว่าติดตรงไหน
```

**จะเห็น:** ไฟล์ `test-results.md` ที่โฟลเดอร์บนสุด มีรายชื่อเทสต์ 5 ตัว พร้อมผ่าน/ไม่ผ่าน และวันเวลาที่รัน

⭐ **เปิดอ่านจริง ๆ แล้วตอบให้ได้ว่า** เทสต์ความปลอดภัย 2 ตัวอยู่บรรทัดไหน และผ่านหรือไม่ · ขาดข้อไหนสั่งเติม
🚫 **ห้ามแก้รายงานให้สวยกว่าผลจริง** — ข้อที่ไม่ผ่านให้จดลง `BACKLOG.md` แทน

### C2 — 🔴 กันคีย์หลุด แล้วส่งงาน (7 นาที · ห้ามข้าม)

```prompt
ผมกำลังจะส่งงานขึ้น GitHub
ช่วยย้ายคีย์ AI ออกจากโค้ด ไปไว้ในไฟล์แยกที่ .gitignore กันไว้
แล้วเขียน URL เว็บออนไลน์กับลิงก์ไปที่ test-results.md ไว้บนสุดของ README.md
จากนั้นแสดงรายการไฟล์ที่กำลังจะส่งขึ้น GitHub ให้ผมดู
```
