## 🔁 วิธีสั่งงาน AI ที่ใช้ทั้งวันนี้ — วงจร 4 จังหวะเดิมจากสัปดาห์ที่แล้ว

```
1️⃣ สั่งสั้น 1–3 บรรทัด  →  2️⃣ AI ร่างแผน/ไฟล์  →  3️⃣ เราอ่านและบอกว่าอะไรขาด  →  4️⃣ สั่งลงมือทีละข้อ
```

- **prompt เกือบทั้งหมดในเอกสารนี้สั้น 1–3 บรรทัด** เหมือนสัปดาห์ที่แล้ว
- 📄 **หลักการเดียวกันนี้ใช้กับไฟล์ด้วย** — ผู้เรียนไม่ต้องนั่งพิมพ์ `CLAUDE.md` หรือ `.gitignore` เอง **ให้ AI ร่าง แล้วเราอ่านและแก้ต่อหน้าห้อง** สิ่งที่ต้องสอนคือ *"อ่านแล้วรู้ว่าอะไรขาด"* ไม่ใช่ *"พิมพ์ได้ครบ"*
- ⚠️ **ทุกครั้งที่ AI ร่างอะไรมา ผู้สอนต้องอ่านออกเสียงและชี้ว่าอะไรขาดให้ผู้เรียนเห็น** ห้ามสั่งแล้วผ่านไปเฉย ๆ

> ⚠️ **บรรทัดที่ต้องพูดออกเสียงอย่างน้อย 1 ครั้งในคาบนี้:** "คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชัน ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ"
> 🔧 **เตรียมตัวก่อนคาบ:** พิมพ์ `/init` ในโฟลเดอร์ซ้อมของตัวเอง 1 รอบ **ให้เห็นกับตาว่าเวอร์ชันของคุณร่างออกมาหน้าตาแบบไหน และขาดหัวข้ออะไรบ้าง** จะได้ชี้ได้ทันทีตอนสอนจริง

### ⚠️ วันนี้มี prompt ยาวกว่าปกติ 2 อัน — และมีเหตุผล

### ขั้นที่ 1 — ร่าง CLAUDE.md ของ FixIt ด้วย `/init` แล้วตรวจเอง ⏱ 5 นาที

**พูดว่า:** "สัปดาห์ที่แล้วผมต้องพิมพ์อธิบาย FixIt ให้ Claude ฟังใหม่ทุกครั้งที่เปิดบทสนทนา วันนี้ผมจะเขียนไว้ครั้งเดียวจบ แล้วไม่ต้องพิมพ์อีกเลยทั้งเดือน"

**ทำ:**
1. เปิด terminal ที่โฟลเดอร์ FixIt → เปิด Claude Code
2. **พิมพ์คำสั่ง `/init` ให้ผู้เรียนเห็นชัด ๆ ก่อนกด Enter** — อย่ารีบกด

> 📄 **หลักการสำคัญของขั้นนี้: ผู้เรียนไม่ต้องนั่งพิมพ์ไฟล์นี้เอง** — ใช้คำสั่งสำเร็จให้ AI ร่างให้ แล้วเราอ่านและแก้ · **สิ่งที่ต้องสาธิตให้เห็นคือจังหวะที่เราอ่านแล้วบอกว่าอะไรขาด** ไม่ใช่จังหวะที่ไฟล์เกิดขึ้น

**จังหวะที่ 1 และ 2 — ใช้คำสั่ง `/init` แทน**

```
/init
```

**พูดว่า:** "ผมจะไม่พิมพ์อธิบายโครงงานให้มันฟังนะครับ Claude Code มีคำสั่งสำเร็จอยู่แล้ว พิมพ์ `/init` คำสั่งเดียว มันจะไล่อ่านไฟล์ในโปรเจกต์ แล้วร่างคู่มือมาให้เราดูก่อน"

**ผู้เรียนจะเห็น:** Claude ไล่อ่านไฟล์ในโปรเจกต์ประมาณ 5–10 ไฟล์ (ชื่อไฟล์ไหลขึ้นบนจอ) แล้ว **แสดงร่าง CLAUDE.md ออกมาบนจอ พร้อมถามว่าจะบันทึกไหม** — ยังไม่มีไฟล์ถูกสร้างจนกว่าเราจะตอบ

> ⭐ **หยุดตรงจุดที่มันถามว่าจะบันทึกไหม 10 วินาที** แล้วพูดว่า "เห็นไหมครับว่ามันถามก่อน ไม่ได้เขียนทับอะไรของผมเอง — **ถ้าเครื่องใครมี CLAUDE.md อยู่แล้ว มันจะไม่ทับให้ แต่จะเสนอมาว่าควรเพิ่มส่วนไหน**"
>
> ⚠️ **สิ่งที่ต้องพูดให้ครบ ห้ามข้าม:** "`/init` ทำแทนเราได้สองจังหวะแรกเท่านั้น คือสั่งสั้นกับให้ AI ร่าง · **จังหวะที่สาม ที่เราอ่านแล้วบอกว่าอะไรขาด ยังเป็นงานของเราเหมือนเดิม** ผมกำลังจะทำให้ดูเดี๋ยวนี้"
>
> ⚠️ **ถ้าพิมพ์ `/init` แล้วไม่ได้ผล หรือไม่มีคำสั่งนี้ในเวอร์ชันของเครื่องผู้สอน:** อย่าไล่แก้สด · พูดว่า **"คำสั่งของ Claude Code เปลี่ยนได้ตามเวอร์ชันนะครับ ถ้าพิมพ์แล้วไม่ได้ผล ให้พิมพ์ `/help` ดูรายการที่ใช้ได้จริงในเครื่องคุณ"** แล้วสั่งด้วยประโยคธรรมดาแทนทันที ผลลัพธ์เท่ากัน
>
> **prompt สำรอง (ใช้แทน `/init` ได้เลย):**
> > อ่านไฟล์ในโปรเจกต์นี้ แล้วร่าง CLAUDE.md คู่มือประจำโครงงานให้ผมดูก่อน
> > เขียนภาษาไทย ยาวไม่เกิน 1 หน้า อย่าเพิ่งบันทึกไฟล์

#### 📖 จังหวะที่ 3 — อ่านออกเสียงแล้วชี้ว่าอะไรขาด ⭐ (จังหวะที่ห้ามข้าม)

**พูดว่า:** "ตรงนี้คือจังหวะของคุณครับ ผมจะอ่านให้ฟังทีละหัวข้อ แล้วบอกว่าอะไรที่ยังไม่ตรงกับโครงงานของผม"

อ่านร่างออกเสียงทีละหัวข้อ แล้ว**ชี้ให้เห็นอย่างน้อย 2 จุดที่ต้องแก้** — ร่างจาก `/init` มักขาดข้อเหล่านี้เสมอ

> ⚠️ **สิ่งที่ต้องพูดตรงนี้ให้ชัด — นี่คือหัวใจของขั้นนี้:** "โปรเจกต์ของเรามีไฟล์ HTML ไม่กี่ไฟล์ **ร่างที่ได้จะบางมาก** และนั่นเป็นเรื่องปกติ เพราะมันเขียนได้เท่าที่มันเห็นในโปรเจกต์ · **ร่างนี้คือจุดเริ่มต้น ไม่ใช่ของเสร็จ** โครงสร้างข้อมูลกับข้อตกลงของโครงงาน เรายังต้องเติมเองอยู่ดี"

| สิ่งที่ต้องมี | ร่างจาก `/init` มักเป็นอย่างไร |
|---|---|
| หัวข้อ **โครงสร้างข้อมูลบน Firestore** | ไม่มีเลย เพราะโปรเจกต์ยังไม่มีฐานข้อมูล — **เราต้องขอให้เพิ่มหัวข้อนี้แล้วเว้นว่างไว้** |
| หัวข้อ **สิ่งที่ห้ามทำ** | มักไม่มี หรือมีแต่กว้างเกินไป |
| **ข้อตกลงของโครงงาน** เช่น ข้อความบนหน้าจอเป็นภาษาไทย | มักไม่มี เพราะมันเดาความตั้งใจของเราไม่ได้ |
| ภาษาและความยาว | มักเป็นภาษาอังกฤษ และอาจยาวเกิน 1 หน้า หรือมีโค้ดปนมา |

**prompt ที่ใช้ (จังหวะที่ 3 — บอกไปเฉพาะที่ขาด):**

> ขอเพิ่มหัวข้อ "โครงสร้างข้อมูลบน Firestore" แล้วเว้นว่างไว้ก่อน เดี๋ยวผมเติมเอง
> ขอเพิ่มหัวข้อ "ข้อตกลงของโครงงาน" กับ "สิ่งที่ห้ามทำ" · เขียนเป็นภาษาไทย ไม่เกิน 1 หน้า และอย่าใส่โค้ดลงในไฟล์นี้
> ที่เหลือโอเค

**prompt ที่ใช้ (จังหวะที่ 4):**

> โอเคแล้ว บันทึกเป็น CLAUDE.md ที่โฟลเดอร์บนสุดได้เลย

**ผู้เรียนจะเห็น:** ไฟล์ `CLAUDE.md` โผล่ในรายชื่อไฟล์ · เปิดในโปรแกรมแก้ข้อความจะเห็นหัวข้อภาษาไทย 4 หัวข้อ และหัวข้อที่ 2 ยังว่างอยู่

**ชี้ให้ดูตรงนี้:**
- ชี้ว่าไฟล์อยู่ที่ **โฟลเดอร์บนสุด** ไม่ใช่ในโฟลเดอร์ย่อย — ถ้าวางผิดที่ Claude จะไม่อ่าน
- ชี้หัวข้อที่ 2 ที่ยังว่าง แล้วพูดว่า **"ช่องนี้คือของที่เราจะไปออกแบบกันในช่วงที่ 2 แล้วกลับมาเติม"**

### ขั้นที่ 3 — ⭐ แปลง ERD ของ FixIt เป็นโฟลเดอร์/ไฟล์ สดบนกระดาน ⏱ 12 นาที

> 🔑 **นี่คือ 12 นาทีที่สำคัญที่สุดของคาบเช้า** — ถ้าเวลาไม่พอ ให้ไปตัดขั้นที่ 9 (deploy) แทน **ห้ามตัดขั้นนี้**
> 🖐️ **ขั้นนี้ไม่ใช้คอมพิวเตอร์เลย** ใช้กระดานร่วมอย่างเดียว เพราะต้องการให้ผู้เรียนคิดตาม ไม่ใช่ดูโค้ดไหล

**พูดว่า:** "ผมจะไม่เปิดโค้ดเลยใน 12 นาทีนี้ เราจะแปลงของที่คุณออกแบบไว้เดือนที่ 1 ด้วยกัน ทีละตาราง และผมจะถามคุณทุกตาราง"

**ทำ — ห้ามเตรียมคำตอบไว้ล่วงหน้าบนกระดาน ต้องเขียนสดทีละบรรทัด:**

1. **เขียน ERD ของ FixIt ลงกระดานฝั่งซ้าย** (มีอยู่แล้วในภาพนิ่ง เอามาวางได้)
   ```
   users ──1:N──► tickets ◄──N:1── categories
                     │
                   1:N
                     ▼
                 comments
   ```
2. **เขียนกติกา 4 ข้อไว้กลางกระดาน** — ตาราง→โฟลเดอร์ · แถว→ไฟล์ · คอลัมน์→ข้อมูลในไฟล์ · FK→เก็บ ID + จดชื่อซ้ำ · ตารางลูก→โฟลเดอร์ย่อย
3. **ตารางที่ 1 — `users`** ถามห้องก่อน: *"ตาราง users กลายเป็นอะไรครับ"* รอคำตอบจริง แล้วค่อยเขียน
   ```
   📁 users/   📄 u001 { name, email, role }
   ```
4. **ตารางที่ 2 — `categories`** ถามอีกครั้ง แล้วเขียน
   ```
   📁 categories/   📄 c001 { name }
   ```
5. **ตารางที่ 3 — `tickets`** เขียนเฉพาะคอลัมน์ธรรมดาก่อน **ยังไม่ใส่ FK**
   ```
   📁 tickets/   📄 t001 { title, detail, status, createdAt }
   ```
6. **หยุดตรงนี้แล้วถามคำถามสำคัญที่สุดของคาบ:** *"แล้วช่อง 'ผู้แจ้ง' ที่ชี้ไปตาราง users จะทำยังไงครับ"*
   - รอให้มีคนตอบว่า "เก็บ id" — **ชมแล้วเขียนลงไป** `reporterId: "u001"`
   - แล้วถามต่อ: *"ทีนี้หน้าจอรายการใบแจ้งซ่อม ผมอยากโชว์ชื่อคนแจ้ง ผมมีแต่ u001 ผมต้องทำยังไง"*
   - รอให้ห้องนึกออกว่า "ต้องไปเปิดโฟลเดอร์ users หา" → **พูดว่า "ถูกต้องครับ และนั่นคือสิ่งที่ Firestore ทำให้อัตโนมัติไม่ได้ เพราะไม่มี JOIN"**
   - **แล้วค่อยเขียนบรรทัดนี้ลงไปช้า ๆ** `reporterName: "สมชาย"`
7. เติมคู่ที่เหลือให้ครบ พูดพร้อมเขียน
   ```
   assigneeId / assigneeName        ← ช่างที่รับผิดชอบ
   categoryId / categoryName        ← หมวดหมู่
   ```
   **ชี้ว่า `reporterId` กับ `assigneeId` ชี้ไปโฟลเดอร์ `users` เดียวกันทั้งคู่** — บอกว่า "จุดนี้คือจุดที่มือใหม่พลาดบ่อยที่สุด"
8. **ตารางที่ 4 — `comments`** ถาม: *"ตารางลูกกลายเป็นอะไร"* → เขียนโฟลเดอร์ย่อยเข้าไปในไฟล์ `t001`
   ```
   📁 tickets/  📄 t001 { ... }
                   📁 comments/   📄 cm001 { authorId, authorName, message, createdAt }
   ```
9. **ปิดด้วยการอ่าน path เต็มพร้อมกันทั้งห้อง:** `tickets/t001/comments/cm001`
10. **คัดลอกผลลัพธ์ทั้งก้อนไปวางใน `CLAUDE.md` หัวข้อที่ 2 ทันทีต่อหน้าผู้เรียน** แล้ว commit

> ⚠️ **prompt อันถัดไปยาวกว่าปกติ และตั้งใจให้ยาว** — เพราะเนื้อหาของมันคือ **รายการชื่อ field ที่ห้ามสะกดผิด** Firestore แยกตัวพิมพ์เล็ก-ใหญ่ สะกดผิดจะพังแบบเงียบ ๆ ไม่มี error ให้เห็น
> 📢 **พูดข้อนี้ออกเสียงให้ผู้เรียนรู้ตัว:** "อันนี้ยาวกว่าปกตินะครับ เพราะเนื้อหาของมันคือรายการชื่อข้อมูลที่ห้ามสะกดผิด · **งานอื่นทั้งวันนี้เรากลับไปสั่งสั้น 1 ถึง 3 บรรทัดเหมือนเดิม**"

**prompt ที่ใช้ (ตอนเติมลง CLAUDE.md · ⚠️ ยาวได้ เพราะเนื้อหาคือรายการชื่อ field):**
> เติมหัวข้อ "โครงสร้างข้อมูลบน Firestore" ใน CLAUDE.md ด้วยโครงสร้างนี้ตามที่ผมวางให้ ห้ามแก้ชื่อ field ห้ามเพิ่ม field ใหม่ และให้เขียนกำกับไว้ด้วยว่าฟิลด์ที่ลงท้ายด้วย Name เป็นการจดชื่อซ้ำ (denormalize) ไว้เพื่อไม่ต้องไปเปิดโฟลเดอร์ users ทุกครั้ง

**ผู้เรียนจะเห็น:** กระดานที่มี ERD อยู่ซ้าย และโครงสร้างโฟลเดอร์/ไฟล์อยู่ขวา วางเทียบกันได้ทีละบรรทัด · จากนั้นเห็น `CLAUDE.md` ที่หัวข้อที่ 2 มีเนื้อหาแล้ว

**ชี้ให้ดูตรงนี้:**
- **ลากนิ้วเทียบซ้าย-ขวาทีละตาราง** "users ตรงนี้ กลายเป็น users ตรงนี้"
- ชี้คู่ `Id` / `Name` ทุกคู่ แล้วพูดว่า "ทุกคู่นี้คือราคาที่เราจ่ายเพื่อความเร็ว และเราจ่ายเต็มใจ"
- ชี้ว่า **โครงสร้างนี้ไปอยู่ใน CLAUDE.md แล้ว** ดังนั้นทุกคำสั่งต่อจากนี้ Claude จะสะกดชื่อ field ตรงกันหมด

**เชื่อมกับ LeaveEasy:** "ตรงนี้ของ FixIt คือ `tickets` มี `reporterId` กับ `reporterName` ตอนบ่ายคุณจะแปลง ERD ของ LeaveEasy เอง โฟลเดอร์หลักชื่อ `leaveRequests` และมี `requesterId` กับ `requesterName` — ขั้นตอนเดียวกัน ชื่อคนละชื่อ"

**ชี้ให้ดูตรงนี้:**

- ชี้คู่ `reporterId` / `reporterName` แล้วพูดว่า "จำการจดชื่อซ้ำเมื่อกี้ได้ไหมครับ นี่คือหน้าตาจริงของมัน"
- **สอนวิธีเปิด Console นี้ให้ครบทุกคลิก** ตั้งแต่หน้าแรกของ Firebase — เพราะครึ่งห้องจะหาไม่เจอตอนบ่าย

**เชื่อมกับ LeaveEasy:** "ตอนบ่ายคุณจะเห็นภาพนี้กับข้อมูลของตัวเอง โฟลเดอร์ `leaveRequests` มีใบลา 5 ไฟล์ — **ภาพนั้นคือ Checkpoint 2 ที่คุณต้องถ่ายส่ง**"

### ขั้นที่ 6 — CRUD ทีละตัว ทดสอบทีละตัว ⏱ 10 นาที

**พูดว่า:** "ผมจะทำทีละตัว แล้วเปิด Console ยืนยันทุกตัว ถ้าทำทั้งสี่ตัวรวดเดียวแล้วพัง เราจะไม่รู้เลยว่าพังที่ตัวไหน"

> ⚠️ **จุดที่ตั้งใจให้พังอยู่ระหว่างตัวที่ 2 กับตัวที่ 3 — อ่านหัวข้อ 💥 ด้านล่างก่อนเริ่มขั้นนี้**

#### 6.1 อ่าน — แสดงรายการใบแจ้งซ่อม ⏱ 3 นาที

**prompt ที่ใช้:**
> ให้หน้าจอรายการใบแจ้งซ่อมอ่านข้อมูลจริงจาก Firestore แทนข้อมูลปลอมในโค้ด
> ใช้ชื่อ field ตามที่เขียนไว้ใน CLAUDE.md และอ่านจาก field ที่จดชื่อซ้ำไว้แล้ว
> ทำหน้านี้หน้าเดียว หน้าอื่นยังไม่ต้องแตะ

**ผู้เรียนจะเห็น:** หน้าเว็บ FixIt แสดงรายการ **5 แถว** ชื่อคนแจ้งขึ้นเป็นภาษาไทย ไม่ใช่รหัส `u001`
**ชี้ให้ดูตรงนี้:** "ชื่อสมชายขึ้นได้เพราะเราจดซ้ำไว้ ถ้าเราเก็บแต่ ID ตรงนี้จะขึ้นเป็น u001" · แล้ว `git commit -m "อ่านรายการใบแจ้งซ่อมจาก Firestore"`

#### 6.2 เขียน — แจ้งซ่อมใบใหม่ ⏱ 3 นาที

**prompt ที่ใช้:**
> ให้ปุ่มบันทึกในหน้าแจ้งซ่อมใหม่ เขียนไฟล์ลง Firestore จริง
> บันทึกครบทุก field ตามโครงสร้างใน CLAUDE.md สถานะเริ่มต้นคือ แจ้งใหม่
> บันทึกไม่สำเร็จให้ขึ้นข้อความภาษาไทยบอกผู้ใช้ ห้ามเงียบ

**ผู้เรียนจะเห็น:** กรอกฟอร์ม → กดบันทึก → กลับมาหน้ารายการที่มี **6 แถว** · ใน Firebase Console กดรีเฟรชแล้วเห็นไฟล์ที่ 6 โผล่ขึ้นมา
**ชี้ให้ดูตรงนี้:** **เปิด Console เทียบกันคนละครึ่งจอ** พูดว่า "ตรงนี้แหละคือช่วงเวลาที่ข้อมูลออกจากเครื่องคุณไปอยู่บนคลาวด์จริง ๆ" · commit

> 💥 **หยุดตรงนี้ — ไปทำหัวข้อ 💥 จุดที่ตั้งใจให้พัง ก่อนทำ 6.3**

#### 6.3 แก้ — เปลี่ยนสถานะเป็นกำลังซ่อม ⏱ 2 นาที

**prompt ที่ใช้:**

> สถานะเรียงตามนี้ แจ้งใหม่ รับเรื่องแล้ว กำลังซ่อม เสร็จสิ้น
> แก้เฉพาะ field status เท่านั้น ห้ามเขียนทับ field อื่น

**ผู้เรียนจะเห็น:** กดปุ่ม → สถานะบนหน้าจอเปลี่ยน · **ใน Console ค่า `status` ของไฟล์นั้นเปลี่ยนตาม**
**ชี้ให้ดูตรงนี้:** ชี้คำว่า "แก้เฉพาะ field status" ใน prompt แล้วบอกว่า "ประโยคนี้กันไม่ให้ AI เขียนทับข้อมูลอื่นทิ้ง เป็นนิสัยที่ควรติดตัว" · commit

#### 6.4 ลบ — ยกเลิกใบแจ้งซ่อม ⏱ 2 นาที

**prompt ที่ใช้:**
> เพิ่มปุ่มลบใบแจ้งซ่อมในหน้ารายละเอียด ลบไฟล์นั้นออกจาก Firestore จริง

**ชี้ให้ดูตรงนี้:** "ลบแล้วคือลบจริง ไม่มีถังขยะให้กู้ นี่คือเหตุผลที่ต้องมีกล่องถามยืนยัน" · commit

**เชื่อมกับ LeaveEasy:** "สี่ตัวนี้ของ FixIt คือ อ่านรายการใบแจ้งซ่อม แจ้งซ่อมใหม่ เปลี่ยนสถานะ และยกเลิก ตอนบ่ายของคุณคือ อ่านรายการใบลา ยื่นใบลาใหม่ อนุมัติหรือปฏิเสธ และยกเลิกใบลา — สี่ตัวเหมือนกัน คนละคำ"

## 💥 จุดที่ตั้งใจให้พัง (Planned Failure) ⏱ 6 นาที

> **แทรกหลังข้อ 6.2 (เขียน) และก่อนข้อ 6.3 (แก้)**

**ทำไมต้องมี:** เพราะ **permission denied คือปัญหาอันดับ 1 ของสัปดาห์นี้** ครึ่งห้องจะเจอในคาบบ่าย ถ้าผู้เรียนเคยเห็นผู้สอนเจอและแก้ให้ดูแล้ว เขาจะไม่ตกใจและไม่คิดว่าตัวเองทำผิด

### 💥 จุดพังหลัก — permission denied

**ทำให้พังอย่างไร (เลือก 1 วิธี):**
- **วิธีที่แนะนำ (คุมได้แน่นอน):** สลับไป Firebase Console → Firestore → แท็บ **Rules** → แก้กฎให้ปฏิเสธทุกอย่าง → กด **Publish** → กลับมาที่หน้าเว็บแล้วกดบันทึกใบแจ้งซ่อมใหม่
- **วิธีสำรอง:** ถ้าไม่อยากแตะ Rules ให้แก้ชื่อโฟลเดอร์ในโค้ดจาก `tickets` เป็น `Tickets` ตัวใหญ่ แล้วบันทึก — จะได้อาการ "ไม่มี error แต่ข้อมูลไม่มา" ซึ่งสอนเรื่องตัวพิมพ์เล็ก-ใหญ่ได้ด้วย

**พูดตอนพัง:** "เห็นไหมครับ ผมเองก็เจอ — และผมเจอแบบนี้ทุกครั้งที่ทำโปรเจกต์ใหม่ มาดูกันว่าจะไล่ยังไง"

**วิธีกู้ทีละขั้น — ทำช้า ๆ ให้ผู้เรียนจดตาม:**

| ขั้น | ทำอะไร | จะเห็นอะไร |
|:--:|---|---|
| 1 | **เปิดหน้าต่างข้อความของเบราว์เซอร์** (กด F12 → แท็บ Console) | ข้อความสีแดง มีคำว่า `Missing or insufficient permissions` |
| 2 | อ่านออกเสียงว่า "ไม่มีสิทธิ์" — **แปลว่าโค้ดไม่ผิด แต่ยามไม่ให้ผ่าน** | — |
| 3 | เปิด Firebase Console → Firestore → แท็บ **Rules** | เห็นกฎปัจจุบันและ **วันหมดอายุของโหมดทดสอบ** |
| 4 | แก้วันหมดอายุให้ยืดออกไป → กด **Publish** | ขึ้นข้อความยืนยันว่าเผยแพร่กฎแล้ว รอ 10–30 วินาที |
| 5 | กลับมารีเฟรชหน้าเว็บ แล้วกดบันทึกใหม่ | บันทึกสำเร็จ ไฟล์ใหม่โผล่ใน Console |

**พูดตอนกู้เสร็จ:** "สังเกตนะครับว่าผมไม่ได้แก้โค้ดเลยสักบรรทัด ปัญหาไม่ได้อยู่ที่โค้ดคุณ อยู่ที่ยามหน้าประตู — และนี่คือสาเหตุที่ผมให้จดวันหมดอายุไว้ตั้งแต่ขั้นที่ 4"

### 💥 จุดพังเสริม — ชื่อคนไม่ขึ้น (ทำเมื่อเวลาเหลือ ⏱ 2 นาที)

**ทำให้พังอย่างไร:** แก้หน้าจอรายการให้แสดง `reporterId` แทน `reporterName` ชั่วคราว
**ผู้เรียนจะเห็น:** ตารางที่คอลัมน์ชื่อผู้แจ้งขึ้นเป็น `u001` `u002` เต็มไปหมด
**พูดว่า:** "หน้าตาแบบนี้คืออาการของคนที่เก็บแต่ ID ไม่ได้จดชื่อซ้ำไว้ ถ้าตอนบ่ายคุณเห็นหน้าจอแบบนี้ ให้กลับไปที่คำว่า 'ไม่มี JOIN' ที่เราเรียนตอนเช้า"

> โฟลเดอร์ไหนยังว่าง ให้ขึ้นข้อความภาษาไทยว่ายังไม่มีรายการ ห้ามปล่อยหน้าว่างเปล่า
> ทำทีละหน้า แล้วบอกผมว่าแก้ไฟล์ไหนไปบ้าง

**ผู้เรียนจะเห็น:** หลังเปิดเบราว์เซอร์ใหม่ **ใบแจ้งซ่อม "ทดสอบตอน 11 โมง" ยังอยู่ในรายการ**

**ชี้ให้ดูตรงนี้:**
- **หยุด แล้วปล่อยให้ภาพนี้ค้างบนจอ 5 วินาที** พูดว่า "นี่คือเส้นแบ่งระหว่างของเล่นกับของจริงครับ"
- ให้ห้องพิมพ์ 🎉 ในแชท
- ย้ำ: "ตอนบ่ายนี่คือ Checkpoint 3 ของคุณ และเป็นข้อที่สำคัญที่สุดของทั้งเดือน"

**เชื่อมกับ LeaveEasy:** "ยื่นใบลา → ปิดเบราว์เซอร์ → เปิดใหม่ → ใบลายังอยู่ ถ้าบ่ายนี้คุณทำได้ถึงตรงนี้ คุณผ่านสัปดาห์นี้แล้ว"

### ขั้นที่ 9 — Deploy ขึ้น Firebase Hosting ⏱ 6 นาที

> ⏱ **ขั้นนี้ตัดได้ถ้าเวลาไม่พอ** — ให้ฉายภาพนิ่งของผลลัพธ์แทน แล้วบอกว่าใบงานมีขั้นตอนครบทุกบรรทัด

**พูดว่า:** "ตอนนี้ระบบทำงานได้จริงแล้ว แต่ยังอยู่ในเครื่องผมคนเดียว ผมจะพามันขึ้นอินเทอร์เน็ตให้คุณเปิดจากมือถือตัวเองได้"

**ทำ:**
1. สั่ง Claude ตาม prompt ให้บอกคำสั่งก่อน **แต่ยังไม่ให้รันเอง**
2. พิมพ์คำสั่งใน terminal ทีละบรรทัดต่อหน้าห้อง อ่านออกเสียงว่าแต่ละบรรทัดทำอะไร
3. รอผล 1–2 นาที **ระหว่างรอ ให้ทวนตารางเทียบ FixIt ↔ LeaveEasy ไปพลาง อย่าปล่อยเงียบ**
4. คัดลอก URL → **เปิดบนโทรศัพท์ของตัวเองแล้วยกให้กล้องเห็น** หรือวางลงแชทให้ผู้เรียนกดเปิดพร้อมกัน

**prompt ที่ใช้:**
> ผมอยากนำโปรเจกต์นี้ขึ้น Firebase Hosting
> เขียนแผนเป็นภาษาไทยว่าผมต้องพิมพ์คำสั่งอะไรบ้าง แต่ละคำสั่งจะถามอะไร ผมควรตอบว่าอะไร
> ยังไม่ต้องรันเอง ผมจะพิมพ์เอง

**📖 จังหวะที่ 3 — อ่านแผนแล้วชี้ว่าอะไรขาด** ร่างแรกมักไม่บอกชื่อโฟลเดอร์ผลลัพธ์ ซึ่งเป็นสิ่งที่ระบบจะถาม

**prompt ที่ใช้ (จังหวะที่ 3):**
> ขอชื่อโฟลเดอร์ผลลัพธ์ของโปรเจกต์นี้ด้วย เพราะตอนตั้งค่าต้องกรอก

**ผู้เรียนจะเห็น:**
- terminal ถามคำถามเป็นข้อ ๆ ให้เลือก (เลือกโปรเจกต์ / ระบุโฟลเดอร์ผลลัพธ์)
- บรรทัดสุดท้ายขึ้นว่า **`Deploy complete!`** พร้อม **Hosting URL** สีฟ้า
- หน้าเว็บ FixIt เปิดได้จาก URL นั้นจริง และมีข้อมูลชุดเดียวกับในเครื่อง

**ชี้ให้ดูตรงนี้:**
- ชี้ URL แล้วพูดว่า "ที่อยู่นี้ส่งให้ใครก็เปิดได้ ระบบของคุณมีที่อยู่บนอินเทอร์เน็ตแล้ว"
- ย้ำว่า **ยังไม่สมบูรณ์ก็ deploy ได้** ไม่ต้องรอให้เสร็จหมด
- 🔒 **ย้ำทันทีตรงนี้:** "เว็บนี้ตอนนี้ใครก็เปิดได้ และยามยังไม่มา — ห้ามใส่ข้อมูลจริงของคนอื่นเด็ดขาด สัปดาห์หน้าเราจะตั้งยามก่อนค่อยเอาของจริงเข้า"

**เชื่อมกับ LeaveEasy:** "ตอนบ่ายนี่คือส่วน D ของใบงาน ทำได้ทันดี ทำไม่ทันไปทำต่อระหว่างสัปดาห์ได้ ขอให้ถึง Checkpoint 3 เป็นอย่างน้อย"

## 🆘 ถ้าเดโมพังจริงโดยไม่ได้ตั้งใจ

> **กติกาของตัวเอง: ให้เวลาแก้สดไม่เกิน 90 วินาที ถ้าไม่จบ ให้สลับไปแผนสำรองทันที** และพูดออกมาตรง ๆ ว่า "อันนี้ผมแก้สดไม่ได้ครับ ผมจะสลับไปของสำรอง แล้วจะกลับมาไล่ให้ดูตอนพัก" — **การพูดแบบนี้คือบทเรียนสำหรับผู้เรียนเอง อย่ารู้สึกว่าเสียหน้า**

| อาการ | ทำอย่างไรภายใน 60 วินาที |
|---|---|
| **permission denied ตอนที่ไม่ได้ตั้งใจ** | เปิด Console → Rules → ต่ออายุโหมดทดสอบ → Publish → รอ 20 วินาที → รีเฟรช |
| **Claude Code ค้าง หรือตอบช้าผิดปกติ** | กดหยุดคำสั่ง → เปิดบทสนทนาใหม่ → สั่งสั้นลง 1 งาน · ระหว่างรอให้ถามคำถามทวนความเข้าใจกับห้อง |
| **Claude แก้แล้วหน้าเว็บพังกว่าเดิม** | `git checkout .` ย้อนกลับ commit ล่าสุดที่ยังดี → พูดว่า "เห็นไหมครับว่าทำไมผมถึง commit ทุกก้อน" → สั่งใหม่ให้เจาะจงขึ้น |
| **Firebase Console โหลดไม่ขึ้น / ช้ามาก** | สลับไปแท็บสำรองที่เปิด `fixit-demo-backup` ค้างไว้ → ใช้ภาพนิ่งประกอบ |
| **หน้าเว็บขึ้นขาวทั้งจอ** | เปิด F12 → อ่าน error บรรทัดแรกออกเสียง → นี่คือการสาธิตทักษะไล่ปัญหาไปในตัว |
| **ข้อมูลไม่ขึ้นแต่ไม่มี error** | เปิด Console เทียบชื่อโฟลเดอร์ตัวเล็ก-ใหญ่ทันที (`tickets` กับ `Tickets`) |
| **seed รันไม่ผ่าน** | ใช้ `backup/seed.js` · ถ้ายังไม่ผ่าน **ใส่ข้อมูล 2 ไฟล์ด้วยมือใน Console ให้ดู** — ได้ผลการสอนดีกว่าเดิมด้วยซ้ำ |
| **อินเทอร์เน็ตหลุด / Firebase ล่ม** | เปลี่ยนเป็นเดินภาพนิ่งทีละหน้าจอ + กลับไปทำขั้นที่ 3 (แปลง ERD บนกระดาน) ต่อ ซึ่งไม่ต้องใช้เน็ต |
| **deploy ไม่ผ่านและเวลาหมด** | ข้ามไปเลย ฉายภาพนิ่ง แล้วบอกว่าใบงานมีขั้นตอนครบ |

**แผนสำรองสุดท้าย:** เปิด repo FixIt ที่แท็ก `week7-end` คู่กับ project `fixit-demo-backup` ที่ seed ข้อมูลไว้แล้ว **แล้วเล่าย้อนว่าไปถึงตรงนั้นได้อย่างไรทีละขั้น** โดยเปิด Firebase Console ของ backup ให้ดูจริง — ผู้เรียนยังได้เห็นสิ่งสำคัญที่สุดของสัปดาห์ คือโฟลเดอร์และไฟล์ข้อมูลจริง
