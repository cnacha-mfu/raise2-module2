# บล็อก A — CLAUDE.md ด้วย `/init` ⏱ 6 นาที

### ขั้นที่ 1 — `/init` ร่างให้ แล้วเราอ่านตรวจว่าอะไรขาด ⏱ 6 นาที

> 📍 **จุดสลับจอ:** สไลด์หน้า **12** *(🎬 สาธิต — /init กับ FixIt แล้วตรวจว่าอะไรขาด)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **13** *(✅ ช่วงที่ 1 คุณต้องได้อะไรกลับไป)*

**พูดว่า:** "สัปดาห์ที่แล้วผมต้องพิมพ์อธิบาย FixIt ให้ Claude ฟังใหม่ทุกบทสนทนา วันนี้ผมจะเขียนไว้ครั้งเดียวจบ และผมจะไม่พิมพ์เองสักตัวอักษร"

**ทำ:**
1. เปิด Claude Code ในโฟลเดอร์ `fixit-demo`
2. **พิมพ์ `/init` ให้เห็นชัด ๆ ก่อนกด Enter** — อย่ารีบกด

```
/init
```

**ผู้เรียนจะเห็น:** Claude ไล่อ่านไฟล์ในโปรเจกต์ (ชื่อไฟล์ไหลขึ้นจอ) แล้ว**แสดงร่าง CLAUDE.md พร้อมถามก่อนบันทึก** — ยังไม่มีไฟล์เกิดจนกว่าเราจะตอบ

> ⚠️ **สิ่งที่ต้องพูดให้ครบ ห้ามข้าม:** "`/init` ทำแทนเราได้สองจังหวะแรกเท่านั้น **จังหวะที่สาม อ่านแล้วบอกว่าอะไรขาด ยังเป็นงานของเราเหมือนเดิม** ผมกำลังจะทำให้ดูเดี๋ยวนี้"
>
> ⚠️ **ถ้า `/init` ไม่ได้ผลในเวอร์ชันของเครื่องผู้สอน:** อย่าไล่แก้สด พูดประโยค `/help` ประจำคาบ แล้วใช้ prompt สำรองนี้แทน — ผลลัพธ์เท่ากัน
> > อ่านไฟล์ในโปรเจกต์นี้ แล้วร่าง CLAUDE.md คู่มือประจำโครงงานให้ผมดูก่อน
> > เขียนภาษาไทย ยาวไม่เกิน 1 หน้า อย่าเพิ่งบันทึกไฟล์

**📖 จังหวะที่ 3 — อ่านออกเสียงแล้วชี้ว่าอะไรขาด ⭐ (หัวใจของขั้นนี้)**

อ่านร่างทีละหัวข้อต่อหน้าห้อง แล้วชี้อย่างน้อย 2 จุดที่ขาด — ร่างจาก `/init` มักขาดชุดนี้

| สิ่งที่ต้องมี | ร่างจาก `/init` มักเป็นอย่างไร |
|---|---|
| **โครงสร้างข้อมูลบน Firestore** ชื่อช่องครบทุกตัว | มีไม่ครบ หรือสะกดไม่ตรงกับ spec |
| **รายการความสามารถ (API List)** จาก Tech Spec | ไม่มี เพราะมันเดาความตั้งใจเราไม่ได้ |
| **ข้อตกลง** เช่น สถานะใช้ได้ 4 ค่า · ข้อความภาษาไทย | มักไม่มี |
| **สิ่งที่ห้ามทำ** | ไม่มี หรือกว้างเกินไป |

**prompt ที่ใช้ (จังหวะที่ 3 — บอกเฉพาะที่ขาด):**

> ขอเพิ่มหัวข้อ โครงสร้างข้อมูลบน Firestore โดยคัดจากหัวข้อ 5.2 ของไฟล์ fixit-spec.md มาทั้งชุด ห้ามเปลี่ยนชื่อช่อง
> ขอเพิ่มหัวข้อ ข้อตกลงของโครงงาน กับ สิ่งที่ห้ามทำ และ API List จากหัวข้อ 3 ของ spec
> เขียนภาษาไทย ไม่เกิน 1 หน้า ที่เหลือโอเค

**prompt ที่ใช้ (จังหวะที่ 4):**

> โอเคแล้ว บันทึกเป็น CLAUDE.md ที่โฟลเดอร์บนสุดได้เลย

จากนั้นสั่ง *"ปักหมุดเก็บงานให้ผม ตั้งข้อความว่า เพิ่ม CLAUDE.md คู่มือประจำโครงงาน"*

**ผู้เรียนจะเห็น:** ไฟล์ `CLAUDE.md` โผล่ที่โฟลเดอร์บนสุด · เปิดดูเห็นหัวข้อภาษาไทย มีโครงสร้างข้อมูลชื่อช่องตรงกับ spec ทุกตัว

**ชี้ให้ดูตรงนี้:**
- ชี้ว่าไฟล์อยู่ **โฟลเดอร์บนสุด** — วางผิดที่ Claude ไม่อ่าน
- ชี้บรรทัดชื่อช่องข้อมูล แล้วพูดว่า "ตั้งแต่นาทีนี้ Claude จะสะกด `reporterName` ชุดเดียวกันทุกบทสนทนา เพราะมันอ่านไฟล์นี้ก่อนทำงานทุกครั้ง"
- ⭐ ปิดท้าย: "ผมไม่ได้พิมพ์ไฟล์นี้เองสักตัวอักษร ผมอ่านแล้วบอกว่าอะไรขาด — นั่นคือส่วนที่คำสั่งทำแทนคุณไม่ได้"

**เชื่อมกับ LeaveEasy:** "ตรงนี้ของ FixIt คือคู่มือระบบแจ้งซ่อม — ถ้าเป็น LeaveEasy จะได้คู่มือที่มีโฟลเดอร์ `leaveRequests` และสถานะ 3 ค่า — **แล้วหัวข้อของคุณ คู่มือจะเขียนโครงสร้างว่าอะไร** บ่ายนี้ส่วน A คุณทำขั้นนี้เป๊ะ ๆ"

> 🆘 **ถ้าร่างยาวเกิน 3 หน้า:** สั่งสั้น ๆ *"ตัด CLAUDE.md ให้เหลือไม่เกิน 1 หน้า เก็บหัวข้อเดิมครบ"* · ยังไม่ดีอีก เปิดไฟล์จาก `fixit-week7-end` มาใช้แล้วเดินต่อ

### ขั้นที่ 2 — C: หน้าแจ้งซ่อมใหม่ บันทึกลงฐานจริง ⏱ 10 นาที

> 📍 **จุดสลับจอ:** สไลด์หน้า **20** *(🎬 สาธิต — C: แจ้งซ่อมใบใหม่ ลงฐานจริง)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **21** *(U — แก้ไข: เปลี่ยนสถานะในไฟล์เดิม)*

**พูดว่า:** "ปุ่มบันทึกของเราตอนนี้ยังหลอกอยู่ กดแล้วเหมือนบันทึก แต่รีเฟรชแล้วหาย วันนี้ต่อสายจริง"

**จังหวะที่ 1 — สั่งสั้น · prompt ที่ใช้:**

> เปลี่ยนหน้าแจ้งซ่อมใหม่ให้บันทึกลง Firestore จริง
> ช่วยเขียนแผนให้ผมดูก่อน อย่าเพิ่งลงมือ

**จังหวะที่ 2 — ผู้เรียนจะเห็น:** แผนประมาณ 4–5 ข้อ ยังไม่มีโค้ด

#### 💥 จุดที่แผนมาผิด — จงใจให้ผู้เรียนเห็น

แผนของ AI ในขั้นนี้**มักขาด 3 เรื่องนี้** — อ่านออกเสียงทีละข้อแล้วชี้

| มักขาด | ทำไมสำคัญ |
|---|---|
| บันทึก**ชื่อที่จดซ้ำ** (`reporterName` `categoryName`) | ขาดแล้วหน้ารายการขึ้นรหัสแทนชื่อ |
| ตั้ง `status` = "แจ้งใหม่" และ `createdAt` อัตโนมัติ | ผู้ใช้ห้ามเลือกสถานะเอง |
| **ตรวจข้อมูลก่อนบันทึก** เมื่อกรอกไม่ครบ | กันขยะเข้าฐาน |

**พูดตอนนี้:** "ถ้าผมพิมพ์โอเคไปตอนนี้ บ่ายนี้หน้ารายการผมจะขึ้น u001 แทนชื่อสมชาย — จังหวะที่สามมีไว้จับตรงนี้เอง"

**จังหวะที่ 3 — เราแก้แผน ⭐ · prompt ที่ใช้:**

> ขอบันทึกชื่อที่จดซ้ำให้ครบทุกคู่ตามโครงสร้างใน CLAUDE.md
> ตั้งสถานะ แจ้งใหม่ กับเวลาที่แจ้ง ให้อัตโนมัติ
> กรอกไม่ครบต้องเตือนเป็นภาษาไทยและไม่บันทึก ที่เหลือโอเค

**จังหวะที่ 4 · prompt ที่ใช้:**

> แผนโอเคแล้ว ลงมือได้ ทำทีละข้อ เสร็จข้อไหนบอกผมก่อน

**ทำต่อ (ตรวจด้วยตา 3 จุด):**
1. กรอกใบใหม่ "ปลั๊กไฟห้องประชุมชำรุด" เลือกหมวดไฟฟ้า → กดบันทึก
2. สลับไปแท็บ **Firebase Console** → รีเฟรช → เปิดโฟลเดอร์ `tickets`
3. ลองกรอกฟอร์มโดย**เว้นหัวข้อว่าง** → กดบันทึก

> ถ้ายัง แก้ให้รอก่อนทุกหน้า

**ทำต่อ (ทดสอบปิดท้าย 2 ทาง):**
1. แท็บล็อกอิน → รีเฟรช → **ใช้งานได้ปกติ**
2. หน้าต่างไม่ระบุตัวตน → เปิดที่อยู่หน้ารายการตรง ๆ → **อ่านอะไรไม่ได้เลย**

**ชี้ให้ดูตรงนี้:** "สองภาพนี้คู่กันคือหลักฐานว่ากุญแจทำงาน คนในบ้านใช้ได้ คนแปลกหน้าเข้าไม่ได้ — และนี่คือครึ่งแรกของ Checkpoint 3 บ่ายนี้"

> ⚠️ **แผนสำรอง — ถ้ารอบของคุณไม่พัง** (AI เขียนโค้ดรอสถานะไว้แล้ว): อย่าฝืนทำให้พัง ให้เปิดโค้ดชี้บรรทัดที่รอสถานะล็อกอิน แล้วพูดว่า "ของผมรอดเพราะมีบรรทัดนี้ ถ้าใครตอนบ่ายโดน permission denied ทั้งที่ล็อกอินอยู่ ให้สงสัยว่าขาดบรรทัดนี้ แล้วใช้ prompt ในใบงานแก้ได้เลย" — บทเรียนยังครบ

**เชื่อมกับ LeaveEasy:** "ถ้าเป็น LeaveEasy ตอนนี้คนไม่ล็อกอินเปิดดูใบลาของใครไม่ได้แล้ว — แต่**ยังไม่ปลอดภัยจริง ใครสมัครใหม่ก็อ่านได้หมด** สัปดาห์หน้าเราปิดรายห้อง ระหว่างนี้ห้ามใส่ข้อมูลจริงของใคร — **คุณก็เช่นกัน**"

# บล็อก E — GitHub + 💥 จุดพังที่ 2 ⏱ 11 นาที

### ขั้นที่ 8 — `.gitignore` ก่อน แล้ว push ขึ้น GitHub ⏱ 4 นาที

> 📍 **จุดสลับจอ:** สไลด์หน้า **49** *(🎬💥 สาธิต — push ขึ้น GitHub แล้วทำให้งานชนกัน)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **50** *(✅ ช่วงที่ 5 คุณต้องได้อะไรกลับไป)*
> ⏭️ **ขั้นที่ 9 ต่อจากขั้นนี้ทันที ไม่ต้องกลับสไลด์คั่น**

**พูดว่า:** "ก่อนส่งงานขึ้นคลาวด์ ต้องบอกก่อนว่าไฟล์ไหนห้ามส่งขึ้นไป ลำดับนี้สลับไม่ได้ ทำ .gitignore ก่อน push เสมอ"

**prompt ที่ใช้:**

> ตรวจไฟล์ .gitignore ให้กันโฟลเดอร์ที่เครื่องมือสร้างเอง และไฟล์ที่มีคำว่า key หรือ secret
> แล้วบอกวิธีสร้าง repo บน GitHub และ push ขึ้นไปทีละขั้น
> ก่อน push ให้แสดงรายชื่อไฟล์ที่จะถูกส่งขึ้นไป ผมจะตรวจเอง

**ทำต่อ:**
1. **อ่านรายชื่อไฟล์ที่ Claude แสดงมาออกเสียงทีละบรรทัด** — ต้อง**ไม่มี** `node_modules` (โฟลเดอร์ที่เครื่องมือสร้างเอง) และไม่มีไฟล์คีย์
2. สร้าง repo ชื่อ `fixit` แบบ **Private** บน GitHub → push ตามขั้นที่ AI บอก
3. รีเฟรชหน้า repo → **เลื่อนกวาดตาดูรายชื่อไฟล์ช้า ๆ ออกเสียง**

**ผู้เรียนจะเห็น:** terminal ขึ้นบรรทัดประมาณ `branch 'main' set up to track 'origin/main'` · หน้า repo มี `CLAUDE.md` แต่**ไม่มี** `node_modules` และไม่มีไฟล์คีย์

**ชี้ให้ดูตรงนี้:** "ผมกวาดตาดูหน้านี้ทุกครั้งหลัง push ใช้ 10 วินาที กันเรื่องใหญ่ได้ — ถ้าเผลอ push คีย์ขึ้นไป ให้**เพิกถอนคีย์ก่อน** แล้วค่อยลบไฟล์ ลบอย่างเดียวไม่พอ"

**เชื่อมกับ LeaveEasy:** "ภาพหน้า repo แบบนี้แหละคือ Checkpoint 1 ของบ่ายนี้ — repo ของคุณ มี CLAUDE.md ไม่มีคีย์"

### ขั้นที่ 9 — 💥 ทำให้งานชนกันจริง แล้วกู้ให้ดู ⏱ 7 นาที

**พูดว่า:** "ทีนี้ผมจะทำสิ่งที่คุณจะเจอกันจริง ๆ ให้ดู คือสองคนแก้ไฟล์เดียวกันโดยไม่บอกกัน ดูอาการแล้วดูวิธีกู้นะครับ"

**ทำ (จำลองโค้ดฝั่ง GitHub):**
1. บนหน้า GitHub เปิดไฟล์ `CLAUDE.md` → กดปุ่มแก้ไข (ไอคอนดินสอ) → เติมบรรทัดในหัวข้อข้อตกลง เช่น `- เพื่อนเพิ่ม: ปุ่มทุกปุ่มต้องมีข้อความไทย` → กด Commit changes บนเว็บ
2. พูดว่า "สมมติว่านี่คือโค้ดอีกชุดที่อยู่บน GitHub เขาเพิ่ง push ไป"
3. **ในเครื่องเรา (ไม่ดึงงานล่าสุดลงมาก่อน — ตั้งใจให้ชน):** แก้บรรทัดบริเวณเดียวกันใน `CLAUDE.md` ด้วย editor → สั่ง Claude *"ปักหมุดแล้ว push ขึ้น GitHub ให้ผม"*

**ผู้เรียนจะเห็น:** push **ถูกปฏิเสธ** ขึ้นข้อความประมาณ `rejected ... fetch first`

**พูดตอนพัง:** "เห็นไหมครับ ผมเองก็เจอ — GitHub ไม่ยอมให้ผมทับงานเพื่อน มันบอกให้ผมไปดึงของล่าสุดมาก่อน นี่คือระบบป้องกัน ไม่ใช่ความเสียหาย"

**ทำต่อ:** เล่าอาการให้ Claude ฟังตาม prompt ข้างล่าง แล้วเปิดไฟล์ `CLAUDE.md` ให้ห้องเห็นว่ามีข้อความ **ทั้งสองฝั่ง** อยู่ในไฟล์เดียวกัน

**ชี้ให้ดูตรงนี้:** "สังเกตนะครับ **งานอยู่ครบทั้งสองฝั่ง** ของฝั่ง GitHub ท่อนบน ของผมท่อนล่าง — ระบบไม่ตัดสินใจแทนเรา มันถามว่าจะเก็บแบบไหน"

**วิธีกู้ · prompt ที่ใช้:**

> ผม pull แล้วมีไฟล์งานชนกัน ช่วยอธิบายว่าฝั่งไหนแก้อะไร
> แล้วรวมให้เก็บของทั้งสองฝั่ง เสร็จแล้วให้ผมดูก่อน commit

**ทำต่อ:** อ่านไฟล์ที่รวมแล้ว → สั่ง *"โอเคแล้ว ปักหมุดแล้ว push ขึ้นไปให้ผม"* → รีเฟรชหน้า GitHub

**ผู้เรียนจะเห็น:** push ผ่าน · บน GitHub เห็นข้อตกลง**ทั้งสองบรรทัด**อยู่ครบ

**ชี้ให้ดูตรงนี้:** "สังเกตนะครับ ผมไม่ได้พิมพ์คำสั่ง git สักตัวตอนแก้ ผมเล่าอาการให้ Claude ฟังเฉย ๆ แล้วมันจัดการให้ — สิ่งที่ผมทำเองมีอย่างเดียวคือ commit ไว้ก่อน"

**เชื่อมกับ LeaveEasy:** "บ่ายนี้ใบงานส่วน A3 ให้คุณทำให้ชนกันเองแล้วส่งให้ Claude แก้ — ไม่ต้องจำคำสั่งอะไรเลย จำอย่างเดียวว่า commit ก่อน"

> 🆘 **ถ้า pull แล้วขึ้นคำถามเรื่องวิธีรวม (rebase/merge):** เลือกตามค่าเริ่มต้นแล้วไปต่อ อย่าอธิบายลึกหน้าห้อง · บอกว่า "ใบงานเขียนวิธีที่ต้องใช้ไว้แล้ว"

# บล็อก F — Deploy ฉากจำของเช้า ⏱ 9 นาที

### ขั้นที่ 10 — FixIt ขึ้น URL จริงต่อหน้าห้อง ⏱ 9 นาที

> 📍 **จุดสลับจอ:** สไลด์หน้า **56** *(🎬 สาธิต — FixIt ขึ้น URL จริง ต่อหน้าห้อง)* → สลับไปหน้าจอสาธิต ทำจนจบ → กลับเข้าสไลด์หน้า **57** *(!! ระบบของเราออนไลน์แล้ว)*

**พูดว่า:** "นาทีที่ผมรอมาทั้งเช้าครับ ระบบที่อยู่ในเครื่องเราคนเดียวยังไม่นับว่าเป็นระบบ เอามันออกสู่โลกกัน"

**prompt ที่ใช้:**

> ช่วยนำเว็บนี้ขึ้น Firebase Hosting บอกผมทีละขั้นว่าต้องพิมพ์อะไร
> และ deploy Security Rules ขึ้นไปด้วยในรอบเดียวกัน
> เสร็จแล้วบอก URL ที่ผมส่งให้คนอื่นเปิดได้

**ทำ:** พิมพ์ตามที่ AI บอกทีละขั้น อ่านออกเสียงทุกคำสั่งก่อนกด · รอ 1–2 นาที

**ผู้เรียนจะเห็น:** terminal ขึ้นข้อความ **`Deploy complete!`** และบรรทัด **Hosting URL** ลงท้ายด้วย `.web.app`

**ทำต่อ (ฉากจำ — อย่ารีบ):**
1. เปิด URL ในเบราว์เซอร์ → เห็นหน้าเข้าสู่ระบบของ FixIt
2. **หยิบโทรศัพท์ตัวเองเปิด URL เดียวกันให้เห็นหน้าจอ** — ออนไลน์จริง ไม่ใช่ในเครื่อง
3. **วาง URL ในแชท แล้วพูดว่า "ทุกคนเปิดตามเดี๋ยวนี้เลยครับ เปิดได้พิมพ์ 🎉"** — รอจนมีอย่างน้อย 5 คนยืนยัน

**ชี้ให้ดูตรงนี้:** ชี้แถบที่อยู่ "ไม่มีคำว่า localhost แล้วนะครับ นี่คือที่อยู่จริงบนอินเทอร์เน็ต ใครก็เปิดได้ และเพราะใครก็เปิดได้ กฎเมื่อกี้ถึงต้องมาก่อนเสมอ" · ย้ำปิดท้าย "**ห้ามใส่ข้อมูลจริงของใครจนกว่ากฎรายห้องจะปิดสัปดาห์หน้า**"

**เชื่อมกับ LeaveEasy:** "ถ้าเป็น LeaveEasy ตอนนี้จะได้ URL ที่เปิดแล้วเจอหน้าเข้าสู่ระบบขอลา — บ่ายนี้ส่วน D คุณจะได้ URL ของตัวเอง แล้ว**แลกกับเพื่อนให้เขาลองเปิด** นั่นคือCheckpoint 4"

> 🆘 **ถ้า deploy ค้างหรือ error กลาง terminal:** อย่าไล่แก้สดเกิน 2 นาที · เปิดโฟลเดอร์สำรอง `fixit-week7-end` ที่ deploy ไว้แล้วก่อนคาบ แล้วเปิด URL สำรองให้ดู พูดว่า "ผมเปิดของที่ deploy ไว้เมื่อเช้าให้ดูผลลัพธ์ก่อน แล้วเดี๋ยวเล่าว่าคำสั่งที่พังเมื่อกี้ใบงานมีทางออกยังไง"
