Firebase Authentication — ระบบล็อกอินสำเร็จรูป

  • Authentication = ระบบยืนยันตัวตน (สมัคร/เข้า/ออก)
  • ใช้แบบอีเมล + รหัสผ่าน
  • ไม่ต้องเขียนระบบรหัสผ่านเอง — เรื่องนี้พลาดแล้วเจ็บจริง
  • เปิดใช้ใน Firebase Console ก่อน แล้วค่อยสั่ง AI ต่อ
🗒️ ย้ำคำแปล Authentication = ระบบยืนยันตัวตน หรือเรียกสั้น ๆ ว่าล็อกอิน · พูดว่า "การเก็บรหัสผ่านคนอื่นคืองานที่มืออาชีพยังพลาด เราไม่เขียนเองเด็ดขาด ใช้ของสำเร็จที่มีคนดูแลให้"

uid — เลขประจำตัวผู้ใช้

  • สมัครสำเร็จ ระบบออก uid (เลขประจำตัวผู้ใช้) ให้อัตโนมัติ
  • ใช้ uid เป็นชื่อไฟล์ในโฟลเดอร์ users
  • ใบแจ้งใหม่บันทึกช่องผู้แจ้ง = uid ของคนที่ล็อกอินอยู่จริง
  • ช่อง role (บทบาท) เก็บไว้ในไฟล์นั้น — มาจาก Persona
🗒️ พูดว่า "uid เหมือนเลขบัตรประชาชนของผู้ใช้ในระบบเรา ระบบออกให้เอง ไม่ซ้ำกันแน่นอน" · ชี้ข้อสาม "ตรงนี้แหละคือคำว่า ระบบรู้จักผู้ใช้ ใบไหนของใคร ตอบได้ทันที" · ข้อสี่บอกว่าค่า role ใช้รหัสอังกฤษตาม spec เพราะสัปดาห์หน้าจะใช้เขียนกฎ

ช่วงที่ 5 — 👥 Git หลายคนบน repo เดียว ⭐ ⏱ 11:10–11:35

🗒️ พูดว่า "ช่วงนี้ 25 นาที และเป็นของใหม่จริงของวันนี้ครับ ที่ผ่านมากลุ่มคุณผลัดกันพิมพ์บนเครื่องเดียว บ่ายนี้เป็นครั้งแรกที่ทุกคนจะแก้ repo เดียวกันจากคนละเครื่อง ผมสอนตรงนี้เพราะอีกสองชั่วโมงคุณได้ใช้ทันที"

บ่ายนี้ทั้งกลุ่มแก้ repo เดียวกันเป็นครั้งแรก

  • บ่ายนี้โค้ดของกลุ่มจะขึ้น GitHub — repo กลางของทีม
  • 👤 ทุกคนต้อง commit ในชื่อตัวเอง — สัปดาห์นี้เริ่มนับจริง
  • ไม่มี commit เลยทั้ง Module = ไม่ผ่านรายบุคคล
  • ทำงานพร้อมกันได้ แต่ต้องมีกติกา
🗒️ ย้ำข้อสองหนัก ๆ "ผมเปิดประวัติ repo ดูได้ว่าใครพิมพ์บ้าง และผมดูทุกสัปดาห์ ไม่ใช่รอตอนจบ คนที่ไม่มี commit เลยจะตอบคำถามตอน Sprint Review ไม่ได้ และนั่นวัดเป็นรายบุคคล"

ก่อน push ครั้งแรก — .gitignore ต้องมาก่อน

  • .gitignore = รายการไฟล์ที่ห้ามส่งขึ้น GitHub
  • ต้องกัน node_modules และไฟล์คีย์ทุกชนิด
  • ให้ AI สร้าง → เราตรวจด้วย git status ว่ากันได้จริง
  • ลำดับสลับไม่ได้ — ของที่ขึ้นไปแล้ว มีคนคัดลอกได้ทันที
🗒️ ย้ำคำแปล .gitignore = รายการไฟล์ที่ห้ามส่งขึ้นไป · พูดว่า "ทำ .gitignore ก่อน push เสมอ สลับลำดับไม่ได้ เพราะไฟล์ที่เคยขึ้นไปแล้ว ต่อให้ลบทีหลัง ก็มีคนคัดลอกไปได้ตั้งแต่วินาทีแรก" · เตือนล่วงหน้า "ถ้าเผลอ push คีย์ขึ้นไป ให้เพิกถอนคีย์ก่อน แล้วค่อยลบไฟล์ ลบอย่างเดียวไม่พอ"

push / pull — ส่งขึ้น กับ ดึงลง

git pull     ดึงงานล่าสุดจาก GitHub ลงเครื่องเรา
git push     ส่งงานจากเครื่องเราขึ้น GitHub
  • pull = ดึงลง ก่อนเริ่มงานทุกครั้ง
  • push = ส่งขึ้น หลัง commit ทุกครั้งที่งานเสร็จ
  • งานล่าสุดอยู่บน GitHub — เครื่องใครก็ตามอาจล้าหลัง
🗒️ เปรียบว่า "GitHub เหมือนแฟ้มกลางของทีม ก่อนเริ่มงานต้องหยิบแฟ้มเวอร์ชันล่าสุดมาก่อน ทำเสร็จต้องเอาไปคืนแฟ้มกลาง ถ้าใครทำงานบนเวอร์ชันเก่า เดี๋ยวจะไปทับของเพื่อน"

กติกา 3 ข้อของทีม — ท่องให้ขึ้นใจ

  • 1️⃣ ดึงก่อนเริ่มเสมอ — git pull ทุกครั้งก่อนแตะงาน
  • 2️⃣ แบ่งกันคนละไฟล์ — ต่างคนต่างหน้า ต่างไฟล์
  • 3️⃣ บอกกันก่อนแก้ไฟล์เดียวกัน — ทักในแชทกลุ่ม 1 บรรทัด
🗒️ อ่านออกเสียงทีละข้อ แล้วพูดว่า "สามข้อนี้กันปัญหาได้เกือบร้อยเปอร์เซ็นต์ครับ ปัญหางานชนกันเกิดจากการละเมิดข้อใดข้อหนึ่งในนี้เสมอ" · บอกว่าใบงานบ่ายนี้บังคับข้อ 1 ไว้ในทุกจุดหมุนคีย์บอร์ด

  • ไม่มีงานของใครหาย — ทั้งสองเวอร์ชันอยู่ในไฟล์นั้น
🗒️ ย้ำข้อสุดท้ายหนักที่สุด "คำว่า conflict ฟังน่ากลัว แต่ความจริงคือ git เก็บของทั้งสองคนไว้ให้ครบ แล้วถามเราว่าจะเอาแบบไหน มันคือคำถาม ไม่ใช่ความเสียหาย" · แปลศัพท์ conflict = งานชนกัน สองคนแก้ที่เดียวกัน git เลือกเองไม่ได้

ช่วงที่ 6 — 🌐 Deploy ขึ้นออนไลน์ ⏱ 11:35–11:55

🗒️ พูดว่า "20 นาทีสุดท้ายของเช้าครับ และเป็นนาทีที่ผมชอบที่สุดของทั้งเดือน ระบบที่อยู่ในเครื่องเราคนเดียวยังไม่นับว่าเป็นระบบ อีกสิบนาที FixIt จะมีที่อยู่จริงบนอินเทอร์เน็ต"

Deploy = นำเว็บขึ้นออนไลน์ให้คนอื่นเปิดได้

  • Deploy = ส่งเว็บจากเครื่องเราขึ้นไปอยู่บนอินเทอร์เน็ต
  • ใช้ Firebase Hosting (บริการที่ทำให้เว็บเรามี URL)
  • localhost = ในเครื่องเราคนเดียว · URL จริง = ใครก็เปิดได้
  • ยังไม่สมบูรณ์ก็ deploy ได้ — ไม่ต้องรอเสร็จร้อยเปอร์เซ็นต์
🗒️ ย้ำคำแปล Deploy = นำเว็บขึ้นออนไลน์ · Hosting = บริการที่ให้เว็บเรามีที่อยู่จริง · พูดว่า "จำคำว่า localhost จากสัปดาห์ที่แล้วได้ไหมครับ วันนี้เราจะเปลี่ยนจาก localhost เป็นที่อยู่ที่ส่งให้ใครก็ได้"

deploy เว็บอย่างเดียวไม่พอ — กฎต้องขึ้นด้วย

  • เว็บกับกฎ deploy แยกกันคนละส่วน
  • กฎที่เขียนไว้ในเครื่อง ยังไม่คุ้มครองของจริง จนกว่าจะ deploy
  • 🚫 ห้ามออกออนไลน์โดยไม่มีกฎขั้นต่ำ — ไม่มีข้อยกเว้น
  • สั่ง AI ให้ deploy ทั้งเว็บและกฎในรอบเดียว
🗒️ พูดว่า "จุดพลาดคลาสสิกคือเขียนกฎไว้ในเครื่องแล้วนึกว่าปลอดภัยแล้ว กฎทำงานเฉพาะฉบับที่อยู่บนเซิร์ฟเวอร์ครับ ใบงานบ่ายนี้จึงเขียนให้ deploy กฎพร้อมเว็บเสมอ"

ในเครื่องได้ ออนไลน์พัง — 2 สาเหตุหลัก

  • สาเหตุ 1: กฎยังไม่ deploy — ขึ้น permission denied
  • สาเหตุ 2: index (สารบัญช่วยค้น) ยังไม่สร้าง
  • ทางแก้ index: อ่าน error → กดลิงก์ในข้อความ → กดสร้าง → รอ
  • อ่าน error ให้จบบรรทัดก่อนตกใจ
🗒️ พูดว่า "สองอาการนี้คืออันดับหนึ่งกับสองของบ่ายนี้ ผมบอกล่วงหน้าเลย ถ้าเว็บออนไลน์พังแต่ในเครื่องปกติ ให้เช็กสองข้อนี้ก่อนเสมอ" · ทวน index จากสัปดาห์ที่แล้ว "Firestore จะบอกเองว่าต้องสร้างสารบัญ พร้อมแนบลิงก์มาให้กด ไม่ต้องทำเอง"
