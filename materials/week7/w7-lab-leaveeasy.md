## ส่วน A — CLAUDE.md แล้วขึ้น GitHub ⏱ ~30 นาที

### A1 — ให้ `/init` ร่าง CLAUDE.md แล้วเราอ่านตรวจ (10 นาที)

พิมพ์ `/init` ใน Claude Code

**จะเห็น:** ไฟล์ `CLAUDE.md` ถูกสร้างขึ้น มีหัวข้อว่าโปรเจกต์นี้คืออะไร ใช้อะไรบ้าง

> ⭐ **อย่าผ่านไปเฉย ๆ — เปิดอ่านแล้วตอบให้ได้ว่าอะไรขาด** สิ่งที่มักขาดคือ ชื่อโฟลเดอร์ใน Firestore · สถานะ 3 แบบ · ข้อห้ามของโปรเจกต์

```prompt
ช่วยเติม CLAUDE.md ให้ครบ 3 เรื่องนี้
ชื่อโฟลเดอร์ทั้งหมดใน Firestore, สถานะใบลา 3 แบบ, ข้อห้ามคือห้ามใส่คีย์ลงไฟล์ที่ push
```

**จะเห็น:** CLAUDE.md มีชื่อ `users` `leaveTypes` `leaveRequests` `approvals` และสถานะ รอพิจารณา / อนุมัติ / ไม่อนุมัติ

### A2 — `.gitignore` ก่อน แล้วค่อย push (12 นาที)

> 🔒 **ลำดับนี้ห้ามสลับ** — push ก่อนแล้วค่อยกัน เท่ากับคีย์ขึ้นไปอยู่บนอินเทอร์เน็ตแล้ว ลบทีหลังไม่หายจากประวัติ

```prompt
ช่วยสร้าง .gitignore ให้กันไฟล์ตั้งค่าและไฟล์ที่มีคีย์ทั้งหมด
แล้วบอกผมทีละขั้นว่าจะ push ขึ้น GitHub อย่างไร ขอดูแผนก่อน
```

**จะเห็น:** `git status` ไม่ขึ้นชื่อไฟล์ที่มีคีย์ · จากนั้นเปิด github.com เห็น repo ของคุณพร้อมไฟล์ครบ

> 🆘 push ไม่ผ่าน ขอ username/password → GitHub ไม่รับรหัสผ่านแล้ว ให้ใช้วิธีล็อกอินผ่านเบราว์เซอร์ที่ Claude แนะนำ

### A3 — ซ้อมแก้ "งานชนกัน" กับตัวเอง (8 นาที)

จงใจทำให้โค้ดสองที่ไม่ตรงกัน แล้วกู้ให้เป็น

1. เปิด repo บน github.com → กดไอคอน ✏️ แก้ `README.md` เพิ่มบรรทัดหนึ่ง → Commit
2. กลับมาในเครื่อง แก้ **บรรทัดเดียวกัน** เป็นข้อความอื่น → commit
3. พิมพ์ `git pull`

**จะเห็น:** ข้อความ `CONFLICT` และในไฟล์มีเครื่องหมาย `<<<<<<<` `=======` `>>>>>>>`

```prompt
ผมเจอ conflict ในไฟล์ README.md
ช่วยอธิบายว่าแต่ละส่วนคืออะไร แล้วบอกวิธีเลือกและปิดงานให้ผมทีละขั้น
```

**จะเห็น:** หลังแก้แล้ว commit ได้ตามปกติ `git status` สะอาด

> 💡 **นี่คือทักษะสำหรับ Module 3** ที่ต้องทำงานหลายคนบน repo เดียว — วันนี้ซ้อมกับตัวเองก่อน

→ 🚩 **Checkpoint 1: repo อยู่บน GitHub มี CLAUDE.md · ไม่มีไฟล์คีย์ · แก้ conflict ผ่านแล้ว**
📸 โพสต์ screenshot หน้า repo บน GitHub · 🔁 สลับคนนำจอ

## ส่วน B — ⭐ ปุ่มเพิ่ม แก้ ลบ ที่ทำงานจริง ⏱ ~50 นาที

### B1 — เพิ่ม: ฟอร์มยื่นใบลาบันทึกลงฐานจริง (15 นาที)

```prompt
ผมอยากให้ฟอร์มในหน้า new-leave-request.html บันทึกลง Firestore จริง
ตั้งสถานะเริ่มต้นเป็น รอพิจารณา แล้วเด้งกลับไปหน้ารายการ
ขอดูแผนก่อน อย่าเพิ่งลงมือ
```

อ่านแผน ตรวจว่ามีข้อ **"ตรวจว่ากรอกครบก่อนบันทึก"** หรือยัง ถ้าไม่มีให้บอกเพิ่ม แล้วสั่งลงมือทีละข้อ

**จะเห็น:** กรอกฟอร์มกดบันทึก → กลับมาหน้ารายการเห็นใบใหม่อยู่บนสุด → เปิด Firebase Console เห็นไฟล์ใหม่จริง

> 🆘 บันทึกแล้วไม่ขึ้นในรายการ → มักเพราะเรียงตามวันที่ ให้ตรวจว่ามีการเขียนช่อง `createdAt` ลงไปจริงไหม

### B2 — แก้: เปลี่ยนสถานะเป็นอนุมัติ / ไม่อนุมัติ (15 นาที)

```prompt
ในหน้า leave-request-detail.html ผมอยากได้ปุ่มอนุมัติกับไม่อนุมัติ
กดแล้วแก้เฉพาะช่อง status ช่องอื่นห้ามแตะ ขอดูแผนก่อน
```

**จะเห็น:** กดปุ่มแล้วสถานะเปลี่ยน → กด F5 ยังเป็นค่าใหม่ → Console เห็นว่าช่องอื่นไม่ถูกแก้

> ⚠️ **อนุมัติหรือไม่อนุมัติแล้ว เปลี่ยนต่อไม่ได้** — บอก AI ให้ปิดปุ่มเมื่อสถานะไม่ใช่ รอพิจารณา

### B3 — ลบ: ต้องยืนยันก่อนเสมอ (10 นาที)

```prompt
ขอปุ่มลบใบลา แต่ต้องมีหน้าต่างถามยืนยันก่อนทุกครั้ง
กดยกเลิกแล้วต้องไม่ลบ ขอดูแผนก่อน
```

**จะเห็น:** กดลบ → มีคำถามยืนยัน → กดยกเลิกข้อมูลยังอยู่ → กดตกลงแถวนั้นหายไปทั้งในหน้าเว็บและใน Console

### B4 — พิสูจน์ว่าระบบมีความจำจริง (10 นาที)

กรอกใบลาใหม่ 1 ใบ → **ปิดเบราว์เซอร์ทั้งหน้าต่าง** → เปิดใหม่ → เข้าหน้ารายการ

**จะเห็น:** ใบลาที่เพิ่งกรอกยังอยู่ · จากนั้น commit งานทั้งหมด

→ 🚩 **Checkpoint 2: ⭐ กรอก → ปิดเบราว์เซอร์ → เปิดใหม่ → ข้อมูลยังอยู่ + แก้ได้ + ลบได้**
📸 โพสต์ screenshot ก่อน-หลังปิดเบราว์เซอร์ · 🔁 สลับคนนำจอ 🎥 มีคลิปสั้น 3 นาทีของขั้นนี้

## ส่วน C — 🔑 ล็อกอิน + กุญแจประตูหน้าบ้าน ⏱ ~30 นาที

### C1 — เปิดใช้ Authentication (5 นาที)

Firebase Console → เมนู **Authentication** → **Get started** → เลือก **Email/Password** → **Enable** → Save

**จะเห็น:** แท็บ Users ว่างเปล่า พร้อมรับผู้ใช้คนแรก

### C2 — สมัคร เข้า ออก และผูกใบลากับเจ้าของ (15 นาที)

```prompt
ผมอยากได้ระบบล็อกอินด้วยอีเมลกับรหัสผ่านของ Firebase
ขอแผนก่อน อย่าเพิ่งลงมือ
```

อ่านแผนแล้วเทียบกับ 5 ข้อนี้ — ขาดข้อไหนให้บอกเพิ่ม

1. หน้าสมัครสมาชิก
2. หน้าเข้าสู่ระบบ
3. ปุ่มออกจากระบบ
4. ยังไม่ล็อกอินให้เด้งไปหน้าเข้าสู่ระบบ
5. ใบลาที่สร้างใหม่ต้องบันทึก **uid ของคนที่ล็อกอินอยู่** ลงช่อง `requesterId`

**จะเห็น:** สมัครแล้วแท็บ Users ใน Console มีอีเมลของคุณขึ้นมา · ล็อกอินแล้วยื่นใบลา เห็น `requesterId` เป็น uid จริงใน Console

> 🆘 หลังใส่ล็อกอินแล้วหน้ารายการว่าง → เพราะหน้าเว็บอ่านข้อมูลก่อนที่สถานะล็อกอินจะพร้อม ให้บอก AI ว่า *"ให้รอสถานะล็อกอินพร้อมก่อนค่อยอ่านข้อมูล"*

### C3 — กุญแจประตูหน้าบ้าน: กฎขั้นต่ำ 1 ข้อ (10 นาที)

```prompt
ช่วยเขียน Firestore Security Rules ให้ผม
กฎข้อเดียวคือ ต้องล็อกอินก่อนถึงจะอ่านหรือเขียนอะไรได้
เขียนไฟล์กฎมาให้ผมอ่านก่อน อย่าเพิ่ง deploy
```

อ่านไฟล์กฎแล้วตอบให้ได้ว่า *บรรทัดไหนคือ "ต้องล็อกอินก่อน"* จากนั้นทดสอบ

- เปิด **หน้าต่างส่วนตัว (Incognito)** แล้วเข้า URL หน้ารายการโดยไม่ล็อกอิน

**จะเห็น:** อ่านข้อมูลไม่ได้ · Console ของเบราว์เซอร์ขึ้น `permission-denied` — **เจอแบบนี้แปลว่ากฎทำงานถูกแล้ว**

> ⚠️ **กฎขั้นต่ำนี้ยังไม่พอ** — ตอนนี้ใครสมัครสมาชิกก็อ่านใบลาของคนอื่นได้หมด
> ของจริงอยู่สัปดาห์ที่ 8 · **ดังนั้นห้ามใส่ข้อมูลจริงของคนอื่น** ใช้ชื่อสมมติ สมชาย สมหญิง สมศรี

→ 🚩 **Checkpoint 3: ล็อกอินได้ + ไม่ล็อกอินอ่านไม่ได้**
📸 โพสต์ screenshot หน้าต่างส่วนตัวที่ขึ้น permission-denied · 🔁 สลับคนนำจอ

## ส่วน D — 🌐 ขึ้นออนไลน์ ⏱ ~25 นาที

### D1 — Deploy เว็บและกฎในรอบเดียวกัน (15 นาที)

> 🔒 **ห้าม deploy โดยไม่มีกฎขั้นต่ำ** — ปล่อยระบบขึ้นออนไลน์โดยเปิดข้อมูลกว้าง คือการทำข้อมูลรั่วจริง ไม่ใช่แบบฝึกหัด

```prompt
ผมอยาก deploy เว็บนี้ขึ้น Firebase Hosting พร้อมกับกฎที่เขียนไว้
บอกผมทีละคำสั่ง แล้วบอกว่าแต่ละคำสั่งจะเห็นอะไรบนจอ
```

**จะเห็น:** รอ 1–2 นาที แล้วขึ้นข้อความ `Deploy complete!` พร้อม **Hosting URL** ที่ลงท้ายด้วย `.web.app`

> 🆘 `firebase: command not found` → ยังไม่ได้ติดตั้ง Firebase CLI ให้ขอ Claude ช่วยติดตั้งก่อน
> 🆘 เว็บขึ้นแล้วแต่ไม่มีข้อมูล → มักเพราะยัง deploy เฉพาะเว็บ ยังไม่ deploy กฎ ให้ deploy ทั้งสองอย่าง

### D2 — แลก URL กับเพื่อน (10 นาที)

โพสต์ URL ของคุณในแชท แล้วเปิด URL ของเพื่อน 2 คนจากเครื่องคุณ

**จะเห็น:** เปิดของเพื่อนได้ · แต่ต้องล็อกอินก่อนถึงจะเห็นข้อมูล · ถ้าไม่ล็อกอินแล้วยังเห็นข้อมูล ให้บอกเจ้าของทันทีว่ากฎยังไม่ทำงาน

จากนั้น commit และ push งานทั้งหมดขึ้น GitHub

→ 🚩 **Checkpoint 4: เพื่อนเปิด URL ของคุณได้จากเครื่องเขา และต้องล็อกอินก่อนจึงเห็นข้อมูล**
📸 โพสต์ URL + screenshot จากเครื่องคุณ
